# TETHER benchmark priorities and methods

**TETHER should now demonstrate useful scientific answering under matched evidence controls.** The next tasks remain SciFact, one original LAB-Bench family, and an Inspect implementation enforcing the same obligations. The completed equal-policy experiment supports a narrower engineering claim: patched TETHER and an independent validator both conform on all 109 authored cases, while the original TETHER missed one replay-binding defect. TETHER also had greater measured execution cost. Current peer systems already provide orchestration, provenance and audit features, so those categories alone cannot establish novelty. The strongest additions are evaluated semantic support, better retrieval where needed, controlled evidence-use tests and calibrated selective answering. This review identifies candidates and methods; it produces no new scientific benchmark results. ([Completed comparison](<D:/Projects/drug_target_agents/planning/TETHER Equal Policy Comparison Results 2026-11-05.md>))

## Existing results narrow the contribution

BG02 now contains two version-specific experiments, each with **109 cases × four arms × three repeats = 1,308 terminal cells**. Patched TETHER 0.5.2 / AsOf 0.3.13 and the independent implementation fully conform on every case; the earlier version falsely admits a response bound to the wrong request. All repeats agree. These are exposed constructions, including 44 eligible cases, 64 rejection controls and one inspection-only case; neither repetitions nor overlapping policy families enlarge the independent sample. The weak hash/schema arm admits 52 invalid cases, showing why hashes alone are insufficient, but it is not a substitute for the full-policy comparator. ([Original reconstruction](<D:/Projects/drug_target_agents/planning/review-assets/tether-equal-policy-v2-20261105/reconstruction/OLD-RESULT-SUMMARY-20261105.json>), [patched reconstruction](<D:/Projects/drug_target_agents/planning/review-assets/tether-equal-policy-v2-20261105/reconstruction/PATCHED-RESULT-SUMMARY-20261105.json>))

The patched median within-case import-plus-operation time ratio is **1.65 relative to the independent implementation**. That is adverse cost evidence for this instrumented, fresh-process Windows experiment, not a warm-service throughput result. Whole-package size includes unrelated capabilities and cannot establish the minimal code needed for equivalent guarantees. The useful finding is that an independent implementation exposed a real defect and reproduced the corrected finite behavior. Universal equivalence, clinical accuracy and superiority over other frameworks remain unestablished. ([Resource and scope record](<D:/Projects/drug_target_agents/planning/review-assets/tether-equal-policy-v2-20261105/reconstruction/PATCHED-RESULT-SUMMARY-20261105.json>))

The peer comparison also needs updating. Virtual Biotech's inspected `main` documentation describes manifests, claims/provenance, trace and cost records, artifact-integrity versus evidence-coverage checks, and incomplete outcomes. Its manifest source records artifact hashes and producing agents/tool calls. This is substantive overlap, although documented coverage checks do not prove scientific truth. The current-main commit could not be resolved reliably during this review; these observations must remain separate from TETHER's fixed Virtual Biotech baseline, commit `71f9da68c95c5ee0ef4c1d9b8f45f10693de022d`. No current Virtual Biotech installation or equal-policy execution was tested. ([Official documentation](https://raw.githubusercontent.com/harrisongzhang/TheVirtualBiotech/main/README.md), [inspected manifest implementation](https://raw.githubusercontent.com/harrisongzhang/TheVirtualBiotech/main/src/utils/run_manifest.py))

Inspect likewise already supplies task/scorer integration and proposed-tool execution checks. Its agent bridge can constrain argument matching and one execution per proposal; opting out changes that guarantee. The defensible comparison is therefore **the same declared policy implemented in different systems**, with added domain code and configuration disclosed. Bare Inspect is not an equivalent-policy baseline. ([Agent bridge](https://inspect.aisi.org.uk/agent-bridge.html))

## Prioritize native tasks over a larger benchmark catalogue

The following shortlist separates task performance from framework conformance. A benchmark becomes usable only after its assets, permissions, scorer and answer producer have been qualified; a public repository alone is insufficient.

| Priority | Native task and metrics | Access and implementation burden | Claim supported; principal limitation |
|---|---|---|---|
| **Next: SciFact** | Scientific abstract retrieval, support/contradiction labels and sentence rationales. Official abstract-label, abstract-rationalized, sentence-selection and sentence-label precision/recall/F1. | Public labelled train/dev; private test labels. Claims/annotations CC-BY-4.0, abstract corpus ODC-By-1.0, code Apache-2.0. Needs a native task contract and real solver. | Evidence interpretation against benchmark annotations; not therapeutic efficacy. Gold evidence and citation metadata must not leak into open retrieval. ([Release](https://github.com/allenai/scifact), [licenses](https://raw.githubusercontent.com/allenai/scifact/master/LICENSE.md), [scorer](https://raw.githubusercontent.com/allenai/scifact-evaluator/master/evaluator/eval.py)) |
| **Then: original LAB-Bench LitQA2 or DbQA** | Scientific literature or database multiple-choice accuracy; additionally report answer coverage and admitted accuracy. | Public CC-BY-SA-4.0 card lists **199 LitQA2 / 520 DbQA** items. LitQA2 includes privileged key passages and source links. Requires accessible source content and an answer-producing adapter. | Biomedical factual answering under frozen sources; not prospective target success. Public questions do not establish hidden evaluation or absent pretraining exposure. ([Official card](https://huggingface.co/datasets/futurehouse/lab-bench/raw/main/README.md)) |
| **Then: Inspect with equivalent obligations** | Same policy decisions, required outputs, failure accounting and costs; native task scores when attached to the same solver. | Framework, not dataset. Pin runtime and extension; count every added policy/helper dependency. | Portability and overhead of equal guarantees. A launcher or weaker default policy cannot establish equivalent functionality. ([Bridge contract](https://inspect.aisi.org.uk/agent-bridge.html)) |
| **Later: ALCE** | ASQA/QAMPARI/ELI5 answers with citations; native correctness, citation precision/recall and fluency. | Released retrieval bundles reduce initial index burden. Needs an answer generator and qualified attribution evaluator; source/model rights remain separate. | Whether useful generated statements are supported. It does not test historical input lineage or biomedical validity. ([Paper](https://aclanthology.org/2023.emnlp-main.398/), [release](https://github.com/princeton-nlp/ALCE)) |
| **Domain extension: R2E** | Masked-gene ranking; MRR, mean rank, hits@10/200; Gene Description Facts uses per-gene macro averaging. | Public evaluation TSVs, distinct terms by product; gene facts CC-BY-NC-SA-4.0. Requires a frozen candidate universe, evidence corpus and ranking producer. | Target-related retrieval/ranking. Released clinical labels describe phase-II/III-to-approval progression, not clinical endpoint success. ([Data/terms](https://github.com/BenevolentAI/r2e-evaluation-data), [native metrics](https://aclanthology.org/2025.acl-long.167.pdf)) |
| **Conditional: LABBench2 SourceQuality** | Scientific source suitability, scored with the pinned task grader. | Gated HF access. March 2026 replaced 150 SourceQuality items; October harness fixes affect attachments, isolation and grading, while published results use the earlier harness. | Whether a source can answer a question, beyond integrity. Pin task and grader together; do not inherit scores from another revision. ([Repository/changelog](https://github.com/EdisonScientific/labbench2), [card](https://huggingface.co/datasets/EdisonScientific/labbench2)) |

For SciFact, use the **official scorer implementation**, not an approximate description: its abstract-rationale cap is `max(3, shortest_gold_rationale_length)`, and sentence credit depends on complete rationale sets. Preserve sentence indices, raw predictions and explicit empty evidence. A correct insufficient-evidence prediction is distinct from policy abstention, absent output or timeout. Source-citation metadata is legitimate for a separately labelled supplied-document condition, not automatically for open retrieval. ([Scorer](https://raw.githubusercontent.com/allenai/scifact-evaluator/master/evaluator/eval.py), [data schema](https://raw.githubusercontent.com/allenai/scifact/master/doc/data.md))

During report preparation, the separate execution task acquired SciFact originals and pinned source archives at commits `68b98a56d93e0f9da0d2aab4e6c3294699a0f72e` and evaluator `66feffc5b2cc9e28e3ce3b8c9e824c3c642981eb`. The receipt says **downloaded, not parsed**; pinned-license review, input projection and solver qualification remain pending. This is acquisition progress, not a benchmark score or historical-availability proof. ([Acquisition receipt](D:/Projects/drug_target_agents/data/raw/scifact_public/20261105-attempt01/COMPLETE.json))

MultiVerS is a concrete SciFact solver candidate: it jointly predicts document labels and rationales from full abstract context. Its released inference uses CUDA and a legacy dependency environment; local operation and checkpoint exposure remain unqualified. Read-only inventory found roughly 32 GiB RAM and a 16-GB-class GPU, which establishes available hardware, not model fit. Qualify a simple trainable baseline and consider MultiVerS rather than inventing a general planner first. Do not replace a failed solver setup with gold replay. ([Model paper](https://aclanthology.org/2022.findings-naacl.6/), [inference](https://raw.githubusercontent.com/dwadden/multivers/main/multivers/predict.py), [local inventory](<D:/Projects/drug_target_agents/research_notes/TETHER benchmark priorities and methods/bg03-resource-inventory.json>))

Other candidates are less immediate. GenomeArena offers 720 annotation-oriented MCQs, but archive licensing and exact scorer remain unqualified here. BiomniBench-DA releases 50 of 100 analytical tasks through gated access and grades trajectories against supplied rubrics; its default API judge is outside the zero-spend route. TargetBench assesses target prioritization across 38 diseases, but custom code is proprietary and available on academic request; its authors warn that retrospective clinical-stage associations are not future-success predictions. These are useful extensions or design references, not reasons to delay SciFact. ([GenomeArena](https://github.com/ksenia007/alvessa_agent), [BiomniBench-DA](https://huggingface.co/datasets/phylobio/BiomniBench-DA), [TargetBench](https://www.nature.com/articles/s41598-026-47765-3))

## Improve interpretation without rebuilding existing safeguards

The maintained-code inspection covered 85 Python files across the core and facade. TETHER already implements immutable evidence, ancestry and hypothesis checks, declared study/cohort grouping, bounded caches, fixed review stages and complete accounting. Its restricted specialist output selects observation IDs; structural interpretation checks explicitly do not establish scientific entailment. That is the most important capability gap. ([Inspection scope](<D:/Projects/drug_target_agents/research_notes/TETHER benchmark priorities and methods/implementation-scope.json>), [selection contract](D:/Projects/drug_target_agents/src/asof/agents.py:46), [interpretation boundary](D:/Projects/drug_target_agents/src/asof/study/diagnostic_codec.py:604))

| Addition and peer method | Current status | Test of value and falsification condition |
|---|---|---|
| **Joint claim/rationale interpretation — MultiVerS** | Semantic capability unqualified; an LLM study seam exists, while a native-compute adapter is missing. | Compare full-context versus extracted-text interpretation using native labels/rationales. No gain if supported useful answers do not improve or context loss creates errors. ([Method](https://aclanthology.org/2022.findings-naacl.6/), [LLM seam](D:/Projects/drug_target_agents/src/asof/study/session.py:75)) |
| **Semantic critic plus bounded repair — Alvessa** | Structural review exists; source entailment and repair quality unqualified. | Compare no critic, critic-only and one repair under equal budgets; count repaired errors and damaged valid answers. An extra role alone is not evidence of value. ([Peer architecture](https://github.com/ksenia007/alvessa_agent), [current critique](D:/Projects/drug_target_agents/src/asof/agents.py:169)) |
| **Retrieval/reranking — R2E and retrieval-augmented evaluation** | Literal overlap retrieval implemented; BM25/dense/reranker absent from audited maintained paths. | Compare relevant-document recall and downstream correctness at equal context limits. Reject added complexity if improved retrieval scores do not improve useful completion. ([R2E](https://aclanthology.org/2025.acl-long.167.pdf), [current retrieval](D:/Projects/drug_target_agents/src/asof/retrieval.py:24)) |
| **Rationale interventions — ERASER** | Evidence masks and neutral views exist; combined answer experiment unqualified. | Remove decisive evidence, retain rationale alone, and add irrelevant/placebo evidence. Use native ERASER metrics only with the required class scores; prediction changes are a separate measure. Neither masking loss nor correct citations prove reasoning. ([Method](https://aclanthology.org/2020.acl-main.408/), [existing masks](D:/Projects/drug_target_agents/tools/framework/compare_development.py:117)) |
| **Selective answering — reject-option methods** | Coverage/chronology abstention implemented; calibrated semantic risk missing. | Freeze thresholds on separate source groups; compare risk at matched coverage and correct-admitted yield. Reject a gain obtained only by refusing harder tasks. ([Method](https://arxiv.org/abs/1705.08500), [current gate](D:/Projects/drug_target_agents/src/asof/scorer.py:130)) |
| **Dependence-aware uncertainty — grouped evaluation** | Transitive study/cohort grouping implemented; upstream identities incomplete. | Split/resample by justified source families; test duplicate-source invariance. Distinct unknown IDs cannot establish independence. ([Grouping](D:/Projects/drug_target_agents/src/asof/features.py:34), [Inspect clustered metrics](https://inspect.aisi.org.uk/metrics.html)) |
| **Scientific process assessment — BiomniBench** | Execution traces exist; statistical-method quality unqualified. | Later test a bounded analytical task against its rubric, including plausible wrong analyses and judge disagreement. Trace completeness or polished prose cannot substitute for sound methods. ([Task format](https://huggingface.co/datasets/phylobio/BiomniBench-DA)) |

These are proposed transfers, not predicted effect sizes. The documented lineage is narrower: SciFact's repository identifies MultiVerS as a later verification model; original LAB-Bench leads explicitly to LABBench2. R2E, ERASER, Alvessa and TETHER are compared methodologically here, without asserting citation ancestry. ([SciFact update](https://github.com/allenai/scifact), [LABBench2 lineage](https://github.com/EdisonScientific/labbench2))

Conformal risk control should remain conditional: its guarantee concerns a specified bounded monotone loss under exchangeability, not automatically error among answered cases. Similarly, AgentDojo's hostile tool-return experiments and tau-bench's repeated all-success reliability are useful later designs, but an inert verifier cannot demonstrate interactive agent security or reliability. Borrow the controls before claiming native benchmark performance. ([Conformal risk control](https://arxiv.org/html/2208.02814), [AgentDojo](https://arxiv.org/abs/2406.13352), [tau-bench](https://arxiv.org/abs/2406.12045))

## Run comparisons that can reveal both benefit and harm

First qualify one native SciFact producer, scorer and immutable input set, with reference labels/rationales isolated from answering. Split calibration and evaluation by justified source/claim groups before threshold selection. Preserve the official retrieval-versus-supplied-evidence distinction. Public development performance remains development performance; dataset dates do not prove a model never encountered the questions. ([SciFact release](https://github.com/allenai/scifact), [current stage plan](<D:/Projects/drug_target_agents/planning/TETHER Benchmark Execution Plan 2026-11-02.md>))

Use **two complementary comparisons**. For admission effects, produce candidates once and pass identical candidate/source artifacts through ungated reporting and separately qualified native-contract extensions of the independent checker and TETHER; add Inspect in its planned stage. BG02's existing archive validators do not already support SciFact labels/rationales. For end-to-end behavior, hold model, evidence, tools, revision opportunities and total budget fixed. If a new semantic model is added, separate provenance-only from provenance-plus-semantic-checking conditions. Otherwise an improvement can arise from extra inference rather than the framework. Source-provenance, stable-read, journal and all-case aggregation primitives are reusable; the current study session requires prompt/token accounting. A trained sparse baseline needs a native-compute adapter with appropriate non-token accounting. ([Session requirements](D:/Projects/drug_target_agents/src/asof/study/session.py:113), [aggregation](D:/Projects/drug_target_agents/src/asof/study/source_fact_evaluation.py:192))

Report native metrics alongside **correct-and-admitted / all scheduled tasks**, coverage, correct-but-rejected outputs, policy-ineligible admissions, semantic errors, input unavailability and operational/judge failures. Wrong-but-provenance-valid is different from violating a source-eligibility rule. Default framework accuracy can omit scorer failures, so retain the complete scheduled denominator separately. Include retrieval, generation, judging and verification costs, failed calls, startup and peak memory. Repeated stochastic answers require a separate reliability design; BG02's deterministic repeats do not supply it. ([Inspect scoring policy](https://inspect.aisi.org.uk/scoring-policy.html), [tau reliability design](https://arxiv.org/abs/2406.12045))

The immediate decision remains **SciFact → one original LAB-Bench family → equal-policy Inspect**. ALCE and ranking/analytical extensions follow only when the native answer route works. Existing public annotations support these tests without recruiting new external reviewers; they still do not validate unrestricted biomedical conclusions. The paper's argument should depend on whether explicit controls preserve useful answers at an acceptable measured cost. A fair comparison that finds parity or harm should remain in the report rather than trigger a search for easier claims.
