# TETHER Gains Value Through Explicit Admission

**TETHER's most defensible contribution is an executable temporal, hypothesis and lineage admission contract joined to source replay.** The retained study demonstrates bounded fidelity to selected source fields; it does not validate target prediction, biomedical reasoning, or unique generic verification. Closely related systems already check evidence, record provenance and support reproducible execution, while several evaluate substantially harder scientific decisions. This audit confirms three new, bounded correctness defects and identifies repeated computation worth addressing in a new version. The most useful immediate additions are a clearer admission/exactness/coverage analysis and an honest verification-cost breakdown; the strongest future experiment compares TETHER with a simpler, independently implemented validator enforcing the same policy. **All fixes and new experiments below are recommendations, not implemented changes.** ([Current working manuscript](<D:/Projects/drug_target_agents/paper/revisions/20261102/manuscript.md>); [independent counterexample review](<D:/Projects/drug_target_agents/research_notes/TETHER efficiency and comparative value/peer_checks.md>))

Audit date: 2 November 2026. Code baseline: `b8d107059c781bb96ab27807f857f1127ed09608`; current interface: TETHER 0.5.0 over the frozen AsOf 0.3.11 engine. Earlier dated reviews describe their own completed scopes and do not certify absence of subsequent findings. The present work leaves runtime code, scientific results and sealed paper/release artifacts unchanged. ([Runtime pins](<D:/Projects/drug_target_agents/research_notes/TETHER efficiency and comparative value/runtime/pins-v1/runtime_inventory.json>); [preceding closure assessment](<D:/Projects/drug_target_agents/planning/Project Progress Reassessment 2026-11-02 - Corrected Working Paper.md>))

TETHER's literal arm solves a deliberately bounded source-reporting task. Its twelve selected units, 24 native outputs, fourteen constructed controls, 38 total outputs and ninety repeated policy decisions are different denominators; none supplies a therapeutic-performance comparison. The current 0.5.0 interface is also later than the frozen study, so its guarantees cannot be retroactively assigned to that experiment. ## Three counterexamples expose bounded correctness gaps

All three findings below have independent paired controls and **P2 severity in their stated scope**. They warrant correction without implying that the historical paper's numerical results are false. No contaminated scientific claim, actual token expenditure, or production data destruction was demonstrated; the probes use fictional inputs. Passing historical suites and the targeted tests in this audit do not cover every relationship: these counterexamples exercise relationships those tests did not assert. ([Peer results and controls](<D:/Projects/drug_target_agents/research_notes/TETHER efficiency and comparative value/peer_checks.md>))

### A report destination can destroy its input receipt

**P2 — supporting transport utility.** [Test-DownloadBatch.ps1:24](<D:/Projects/drug_target_agents/tools/data/Test-DownloadBatch.ps1:24>) reads and validates a receipt; [line 69](<D:/Projects/drug_target_agents/tools/data/Test-DownloadBatch.ps1:69>) starts unrestricted report publication. Passing the same receipt path as `OutputPath` makes the utility exit successfully with `complete=true` while replacing the evidence it just validated. The independent control used a twenty-byte fictional CSV: raw bytes remained unchanged, but the next verification with a separate report failed because the receipt identity had disappeared. A separate new report destination preserves the receipt, and a wrong-dataset receipt still fails correctly. This is a new output/input alias defect, distinct from the earlier fixed identity-comparison bug. ([Paired witness](<D:/Projects/drug_target_agents/research_notes/TETHER efficiency and comparative value/evidence-v1/peer-controls-results.json>))

The practical risk is loss of required provenance after a reported successful check. Reject an existing destination before expensive work and publish exclusively to a fresh path. If mutable report replacement is deliberately supported, explicitly prohibit aliases to every queue, source and receipt, including filesystem identity aliases. Acceptance should show that identical-path, equivalent-path and supported hard-link alias cases fail without modifying any input; a fresh output succeeds; collision and partial-failure behavior retains evidence. Ordinary report overwriting alone is a retention-policy concern, not a second proven correctness bug. ([Pipeline diagnosis](<D:/Projects/drug_target_agents/research_notes/TETHER efficiency and comparative value/pipeline_argument.md>))

### Validated over-reservation usage disappears before accounting

**P2 — opt-in local-model/legacy engine path.** [local_model.py:194](<D:/Projects/drug_target_agents/src/asof/local_model.py:194>) raises a plain `ContractError` after parsing a valid response whose reported usage exceeds its reservation. The general-error branch at [workflow.py:200](<D:/Projects/drug_target_agents/src/asof/workflow.py:200>) replaces that known usage with the smaller quote, marks it unmeasured and then checks for a reservation violation against the substituted value. The inner attempt fails, but subsequent category dispatches continue. Failed-archive verification also accepts quoted accounting without reconciling the parseable retained response. ([Archive checker](<D:/Projects/drug_target_agents/src/asof/local_model.py:109>))

In the counterexample, each fake response reports 1,000,000 input tokens and one output token. Against a 100,000-input-token workflow budget, **eight fake calls continue**, leaving responses that report 8,000,000 input tokens while accounting records only 36,365 estimated input tokens, zero measured usage and no usage-contract violation event. A nearby fifty-input-token control correctly records 400 input/eight output tokens across eight calls. These are validated adapter reports, not independently authenticated physical consumption. Current schema-2 `run` excludes local-model/replay/scorer options, so this is not a failure in its offline token budget. ([Independent results](<D:/Projects/drug_target_agents/research_notes/TETHER efficiency and comparative value/evidence-v1/peer-controls-results.json>); [strong-mode restriction](<D:/Projects/drug_target_agents/packages/tether/src/tether/_presentation.py:254>))

Preserve already validated reported usage through `BackendFailure(usage)` or an explicit failed-call result, record the breach and stop before any further dispatch. Reconcile such usage in the retained archive. Acceptance for this witness is one call, 1,000,000 reported input tokens accounted, one violation, no selected claim and no later dispatch. Malformed or unavailable usage must remain explicitly unknown/estimated; it must not be invented as measured. Correct a new engine/version or adapter boundary without silently changing frozen 0.3.11 artifacts or reopening closed model attempts. ([Existing measured-failure branch](<D:/Projects/drug_target_agents/src/asof/workflow.py:190>))

### An unused granted raw node can carry contradictory time evidence

**P2 — current 0.5.0 whole-inventory consistency claim.** An explicitly granted raw node declares `known_public_by=2022-01-01` using a pinned `public_download_receipt` completed in 2024, against a 2023 case origin. Bytes, transport identity and policy/snapshot declarations agree, but the receipt contradicts the asserted public-by bound. When unused, the node is accepted with `artifact_policy_consistency_verified` and four checked inputs. A qualified installed 0.5.0 witness also completes a fictional outer run and anchored verification. Making the identical node an ancestor of the used mapping rejects it before dispatch with the expected receipt-bound error. **No claim from the contradictory unused node was admitted.** ([Installed positive/negative witness](<D:/Projects/drug_target_agents/research_notes/TETHER efficiency and comparative value/runtime/evidence-v1/installed-witness.json>))

The gap is between [policy cutoff checking](<D:/Projects/drug_target_agents/packages/tether/src/tether/_catalog_policy.py:421>), [outer receipt checking](<D:/Projects/drug_target_agents/packages/tether/src/tether/_catalog_binding.py:113>) and the stronger relationship check in [provenance.py:127](<D:/Projects/drug_target_agents/src/asof/provenance.py:127>), reached only through used ancestry. This requires contradictory metadata to be registered in both supplied policy and snapshot; it is not arbitrary ungranted-input injection. Apply the receipt/availability relationship to every supplied raw node when promising whole-inventory consistency, independently of reachability. Acceptance should reject used and unused contradictions before dispatch and during verification, reject mismatched evidence references/URLs, and retain valid receipt and alternative-basis controls. A later download receipt must not become proof of earlier availability. ([Declared scope](<D:/Projects/drug_target_agents/docs/TETHER-CATALOG-POLICY.md:35>); [independent narrowing](<D:/Projects/drug_target_agents/research_notes/TETHER efficiency and comparative value/peer_checks.md>))

## Repeated work offers savings within explicit stability boundaries

The best optimization target is computation repeated over an immutable value within one operation. In the frozen reporting compiler, the validated task is frozen, yet its fingerprint is recomputed per field plus three fixed uses. A shared JSON original is also reread and parsed for every selected row. The following synthetic measurements instrument real parser/hash behavior under the existing Windows source locks; they measure logical work, not physical I/O or an optimized speedup. The fixtures contain an unselected one-MiB JSON string, and instrumentation itself adds overhead. ([Compiler probe and results](<D:/Projects/drug_target_agents/research_notes/TETHER efficiency and comparative value/runtime/evidence-v1/accounting-and-compiler-probes.json>); [per-field hash](<D:/Projects/drug_target_agents/src/asof/study/source_fact_sources.py:486>))

| Selected rows / fields | Original bytes | Whole-file JSON reads | JSON logical bytes | Unchanged-task hashes |
|---|---:|---:|---:|---:|
| 1 / 4 | 1,048,724 | 1 | 1,048,724 | 7 |
| 8 / 32 | 1,049,522 | 8 | 8,396,176 | 35 |
| 32 / 128 | 1,052,280 | 32 | 33,672,960 | 131 |

Hoist the task fingerprint and encoded scope out of field loops, preserving exact fact identifiers and output bytes. Then group selections by canonical source identity and parse each JSON source once inside its existing stable-file lifetime. Process one bounded source group at a time to avoid trading repeated reads for an unbounded memory cache. Preserve deadlines, duplicate-key/representation checks, locator behavior and output order. Parquet replay opens/scans a row group per locator; batching columns and requested rows by file/row group is plausible, but its benefit was not measured. The compiler also rehashes a locked original after graph verification, another scoped candidate for reuse. ([Source loop](<D:/Projects/drug_target_agents/src/asof/study/source_fact_sources.py:405>); [JSON selection](<D:/Projects/drug_target_agents/src/asof/study/source_fact_sources.py:234>); [stable-file primitive](<D:/Projects/drug_target_agents/src/asof/study/stable_read.py:122>); [Parquet replay](<D:/Projects/drug_target_agents/src/asof/study/source_rows.py:169>))

Current 0.5.0 policy preparation performs **five whole-raw-file hash passes before child dispatch** in the instrumented path: three wrapper/stable-helper passes and two engine passes. A 20,001-byte fictional original therefore accounts for 100,005 logical hash bytes. This count is confirmed, but it does not prove that all five checks are redundant: original preparation, copied-control verification and immediate pre-dispatch verification cross different times and trust boundaries. Post-child and later independent verification address additional mutation windows. The fixture's 0.302 seconds is not a source-throughput benchmark, and this new call-path count is not the old P06 workload measurement. ([Count witness](<D:/Projects/drug_target_agents/research_notes/TETHER efficiency and comparative value/runtime/evidence-v1/policy-and-hash-probes.json>); [preparation](<D:/Projects/drug_target_agents/packages/tether/src/tether/_catalog_binding.py:186>); [outer repeat](<D:/Projects/drug_target_agents/packages/tether/src/tether/_presentation.py:263>))

A safe consolidation requires an operation-scoped proof object or immutable snapshot that binds bytes, receipt checks, policy version, intended use, hypothesis, cutoff and ancestry. The child currently reopens paths, so crossing that boundary needs a specified stability protocol, not merely passing a cached digest. A path/size/mtime cache cannot substitute for the present content guarantee. Test source mutation and same-size replacement at every permitted boundary, and preserve fresh independent verification. Evaluate byte-identical outputs, rejection equivalence, logical bytes, parse counts, wall/CPU time and peak memory; use controlled cold/warm runs before claiming speed. ([Runtime refactor analysis](<D:/Projects/drug_target_agents/research_notes/TETHER efficiency and comparative value/runtime/runtime_audit.md>))

The maintenance audit found seventeen exact AST duplicate-function groups with a minimum nine-line span, primarily versioned renderers and packagers. **Frozen reproduction copies are intentional**, including the v1/v2 packet lifecycle and a portable builder that avoids importing historical producer code. No dead shim was proved removable. An explicit maintained/frozen/retired inventory would clarify routing; a shared core is appropriate only for actively maintained paths with a common contract and differential tests. Preserve historical hashes. Concrete repeated computation is a better refactoring priority than code volume or the mere presence of wrappers. ([Tool inventory](<D:/Projects/drug_target_agents/research_notes/TETHER efficiency and comparative value/evidence-v1/pipeline-tool-inventory.json>); [Q06 build recipe](<D:/Projects/drug_target_agents/planning/review-assets/tether-q06-20261102/BUILD-RECIPE.md>))

The local `.venv` exposes current editable source but reports TETHER distribution metadata 0.4.1. That drift makes it unsuitable for a current successful code-proof claim; fail-closed rejection is not a platform bug. Installed witnesses instead use the existing qualified 0.5.0 environment, whose eighteen launcher members and all sixty-six installed engine source members match the checkout. No environment was changed. ([Environment and source equality](<D:/Projects/drug_target_agents/research_notes/TETHER efficiency and comparative value/runtime/pins-v1/runtime_inventory.json>))

## A matched conformance study would test the central claim

The highest-value future study needs **three matched implementations**: a minimal typed extractor with source-hash/schema checks as a diagnostic ablation; a simple, independently written deterministic validator enforcing the **same temporal, hypothesis and lineage rules** as TETHER; and TETHER itself. Use the same inputs, output requirements and budgets. The weaker baseline identifies the value of omitted requirements, largely repeating the logic of P05; expected victories over it cannot establish unique TETHER benefit. The policy-equivalent baseline tests whether the architecture improves end-to-end admission, replay, accounting and recovery at an acceptable resource and maintenance cost. If both full-policy implementations make zero errors and TETHER is slower or materially more complex, that falsifies an efficiency/architectural-benefit claim and supports the narrower reference-implementation position. This is a proposed design, not an existing result. ([Comparative design rationale](<D:/Projects/drug_target_agents/research_notes/TETHER efficiency and comparative value/comparative_systems.md>))

Specify desired decisions independently of candidate code, freeze the fault suite before execution, and include valid near misses so blanket rejection cannot win. Vary intended action/modality/tissue, late mapping ancestors, evaluator ancestry behind an intermediate, valid new computations from old inputs and contradictory used/unused inventory records. Measure false admissions and false rejections separately by fault family, alongside wall time, peak memory and logical bytes. Current counterexamples are now exposed regression cases; they cannot become unseen-test evidence. This experiment needs no model. A contract-matched component comparison is also distinct from a full Virtual Biotech reproduction with its documented inputs/tools; neither was run here. A larger generator or more copying cases would not resolve the central contribution question.
