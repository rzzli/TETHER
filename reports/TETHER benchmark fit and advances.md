# TETHER benchmark fit and advances

**TETHER's strongest next paper would demonstrate that its evidence controls preserve useful answers while preventing identifiable errors, at an acceptable cost.** The best immediate sequence remains the independent equal-policy comparison, native SciFact evaluation, one original LAB-Bench family, and an Inspect implementation enforcing the same obligations. ALCE is the strongest subsequent citation-quality extension. General agent benchmarks become useful only when TETHER has the interactive capabilities they test. The largest missing methods are qualified semantic support checking, controlled evidence-use experiments and selective-answering evaluation; provenance, bounded retrieval, dependence grouping and failure accounting already exist. This research adds no benchmark result: BG02 remains unscored, and native SciFact, LAB-Bench and Inspect evaluations remain unfinished. ## Peer systems test different parts of TETHER

TETHER is currently an evidence-admission, source-reporting and execution-verification harness with bounded specialist selection and separate study interfaces. Its core `Selection` returns observation IDs and usage; it does not produce SciFact support/contradiction labels or a LAB-Bench answer. The existing local-model interface and fixed role chains therefore cannot be counted as a qualified scientific solver. The retained literal assembler reached exact source reporting on twelve native units: this is a deterministic copying baseline, not model performance. Stronger evidence now requires a task where interpretation or evidence selection can fail while copying remains correct. ([Selection contract](<D:/Projects/drug_target_agents/src/asof/agents.py:46>); [study interface](<D:/Projects/drug_target_agents/src/asof/study/session.py:75>); [retained results](<D:/Projects/drug_target_agents/paper/results/tables/native_case_results.md>))

Virtual Biotech and Biomni are useful scientific-system peers, but their breadth is not a direct baseline for this endpoint. Virtual Biotech delegates across scientific divisions and assembles clinical annotations from registries, literature and disclosures; its distinction between phase progression and endpoint success matters for any future clinical comparison. Biomni combines a biomedical environment with tool planning and code-based analysis. TETHER has relevant evidence controls, but has not reproduced either full system. A matched subtask can test incremental value; comparing a source validator against an entire discovery agent would conflate different inputs, outputs and resource budgets. ([Virtual Biotech](https://pmc.ncbi.nlm.nih.gov/articles/PMC12970349/); [Biomni paper](https://www-cs-faculty.stanford.edu/people/jure/pubs/biomni-biorxiv25.pdf); [current scientific limits](<D:/Projects/drug_target_agents/paper/revisions/20261102/manuscript.md:153>))

Inspect is the more direct framework comparator. It already supports external-agent integration, scorers, logs, limits and tool approval. Its current bridge documents execution once per model-proposed tool call with matching arguments. General orchestration and dispatch governance therefore cannot be presented as uniquely TETHER. The question is whether TETHER's particular historical-availability, hypothesis, authorized-use and transitive-lineage contract adds useful assurance, and how much code and runtime cost are needed to implement the same contract elsewhere. Ordinary evaluation logs do not automatically establish those domain-specific guarantees. ([Inspect bridge](https://inspect.aisi.org.uk/agent-bridge.html); [TETHER obligations](<D:/Projects/drug_target_agents/planning/review-assets/tether-equal-policy-20261102/POLICY-SPEC.md>))

Two comparisons answer different questions. **Fixed candidate artifacts** isolate what admission rules accept or reject. **Fresh matched executions** assess the whole workflow while holding model, tasks, accessible evidence, tools and budgets constant. A hash/schema-only arm is useful for identifying omitted-policy effects; it cannot establish superiority over an equal-policy architecture. Likewise, replaying gold answers qualifies adapters and verification, not task answering. ([Authorized comparison design](<D:/Projects/drug_target_agents/planning/TETHER Benchmark Execution Plan 2026-11-02.md:19>))

## Five comparisons cover the immediate research claims

The following order preserves the active execution plan. “Available” means a documented public route, not successful local acquisition or native execution. Every external object still needs an exact revision, source and scorer hashes, terms review and reference isolation. Public development scores must remain development scores; a dataset's release date does not establish that model weights have never encountered its answers. ([Current roadmap](<D:/Projects/drug_target_agents/TODO.md:26>); [existing exposure limits](<D:/Projects/drug_target_agents/paper/revisions/20261102/manuscript.md:159>))

There is a practical reuse opportunity for LAB-Bench. Inspect Evals exposes `lab_bench_litqa` and `lab_bench_dbqa`, pinning dataset revision `5c77cec648430f30611808808861eb86f81d5eaa`. The base adapter maps question, ideal answer, distractors and ID, appends an insufficient-information option and shuffles choices. Its scorer distinguishes that option, while custom metrics calculate answered-question precision and coverage. This is externally available code, not an installed TETHER integration, and the base prompt is not a qualified literature-retrieval pipeline. No built-in Inspect SciFact integration was established in the checked sources. ([Task code](https://raw.githubusercontent.com/UKGovernmentBEIS/inspect_evals/main/src/inspect_evals/lab_bench/lab_bench.py); [sample mapping](https://raw.githubusercontent.com/UKGovernmentBEIS/inspect_evals/main/src/inspect_evals/lab_bench/record_to_sample_helpers.py); [metrics](https://raw.githubusercontent.com/UKGovernmentBEIS/inspect_evals/main/src/inspect_evals/lab_bench/metrics.py))

Generic tasks should enter through a separate typed study adapter and verifier, preserving their native claim/document or question/option semantics. Inventing therapeutic target IDs to fit T1/T6 would obscure what was tested. Before full execution, validate parser/scorer behavior with invented records, establish that a producer can answer positive controls, freeze splits and sources, then schedule every case. Unavailable source papers remain explicit access limitations; they cannot be reconstructed from evaluator answers. ## Peer methods expose semantic and evaluation gaps

The decisive distinction is between **correctly tracking evidence and correctly interpreting it**. TETHER's interpretation codec explicitly excludes scientific entailment. Its citation-review utility checks supplied judgments and cited bytes, not whether those judgments are true. ALCE evaluates citation support using learned inference; SciFact supplies support/contradiction and rationale references. These offer measurable semantic targets, but neither turns an NLI judgment into formal proof. Their relationship to TETHER is a methodological comparison, not an asserted citation lineage. ([Codec](<D:/Projects/drug_target_agents/src/asof/study/diagnostic_codec.py:603>); [audit limitation](<D:/Projects/drug_target_agents/tools/science/t6_claim_audit.py:186>); [ALCE evaluator](https://raw.githubusercontent.com/princeton-nlp/ALCE/main/eval.py))

|---|---|---|

[SciFact](https://github.com/allenai/scifact); [MultiVerS](https://github.com/dwadden/multivers) | Score native labels/rationales, including contradiction and insufficient evidence. Compare relevant, absent and irrelevant evidence. No semantic benefit if checking merely echoes the generator or removes errors only by rejecting more valid answers. |

The primary denominator should be **all scheduled tasks** for useful completion. Keep native benchmark accuracy/F1 alongside correct-and-admitted completion, valid rejection, unsafe admission, abstention and operational/judge failures. Define unsafe admission against the frozen tested rule or reference, such as an ineligible source or a claim rejected by a qualified semantic check. Separately report a wrong answer admitted by a provenance-only policy; source integrity does not promise scientific correctness. Conditional accuracy among admitted answers is informative only with its coverage. This is especially important when using Inspect: current documentation distinguishes wrong answers, scorer exceptions and unscored judgments, with the latter two potentially excluded from accuracy. Default epoch averaging can also obscure an unscored repeat, so retain unreduced records and reconstruct the scheduled denominator independently. TETHER already has a complete-cell aggregator; preserve it rather than proposing failure accounting as new. ([Inspect scoring policy](https://inspect.aisi.org.uk/scoring-policy.html); [local aggregator](<D:/Projects/drug_target_agents/src/asof/study/source_fact_evaluation.py:192>))

Cost comparisons require equivalent boundaries. Include imports, preparation, source verification, retained copies, retrieval, model and judge calls. Distinguish adapter-reported usage, conservative estimates and actual billing; pin any price assumptions. Report logical bytes separately from physical I/O and process peak memory separately from allocation tracing. Existing study/source/cohort grouping is valuable, but unknown upstream identities remain unknown dependence. Cluster analysis by justified task, paper or study units; repeated fields, policy projections and seeds do not automatically increase the independent sample size. ([Existing resource limits](<D:/Projects/drug_target_agents/paper/results/tables/resource_phases.md>); [dependence implementation](<D:/Projects/drug_target_agents/src/asof/features.py:34>); [Inspect metrics](https://inspect.aisi.org.uk/metrics.html))

## New releases strengthen the plan without blocking it

The most useful update to the November 2 survey is **LABBench2**, explicitly developed from the original LAB-Bench research line. Its open-response tasks include SourceQuality, which asks why a study cannot answer a research question. That tests scientific appropriateness beyond provenance and literal fidelity. It is conditional: the official dataset requires accepting conditions and sharing account information, and both data and harness changed in 2026. The documented SourceQuality replacement and later answer correction need distinct version pins; the harness states that published results used an earlier implementation. A current run must not be described as an exact reproduction of those paper results. These access requirements should not delay the original public LAB-Bench route. ([LABBench2 paper](https://arxiv.org/html/2604.09554v2); [dataset/changelog](https://huggingface.co/datasets/EdisonScientific/labbench2); [harness history](https://raw.githubusercontent.com/EdisonScientific/labbench2/main/README.md))

The October 27 preprint **Identity or Evidence?** supplies a sharper diagnostic for evidence use. It varies named identities and evidence availability with recall, placebo and positive controls. Its limitations are central: masking can remove necessary task context, database identity can be the retrieval key, and some controls remain inconclusive. Its primary LitQA2 redaction analysis uses one model and one fixed mask; selected other comparisons were repeated with a smaller model. These results do not establish a universal effect or prove memorization. Adopt the controlled design as a new task-specific experiment, without treating the preprint as a validated TETHER result or pretending the project's existing masks already perform that full experiment. ([Canonical v1](https://arxiv.org/abs/2610.36510v1); [methods and limitations](https://arxiv.org/html/2610.36510v1); [local implementation assessment](<D:/Projects/drug_target_agents/research_notes/TETHER benchmark fit and advances/current_project_gap_map.md>))

Among domain-specific extensions, **R2E** is preferable when the aim becomes target-side ranking: its public gene-description and literature tasks support rank metrics, but require an actual ranker and declared candidate universe. **GenomeArena/Alvessa** offers closer database/annotation tasks, with unresolved dataset-specific redistribution terms and a substantial full-system environment. **TRQA** requires particular scorer scrutiny: its official code uses model grading even for multiple-choice extraction, and question joins and skipped malformed options need an independent denominator audit. These are potential future tasks, not interchangeable clinical benchmarks. Released clinical labels do not repair input chronology, censoring or endpoint definition. ([R2E data](https://github.com/BenevolentAI/r2e-evaluation-data); [Alvessa](https://raw.githubusercontent.com/ksenia007/alvessa_agent/main/README.md); [TRQA scorer](https://raw.githubusercontent.com/GENTEL-lab/OriGene/main/src/local_deep_research/score_evaluation_results.py))

**BixBench** and **BiomniBench-DA** belong after analytical execution is qualified. The former changes questions across releases and requires computational environments; the latter exposes a gated 50 of 100 tasks and uses model-based process grading. A public-half result cannot represent the full benchmark. TxBench-PP's public repository supplies seven examples rather than the complete evaluation suite. These access and task differences make them poor immediate replacements for SciFact or a single LAB-Bench family. ([BixBench version history](https://huggingface.co/datasets/futurehouse/BixBench/raw/main/README.md); [BiomniBench card](https://huggingface.co/datasets/phylobio/BiomniBench-DA); [TxBench release](https://github.com/latchbio/txbench-pp))

For general-purpose extensions, **AgentDojo** measures indirect prompt injection during legitimate tool tasks; AgentHarm instead measures completion of directly requested harmful tasks. Neither can be won meaningfully by exposing no useful actions. The tau family contributes repeated interactive reliability, but its old repository warns of outdated tasks while current successor documentation uses newer release names and manifests. Pin a corrected exact release; current custom subsets are not official full-benchmark scores and simulator/judge access adds cost. CRAG is the lighter conditional alternative for factual QA and abstention, but its query timestamps do not supply complete historical lineage. ([AgentDojo](https://github.com/ethz-spylab/agentdojo); [AgentHarm](https://www.aisi.gov.uk/research/agentharm-a-benchmark-for-measuring-harmfulness-of-llm-agents); [tau release warning](https://raw.githubusercontent.com/sierra-research/tau-bench/main/README.md); [current execution rules](https://raw.githubusercontent.com/sierra-research/tau2-bench/main/docs/running-the-benchmark.md); [CRAG schema](https://raw.githubusercontent.com/facebookresearch/CRAG/main/docs/dataset.md))

The immediate implementation order therefore stays intact: finish BG02's complete frozen comparison, build and evaluate an actual SciFact solver, complete one source-feasible original LAB-Bench family, then test Inspect with equal obligations. Include semantic, coverage, cost and exposure controls within those protocols rather than adding gated prerequisites. Equal correctness with materially worse cost or maintenance would narrow TETHER's contribution to a reference implementation; improved error prevention with preserved useful completion would support a stronger assurance claim. Either outcome would inform the paper if the comparison is fair. No external-expert gate, paid execution, clinical-success claim or completed benchmark is introduced by this review.
