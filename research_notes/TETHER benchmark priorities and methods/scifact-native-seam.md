# Native SciFact integration: bounded architecture recommendation

Planning review only, 2026-11-05. No source, frozen experiment, model or benchmark was executed or changed. This recommendation supplements the BG03 protocol; each proposed interface remains unimplemented and needs qualification.

`StudySession._capacity` requires a prompt, `n_predict`, positive context/output token limits and an input-token reservation at least UTF-8 prompt bytes plus 32. A scikit-learn learner is not this backend. Do not invent prompt tokens, call measured compute a token quote, or bypass capacity validation. [Existing capacity contract](D:/Projects/drug_target_agents/src/asof/study/session.py:113).

Add a separate native-task plugin/session, potentially `src/asof/study/native_task.py`, `src/asof/study/scifact.py` and a small facade study entrypoint. These are proposed paths. Keep T1/T6 `Case` and the LLM study interface unchanged. A native task contains benchmark/split/version identity, claim ID/text, exact corpus/projection/model pins and a cutoff; output contains native document IDs, allowed labels and sentence indices. There is no invented gene, indication, intervention or modality. Actual `Snapshot`, `SourceNode` and `Availability` can represent target-free source lineage. [Contracts](D:/Projects/drug_target_agents/src/asof/contracts.py:205).

Reuse `InputGraph`, `catalog_index`, role and receipt checks for admitted original release bytes. `InputGraph.exclusion` needs the cutoff; the existing source-reporting compiler already supplies a cutoff-only context rather than a fabricated `Case`. Do not reuse that compiler's full task schema: its records and join authority are target/indication-specific. Use the real stable-read, journal and atomic-publication primitives. Add native event semantics rather than claiming generic `inspect_run` understands new compute events. Independent verification must reconstruct the new native schedule, resource totals and source/prediction bindings. Resource fields should be wall time, CPU time, peak memory, training/prediction calls, examples/documents/features and artifact bytes; token usage is `null`/not applicable and provider spending is zero. ## Mixed-container and training authority are a new boundary

The downloaded tarball contains logically different products. Treat it as a **preparation-only distribution container**, not universally evaluator-only and not an inference-readable evidence file. Retain its genuine download receipt and exact member identities. Do not manufacture public-download receipts for extracted files or silently exempt descendants of an evaluator-only parent.

A new, explicitly reviewed projection authority must distinguish physical containment provenance from permitted information dependencies. Retain container/member/field hashes and transformation code/configuration in a preparation receipt. Purpose-specific grants identify corpus, train questions/labels, held-out question fields and held-out answers. Whole raw development files and `cited_doc_ids` must not be passed to open-retrieval prediction. Claim-only questions are task inputs, not scientific evidence. Rooting a projection at a trusted compiler is a newly tested policy boundary, not an existing canonical guarantee.

`SourceNode` permits only `agent_evidence` and `reference`; neither encodes training versus prediction purpose. Do not invent `training_reference` or relabel development gold as `reference`. Keep three explicitly typed proof domains: admitted source/corpus bytes; fitting/model provenance; evaluator/query-authoring provenance. Join them in the final native receipt. The fitted model's information parents may include permitted training labels, but never held-out answer products. Container provenance remains visible in the preparation proofs even when answer products are excluded from predictor capabilities. [Role vocabulary](D:/Projects/drug_target_agents/src/asof/provenance.py:22).

Current schema2 `authorize_snapshot` binds a therapeutic case/use/frame and is not a drop-in SciFact policy. Label the new route as a native task extension using TETHER primitives and a new purpose/field policy; do not claim all 27 BG02 obligations, hypothesis semantics or full canonical outer-run parity automatically apply. Predictor staging/access audits establish a reviewed code boundary, not an OS sandbox or protection against malicious host owners. [Existing authorization boundary](D:/Projects/drug_target_agents/packages/tether/src/tether/_catalog_policy.py:363).

## Minimal qualification and comparison gates

1. Qualify container extraction and field projection: safe names, no links/traversal/duplicates, exact member hashes, bounded inputs, complete lineage and current availability. A receipt proves availability by acquisition time, not historical eligibility.
2. Mutate held-out labels/rationales/cited-document fields and verify predictor-view bytes are invariant. Attempt direct and derived gold-parent injection; both must fail. Trace which files the fitting and prediction workers open, retaining the code-level isolation limitation.
3. Freeze disjoint training/calibration/evaluation groups. Bind fitted vocabulary, feature construction, hyperparameters, training membership, package versions and parameters to the training receipt. No inference-time fitting on gold or alternate evaluation labels. Prefer safe numeric/JSON model assets or explicitly trusted, hash-bound local loading; do not execute arbitrary archived pickle objects.
4. Test exact native IDs, labels, sentence bounds, duplicate/conflicting outputs and complete claim inventory. Preserve raw predictions. Reference-aware scientific scoring is evaluator-only and separate from source eligibility.
5. Cross-check the pinned official scorer with invented edge cases, including long complete rationales, missing parts, duplicate IDs, empty evidence and wrong labels. The official abstract rationale cap is `max(3, shortest gold rationale length)`, not a blanket three. A policy rejection, timeout and a genuine empty-evidence prediction require separate terminal states even if an evaluation projection uses an empty map.
6. Reserve outputs before work; retain failed/interrupted attempts, measured compute and unknown measurements; test no-clobber, no automatic retry and full scheduled denominators. Keep tokens inapplicable rather than measured zero.
7. Produce candidates once for admission ablations. Both conditions consume identical sealed source/model/candidate bytes. Native solver scores and admitted utility are separate: provenance checks can accept a scientifically wrong label. Any controlled invalid-source mutants form a separate conformance set, never additional native questions or hidden score exclusions.
8. Qualify a separately implemented native-contract checker before claiming an equal-policy native comparison. Existing BG02 validators do not parse SciFact tasks. Account for the projection, compute session and scorer adapters in implementation surface and cost.

No larger model is required if a reproducible train-only sparse baseline can answer the native task honestly. Its weakness is a reportable result; gold replay does not rescue an unsuccessful solver.
