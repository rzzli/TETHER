# Public registry frame and origin-only acquisition readiness

## Can a source-defined frame be acquired without another user AACT archive?

### Takeaway
Yes as a technically plausible **future current-state capture**, using the public ClinicalTrials.gov v2 API; no new user archive is an established dependency. This is documentation/schema readiness, not evidence of complete candidate retrieval, authentic origin-available efficacy rules, historical reconstruction, or clinical feasibility. No trial API request, outcome query, cohort activation, download of datasets/documents, login, or runtime/source change occurred in this investigation (October 23, 2026).

### Cited Findings
- Direct anonymous GET of [OpenAPI YAML](https://clinicaltrials.gov/api/oas/v2) returned HTTP 200, application/yaml, 80,983 bytes. It identifies API 2.0.5 and describes access to the most recent study version. Documented paths are `/studies`, `/studies/{nctId}`, `/studies/metadata`, `/studies/search-areas`, `/studies/enums`, three `/stats/*` endpoints and `/version`; no record-history endpoint is documented there. This establishes the documented surface, not proof that no internal history facility exists.
- Direct anonymous GET of [version metadata](https://clinicaltrials.gov/api/v2/version) returned HTTP 200, 71 bytes, `apiVersion=2.0.5`, `dataTimestamp=2026-10-23T09:00:04`. The [field metadata](https://clinicaltrials.gov/api/v2/studies/metadata) returned HTTP 200, application/json, 175,633 bytes; [search-area definitions](https://clinicaltrials.gov/api/v2/studies/search-areas) returned HTTP 200, application/json, 25,359 bytes. These are schema/metadata responses, not trial records.
- The [OpenAPI specification](https://clinicaltrials.gov/api/oas/v2) supports explicit `fields`, search/filter expressions, `sort`, `pageSize`, `countTotal`, and `pageToken`. Unspecified fields return all fields; branch-node fields include all descendants. Subsequent pages must preserve parameters except countTotal/pageSize/pageToken; an empty page can still have a next-page token. A query consisting only of NCT IDs can cause filters to be ignored. Exact fields and requests must therefore be sealed before dispatch.
- [AACT landing documentation](https://aact.ctti-clinicaltrials.org/landing) was readable and advertises daily registry refresh, cloud SQL and historical downloads, with account creation for database credentials. It is not proof of available anonymous archives or embedded original PDF coverage. Direct GET of [legacy snapshot listing](https://aact.ctti-clinicaltrials.org/downloads/snapshots?type=flatfiles) returned HTTP 404 despite an indexed cached listing. Direct GET of [schema](https://aact.ctti-clinicaltrials.org/schema) returned HTTP 200 **after redirect to** [sign in](https://aact.ctti-clinicaltrials.org/session/new). `/data_dictionary` and `/data-dictionary` both returned HTTP 404. No authentication was attempted.

### Inferences
- Archive acquisition is unnecessary for a new prospective public capture made before its eventual prediction origin; it would not repair historical chronology or the old endpoint truth. This is a proposed route, with actual record transport and completeness still untested.
- API version/dataTimestamp before and after pagination can detect some update drift, but are not documented snapshot isolation. Reject an inconsistent capture; never advertise it as an atomic registry snapshot solely because both timestamps match.

### Gaps
- Study endpoint access, record projection acceptance, complete pagination, rate limits and available frame size were deliberately not tested. Successful metadata requests do not pass these gates.
- General official-document searches incidentally returned trial-history and PDF snippets. No such record/PDF was opened or used as scientific evidence; no trial membership or outcome was extracted. Exposure ledger for later screening: NCT02310321, NCT04332081, NCT03941483, NCT02783729, NCT04612296, NCT04348708, NCT00001393 and NCT00001208. Treat these as exposed to the research/design agent; exclude from any future purported untouched test or explicitly mark development exposure under a frozen policy. Local catalog also contains prior exact-ID access evidence for NCT00000102; it was not re-requested.
- No specific missing user file or credential is established. The observed AACT sign-in/404 limitations are optional-route access findings, not a reason to request an archive.

## What does registry metadata establish about prespecified rules and public availability?

### Takeaway
Structured primary-outcome names, document flags and upload dates locate candidate evidence. They do not establish a full authentic efficacy decision rule, the rule's prespecification, its origin-public availability, or a negative efficacy outcome.

### Cited Findings
- The current [field metadata](https://clinicaltrials.gov/api/v2/studies/metadata) separately describes `protocolSection.outcomesModule.primaryOutcomes` and `documentSection.largeDocumentModule.largeDocs`. LargeDoc children include `hasProtocol`, `hasSap`, `hasIcf`, `date`, `uploadDate`, `filename` and `size`; uploadDate is described as the date uploaded to PRS. Document flags describe included content, not independent verification of the PDF or its statistical validity.
- [NIH's API catalog](https://data.nih.gov/data-sources/clinicaltrialsgov-api) likewise describes metadata/statistics and the most recent trial version. NLM's [modernized website announcement](https://www.nlm.nih.gov/pubs/techbull/mj23/mj23_clinicaltrials_website.html) documents a separate Record History tab for historical versions. That older announcement establishes a historical viewing concept, not current programmatic history access or exact posting chronology for any candidate.
- Direct GETs of [API documentation](https://clinicaltrials.gov/data-api/api), [study-data structure page](https://clinicaltrials.gov/data-api/about-api/study-data-structure) and [results definitions](https://clinicaltrials.gov/policy/results-definitions#DocumentUpload) yielded only a generic 11-line shell through web extraction. Direct results-definitions HTML returned HTTP 200 and 94,247 bytes but did not contain the searched document-upload/prespecification text. Thus this session does **not** claim current policy-body verification from a successful HTTP status. Machine-readable metadata was the readable current schema source.

### Inferences
- Future rule qualification must read the exact original document: identify trial/product/regimen/population, primary efficacy endpoint/estimand, analysis population, comparison, timing, success/failure criterion, missing-data/intercurrent-event handling and multiplicity/interim stopping provisions where applicable. A generic p<0.05 default is prohibited; preserve the authentic rule and any ambiguity.
- Treat document date, PRS upload date, public posting and retrieval timestamp as distinct. A future retrieved-and-hashed source actually captured before the later origin supplies bounded observed availability; a current document dated earlier cannot retrospectively supply historical availability.
- Rules absent from a supplied listing are `not_listed_in_observed_projection`, not proof no protocol/SAP exists. HTTP failure, inaccessible body, identity ambiguity, superseded/unresolved version and no authentic decision rule each retain separate unknown/readiness-failure reasons. Never recode them as efficacy negatives.

### Gaps
- No candidate-level rule yield, origin availability, version integrity or endpoint truth has been measured. Current policy language on mandatory/optional protocol upload was not fully readable and is not relied on to predict source coverage.
- Public record-history viewing is different from original document revision history. The documented API surface does not establish a versioned archive of every protocol/SAP PDF or prove when each file first became public.

## What bounded future acquisition design and access gates should be frozen?

### Takeaway
Use a separately approved origin-readiness pilot with a complete bounded registry denominator and deterministic sampling, before any outcomes or predictions. The following is a concrete **proposal**, not an activated protocol; the coordinator must resolve and seal exact field projection/request bytes, calendar bounds and screen order before dispatch.

### Cited Findings
- The existing catalog marks `clinicaltrials_current` as public-anonymous, contemporary-only, agent evidence for T6, excluded from historical benchmarks and not a label source; `aact_snapshots` is a separately collected seven-archive product with scientific qualification still withheld. These are local product contracts, not an authorization to promote either product's role. [Local catalog](../../data/catalog/sources.json).
- `registry_document_refs` already projects exact NCT-bound document references with flags, filename, dates, size, source JSON pointer and no absence/clinical claim. `fetch_control` already retains original bytes, hashes, sanitized headers, exact URLs, bounded time/bytes and journal receipts, with no automatic retry. Its current URL policy forbids query strings and it requires an exact NCT; it cannot directly execute paginated list queries. [Existing source helper](../../tools/science/source_retrieval.py).
- Existing `select_document`/`verify_document` enforce an exact retained listing, fixed selected filename and size, PDF signature, body hash, host binding and no automatic replacement. They currently require a combined protocol+SAP without ICF and emit evaluator-only/contemporary-only outputs. Separate protocol/SAP documents and new origin-evidence roles need a separately reviewed contract; never weaken old evaluator controls silently. [Document helper](../../tools/science/registry_documents.py).
- The B0 transport is an owned read-only **local PostgreSQL** lifecycle with frozen source-bound queries, not a public API downloader or new-cohort authorization. Its failed scientific/coverage branch remains stopped. [Local B0 transport](../../tools/science/registry_content_transport.py); [remaining gates](../../planning/Remaining%20Scientific%20Gates%20and%20Prospective%20Design%202026-10-23.md).

### Inferences
Proposed finite frame and sequence:
1. Before acquisition, freeze a future readiness capture date R and a closed 30-calendar-day first-public-posting interval ending before R. A later prediction origin F remains unset until readiness passes; never assign F retrospectively. Proposed source population: newly first-posted interventional therapeutic phase-2/phase-2–3 drug/biological studies, all indications/countries/sponsors; predeclare exact phase handling. It estimates readiness only for this registry-defined population, not all clinical development.
2. Enumerate the entire interval first, with a narrow leaf-field frame projection; screen study type/purpose/phase/intervention from retained origin-only fields. This is an exposed source-readiness exercise, never a held-out clinical set; even complete retrieval would cover only its source/date-defined frame. Keep missing or ambiguous phase/type/date in an explicit screen-unknown stratum rather than silently treating as ineligible. Proposed ceilings: 500 interval records, pages of 100, 10 page attempts, 2 MiB/page, 20 MiB total, 10 minutes, one request attempt per exact request. If count/pagination exceeds a ceiling, retain failure and stop; no first-N truncation, moving date window, replacement sample or automatic retry. Revise a fresh interval/protocol before seeing more records.
3. Seal all returned identities, raw-response hashes, source version checks, exclusions and unknowns before document retrieval. Compare countTotal, unique IDs and terminal pagination; duplicate/conflicting IDs, schema drift, unexpected results content, changed capture timestamp, missing token chain or incomplete enumeration stop the frame. Sort locally by SHA256(protocol digest + canonical NCT ID), with NCT as tie-break; take at most 50 from the entire screened candidate/unknown pool. Keep every sampled disposition, including inaccessible sources and unusable rules; no source-rich replacement. N<50 means all candidates, not an instruction to enlarge the interval.
4. Freeze exact per-ID leaf-field design/document projections only after the identity sample seal. Do not request `resultsSection`, HasResults, results dates/tables, WhyStopped, unbounded protocol branches or publication/result references for selecting candidates. Status may be retained only if explicitly required for an origin-risk screen; any stop/outcome-bearing text stays quarantined from source acquisition/selection. Never use document availability as a frame filter. Seal the precise policy for separating outcome text incidentally embedded in protocols before retrieval.
5. For each sampled ID permit at most one listing plus at most two exact eligible protocol/SAP PDFs (16 MiB each, 40-second per-request timeout, 120-second elapsed per attempt, 250 MiB aggregate source cap and 30-minute aggregate elapsed cap). Choose required version(s) by a frozen origin/public-date and document-type rule, never by favorable result or easiest access. A combined protocol+SAP can count as one; if more documents/versions are needed, classify insufficient-under-cap, retain the denominator and do not improvise replacements. Reuse existing bounded receipt/hash/host controls after an explicit new product/request contract is reviewed; do not create an untracked generic downloader.
6. Reconstruct experimental regimen × indication/population × origin phase units and dependencies from origin fields only. Keep ambiguous program mappings as unknown. One registry record can contain several programs; do not count every drug/target as an independent event. Report both record-level sampling denominator and program-level qualified/ambiguous counts. No outcome prevalence or clinical independent-event count can be inferred at this stage.
7. Source review determines readiness, not success/failure. Retain authentic rule present/absent/ambiguous, scope eligible/ambiguous, temporal public proof sufficient/unknown, and access success/failure independently. Later outcome labels require the frozen rule and independent occurrence/ascertainment evidence. No report, terminated/withdrawn status, missing results, failed access and elapsed reporting allowance remain unknown or separate competing/stop states; none automatically yields negative efficacy.
8. A technical acquisition pass requires complete bounded enumeration, exact origin-only projection, all-member disposition accounting and verified original-source provenance. A scientific readiness decision additionally needs a predeclared claim-specific rule/scope/public-availability completeness target and uncertainty criterion, credible independent reference route and a separately justified attainable event/power design. Do not borrow B0's 90% criterion or invent a sufficient clinical N. A failed gate yields revise/stop with no predictions, cohort activation, training, monitoring, public registration or follow-up query.

Actual gates before any future dispatch:
- Exact new dataset role/contract and ancestry: catalog promotion is presently unqualified; preserve old evaluator-only and historical exclusions.
- Exact list request/projection, pagination/response allowlist and safety budget sealed and offline tested. The current exact-NCT transport rejects query parameters, so bounded listing support is an established implementation-contract gap, **not** a missing user file.
- Exact origin-risk/scope screens and missingness rules; deterministic complete-frame membership; explicit handling of accidental outcome text and version ambiguity.
- Readable original PDF source, identity/size/hash and public-capture timing; accessible metadata alone cannot pass authentic-rule review.
- Record request/start/end/receipt UTC times, exact query and returned-field set, API version/dataTimestamp checks, headers, raw-byte/hash pins and transformation version. Treat the original observed payload as the capture; a later changed response is a new version with a new receipt, never an overwrite or repair. A failed/changed frame has no eligibility seal. Document discovery controls must demonstrate exact record-to-file identity and absent/inaccessible/ambiguous classification independently from metadata transport controls; neither is a clinical gate pass.
- Separate statistical/reference activation gates; the present finite caps are operational limits, not clinical power evidence.

### Gaps
- All numeric caps/frame choices above are proposed operational design choices, not measured yields or provider guarantees. The exact source request, leaf-field list, future dates and a feasible independent reference/clinical event plan remain to be sealed by the parent protocol.
- No new access-dependent user action is currently warranted. If a later exact allowed request fails, retain its receipt and escalate that concrete failure rather than speculate about credentials or archives.
