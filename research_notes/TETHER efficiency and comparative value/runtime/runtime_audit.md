# Current runtime correctness and efficiency audit

## What is established about the current implementation?

### Takeaway

Two new internally inconsistent cases are reproducible: validated local-adapter usage above its reservation is discarded and execution continues; and schema-2 admission accepts a contradictory public-download time proof on an unused granted raw node. Separately, current policy preflight and the frozen source compiler perform demonstrably redundant work. No runtime source was changed. These findings do not establish an incorrect scientific result in the retained study.

### R1: known reported usage disappears at the adapter/workflow boundary

The local adapter first calls `parse_selection`, which validates the selection and returns finite, nonnegative, integer token counts. It then raises plain `ContractError` solely because those counts exceed the quote. The workflow catches that generic error, substitutes the quote, marks it unmeasured, and tests `over_quote` against this substituted value. Consequently it never sees the original violation. The local archive verifier accepts a failed attempt with quoted accounting without reconciling a retained, parseable response's usage. [Adapter](D:/Projects/drug_target_agents/src/asof/local_model.py:194), [workflow fallback and stop decision](D:/Projects/drug_target_agents/src/asof/workflow.py:200), [failed archive verification](D:/Projects/drug_target_agents/src/asof/local_model.py:109).

The fictional opener returns correct schema, IDs and `truncated=false`, with 1,000,000 input tokens and one output token each time. Under a 100,000-input-token workflow budget the engine performs eight fake calls, retains responses reporting 8,000,000 input tokens, accounts 36,365 estimated input tokens, records zero measured input tokens and zero `backend_usage_contract_violated` events, and ends `partial`. `verify_backend_execution` accepts the retained archive. There are zero network/model/provider calls. This is an internal accounting counterexample; the reports are adapter-reported usage, not independently authenticated token measurement. [Reproduction](<D:/Projects/drug_target_agents/research_notes/TETHER efficiency and comparative value/runtime/probe_accounting_and_compiler.py:29>), [retained responses](D:/Projects/drug_target_agents/data/cache/comparative-audit-20261102/runtime-mechanics-v1/accounting/backend-execution.json), [trace](D:/Projects/drug_target_agents/data/cache/comparative-audit-20261102/runtime-mechanics-v1/accounting/trace.json).

This is distinct from malformed or unavailable usage, where falling back to an explicitly estimated reservation is appropriate. Existing tests reject malformed content/counts and over-budget selections but do not require validated over-budget usage to survive into workflow accounting. Strong schema-2 `run` explicitly rejects local-model/replay/scorer options, so this issue must not be presented as a defect in its default offline token accounting. [Existing adapter tests](D:/Projects/drug_target_agents/tests/test_local_model.py:130), [malformed usage tests](D:/Projects/drug_target_agents/tests/test_backend_hardening.py:41), [schema-2 restriction](D:/Projects/drug_target_agents/packages/tether/src/tether/_presentation.py:254).

Recommended versioned fix: retain already validated usage before rejecting a response and propagate it through the existing `BackendFailure(usage)` route or an equivalently explicit failed-call result; record the reservation violation and stop before any further dispatch. Update the archive checker to reconcile any validated retained usage. Preserve unknown/malformed usage as estimated rather than inventing measurement. Acceptance: the current witness produces one call, accounts 1,000,000 reported input tokens, records the violation, selects no claim and performs no further calls; malformed usage still yields explicit unknown/estimated accounting. Frozen 0.3.11 artifacts must retain their historical interpretation. [Existing measured-failure branch](D:/Projects/drug_target_agents/src/asof/workflow.py:190).

### R2: all-node policy admission does not check all receipt time relationships

The added raw node has its own exact declared bytes, matching receipt hash/identity, matching policy grant, and `availability.basis=public_download_receipt`. Its asserted `known_public_by` is 2022-01-01, its actual pinned receipt says `completed_at_utc=2024-01-01`, and the case origin is 2023-01-01. The contradictory node is in the granted/supplied inventory but is not a packet ancestor. Preparation and verification return `artifact_policy_consistency_verified` with four checked inputs. The installed 0.5.0 wheel also completes an ordinary fictional offline run and accepts externally anchored outer verification. Adding the very same node as a mapping ancestor causes rejection with `Contemporary availability bound does not match public-download receipt`, including a fresh installed negative attempt before engine dispatch. [Probe implementation](<D:/Projects/drug_target_agents/research_notes/TETHER efficiency and comparative value/runtime/probe_runtime.py:31>), [positive/negative outputs](<D:/Projects/drug_target_agents/research_notes/TETHER efficiency and comparative value/runtime/evidence-v1/installed-witness.json>), [retained negative failure](D:/Projects/drug_target_agents/data/cache/comparative-audit-20261102/runtime-probe-v1/referenced-future-receipt/outer-negative-v1/tether-failure.json).

The root cause is precise: policy authorization checks the asserted availability object's cutoff, while `_check_receipt` checks transport identity, size and hash. The receipt/`known_public_by`/`evidence_ref` relationship exists in the engine's `InputGraph.verify`, reached by `load_snapshot` only for eligible artifact/observation ancestry. Extra unused granted nodes therefore get raw hashing and transport checks but miss this temporal relationship. This is not forged-but-self-consistent metadata; it is a supplied proof contradicting supplied metadata under an explicitly named proof basis. [Policy raw cutoff gate](D:/Projects/drug_target_agents/packages/tether/src/tether/_catalog_policy.py:421), [wrapper receipt check](D:/Projects/drug_target_agents/packages/tether/src/tether/_catalog_binding.py:113), [engine relationship check](D:/Projects/drug_target_agents/src/asof/provenance.py:127), [eligible-only source traversal](D:/Projects/drug_target_agents/src/asof/chrono.py:215).

Severity is P2 because the demonstrated node contributes no claim and would be rejected if it became an ancestor. Nevertheless the documented all-node temporal consistency guarantee and successful `checked_inputs=4` result are too strong for this case. Keep the admission/use status separate from scientific validity. The positive receipt anchor is `70180cc79778d85a4c3eacdc4c75d64884549d1002f858ebc8dd24a92445df53`. [Declared all-node scope](D:/Projects/drug_target_agents/docs/TETHER-CATALOG-POLICY.md:35), [installed positive result](<D:/Projects/drug_target_agents/research_notes/TETHER efficiency and comparative value/runtime/evidence-v1/installed-witness.json>).

Recommended versioned fix: apply the existing temporal proof relationship to every supplied raw inventory node during the wrapper's receipt pass, independently of packet reachability. Require valid receipt completion time, matching evidence reference and URL, and a public-by bound no earlier than the receipt observation when that basis is used. Do not pretend a later receipt proves earlier availability. Acceptance includes unused and used contradictory nodes, mismatched evidence refs, valid earlier receipts, and valid other availability bases; both negative variants must fail before dispatch and at verification. [Current intended relationship](D:/Projects/drug_target_agents/src/asof/provenance.py:127).

## Where can work be removed without weakening integrity?

### Takeaway

The highest-confidence targets are redundant work within one immutable/stable input lifetime: one parsed JSON source reused for multiple selectors, one task fingerprint reused for all fields, and a coherent policy preparation pass. Reusing an old digest based only on file modification time is not an acceptable replacement for verification.

### Cited findings

**R3, current outer preflight.** Instrumentation wraps the real stable hash helper and engine source hash helper; both still perform their real reads and hashes. `prepare_policy_run` hashes the fictional raw original twice through the wrapper plus once through engine admission. The immediate second `verify_policy_run` in `create_outer` adds another wrapper and engine hash: **five whole raw-file passes before dispatch**. For the 20,001-byte fictional original this is 100,005 logical bytes. The observation counts logical hashing, not physical disk transfer. Its 0.302-second timing includes fixture-scale Python, metadata and filesystem work and is not a source-size throughput benchmark. [Instrumented counts](<D:/Projects/drug_target_agents/research_notes/TETHER efficiency and comparative value/runtime/evidence-v1/policy-and-hash-probes.json>), [prepare self-verification](D:/Projects/drug_target_agents/packages/tether/src/tether/_catalog_binding.py:210), [immediate outer repeat](D:/Projects/drug_target_agents/packages/tether/src/tether/_presentation.py:263), [explicit source hash followed by engine admission](D:/Projects/drug_target_agents/packages/tether/src/tether/_catalog_binding.py:281).

This extends the previous F11 insight with a new 0.5.0 call-path measurement; it is not a new estimate for the old paper's 49-frame-equivalent hashing. The source-boundary checks after child execution and at later independent verification address different mutation windows. Simply deleting these later checks or all repeated preflight calls would weaken the guarantee. A new preparation capability could carry immutable decoded controls, a complete inventory and receipt/time validation, stable source handles, and proof tokens bound to bytes across an explicitly scoped lifetime. The legacy child currently reopens original paths, so reuse crossing that boundary requires an explicit protocol/version design. [Current control lifecycle](D:/Projects/drug_target_agents/packages/tether/src/tether/_presentation.py:249), [stable-file primitive and limitations](D:/Projects/drug_target_agents/src/asof/study/stable_read.py:122), [prior F11](<D:/Projects/drug_target_agents/planning/TETHER Full Project Critical Review 2026-11-02.md>).

### Inferences and ordered refactor strategy

1. Correct the two reproduced consistency defects in separately versioned paths, with rejection/accounting tests and preserved old artifacts. Do not edit the frozen engine silently.
2. Hoist the immutable validated task hash and encoded scope out of per-field loops. This is the smallest, dependency-free optimization; preserve every fact ID and reference byte exactly.
3. Group source selections by canonical source identity. Under the existing stable-file scope, parse each selected JSON original once, apply all pointers, and discard that source's parse tree before proceeding. Bound the number/size of live parse trees; do not retain an unbounded global document cache. For Parquet, union the required columns and serve locators in a single pass per row group while preserving requested output order.
4. Separate graph/role/time/receipt validation from the physical hashing provider so one bounded stable-handle pass can supply the complete checked proof. Keep source-inclusive verification fresh for a new operation and preserve all evaluator/ancestor checks.
5. Only then consolidate 0.5.0 policy preparation and its repeated decoding/copying. Shared metadata proofs are reread per inventory entry, and policy validation returns deep copies, so a scoped validated-policy object can reduce secondary work after raw-read duplication is addressed. [Repeated provenance loop](D:/Projects/drug_target_agents/packages/tether/src/tether/_catalog_binding.py:124), [policy copy](D:/Projects/drug_target_agents/packages/tether/src/tether/_catalog_policy.py:352).

Benchmark acceptance should compare old/new outputs byte-for-byte on the same fictional cases, test mutations and same-size replacements between every permitted boundary, retain all negative admission outcomes, and report logical source bytes, read/parse counts, wall time and process peak memory separately. For compiler cases above, target one JSON parse per source and one task hash per compilation. For current outer preparation, state an explicit proposed stability protocol before setting a lower raw-pass target. Use repeated runs with medians/ranges and separately controlled cache conditions if making throughput claims. Keep the default runtime dependency-free; use pinned optional PyArrow 21.0.0 only for Parquet. [Dependency declarations](D:/Projects/drug_target_agents/packages/tether/pyproject.toml:6), [core dependencies](D:/Projects/drug_target_agents/pyproject.toml:6).
