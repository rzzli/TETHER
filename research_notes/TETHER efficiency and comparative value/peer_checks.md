# Independent peer checks of TETHER audit counterexamples

## Which alleged defects survive independent checking?

### Takeaway

Three bounded defects survive: destructive receipt/report aliasing in a supporting utility, lost adapter-reported usage on a local-model failure path, and incomplete receipt/availability consistency checking for an unused granted raw node. None demonstrates an accepted contaminated scientific claim. These are separate mechanisms with different scopes; the local-model finding does not bypass the current strong artifact-policy execution mode. [Independent controls](</D:/Projects/drug_target_agents/data/cache/comparative-audit-20261102/peer-controls-v1/results.json>), [strong-mode restriction](</D:/Projects/drug_target_agents/packages/tether/src/tether/_presentation.py:255>).

### Inferences

- Fix priorities should reflect the affected boundary: protect input files from report publication; carry already-validated response usage through local adapter failures and stop further dispatch on a reservation breach; reconcile receipt-derived availability for every granted raw inventory node when reporting whole-inventory consistency. These are correction directions, not patches made during this audit. [Publication boundary](</D:/Projects/drug_target_agents/tools/data/Test-DownloadBatch.ps1:69>), [overquote failure](</D:/Projects/drug_target_agents/src/asof/local_model.py:194>), [outer receipt reconciliation](</D:/Projects/drug_target_agents/packages/tether/src/tether/_catalog_binding.py:113>).
- The receipt contradiction should be described as declared availability inconsistent with retained evidence. Hash binding does not authenticate publisher truth or amount to a cryptographic signature. Changing both declarations cannot establish real-world availability, but the checker can still reject their contradiction with the receipt it actually possesses. [Exact metadata matching](</D:/Projects/drug_target_agents/packages/tether/src/tether/_catalog_policy.py:420>), [receipt reconciliation](</D:/Projects/drug_target_agents/packages/tether/src/tether/_catalog_policy.py:483>).

### Gaps

These probes establish behavior under deliberately constructed conditions, not defect prevalence or historical harm. The policy probe stops at preparation/reverification with `check_engine=False`; it does not produce an outer success receipt or execute a candidate. The local transport reports synthetic token counts without a model or network connection, and no actual expenditure is inferred. No protected clinical outcomes, human responses, answer-aware derivatives, original study inputs or candidate outputs were read for these peer checks. ## What exact mechanisms and controls support the narrowed findings?

### Takeaway

The paired controls explain the failures better than their headline outcomes: receipt destruction changes the next verification result; valid local usage is retained while overquote usage is discarded; the contradictory raw node is rejected when it enters used ancestry. The affected checks are real, but their coverage differs. [Independent paired results](</D:/Projects/drug_target_agents/data/cache/comparative-audit-20261102/peer-controls-v1/results.json>).

### Cited Findings

- **Receipt/report alias:** the utility reads each receipt at lines 24–26, computes success at lines 63–67, then uses unrestricted `Set-Content` at line 71. No destination/input disjointness check precedes that write. The independent second invocation demonstrates the original receipt contract has actually been destroyed; raw source bytes stay unchanged. [Utility](</D:/Projects/drug_target_agents/tools/data/Test-DownloadBatch.ps1:24>), [recheck report](</D:/Projects/drug_target_agents/data/cache/comparative-audit-20261102/peer-controls-v1/receipt-alias/recheck-report.json>).
- **Usage loss:** `parse_selection` constructs and validates `Usage` before returning. `select` saves the response but raises bare `ContractError` when usage exceeds the reservation, before storing `measured_usage` or returning a `Selection`. The workflow's `BackendFailure` branch can preserve supplied usage; its general-exception branch instead uses the quote and marks it unmeasured. Since `actual` has become the quote, the later overquote check is false. The inner attempt stops, but the outer category loop proceeds. [Parser](</D:/Projects/drug_target_agents/src/asof/local_model.py:70>), [adapter failure](</D:/Projects/drug_target_agents/src/asof/local_model.py:191>), [workflow accounting](</D:/Projects/drug_target_agents/src/asof/workflow.py:192>).
- **Archive acceptance:** completed attempts receive response/hash/selection/usage comparisons; failed attempts only need an accepted failure status and quote-accounting basis in this branch. Consequently the saved overquote responses are not reconciled to charged usage. This does not mean the archive lost all response evidence: raw adapter-reported counts remain present in each saved response. The defect is the failed-attempt accounting/verification interpretation. [Verifier](</D:/Projects/drug_target_agents/src/asof/local_model.py:101>), [retained fake execution](</D:/Projects/drug_target_agents/data/cache/comparative-audit-20261102/peer-controls-v1/accounting-1000000/execution.json>).
- **Unused receipt contradiction:** all supplied raw nodes must match an explicit grant and declared policy availability, and declared availability must pass the origin check. Outer receipt reconciliation validates its identity, byte count, hash and timestamp syntax, without comparing that timestamp to the declared bound. Full provenance verification makes the comparison only on the closure of used references. This explains both acceptance when unused and rejection when attached to the used mapping. [Grant and availability](</D:/Projects/drug_target_agents/packages/tether/src/tether/_catalog_policy.py:412>), [receipt timestamp syntax](</D:/Projects/drug_target_agents/packages/tether/src/tether/_catalog_policy.py:488>), [reference closure](</D:/Projects/drug_target_agents/src/asof/provenance.py:105>), [admission verification calls](</D:/Projects/drug_target_agents/src/asof/chrono.py:217>).
- **Strong-mode boundary:** the current artifact-policy launcher excludes `--local-model`, `--replay` and `--scorer`, then later checks that the engine used `offline-extractive-v1`. The accounting finding applies to the compatibility/local-model path available in the installed dependency, not that stronger policy execution contract. [Launcher restriction](</D:/Projects/drug_target_agents/packages/tether/src/tether/_presentation.py:255>), [engine binding](</D:/Projects/drug_target_agents/packages/tether/src/tether/_catalog_binding.py:313>).

### Inferences

The useful distinction is between an omitted internal consistency comparison and unverifiable external truth. A malicious authority could consistently invent both metadata and receipt content; these controls do not establish defenses against that. Here the two retained records disagree under the system's own `public_download_receipt` rule, so the inconsistency is locally detectable. The ancestor negative control also shows an existing line of defense working rather than a general temporal-admission collapse. [Explicit rule](</D:/Projects/drug_target_agents/src/asof/provenance.py:128>), [paired policy outcomes](</D:/Projects/drug_target_agents/data/cache/comparative-audit-20261102/peer-controls-v1/results.json>).

### Gaps

No direct consumed-source temporal bypass was found in these checks. No claim about all failure modes follows from the overquote witness: invalid response schemas can fail before usage validation, and no actual usage can safely be inferred in those cases without a separate policy. Future corrections need distinguish validated reported usage from genuinely unavailable or invalid usage. [Parsing order](</D:/Projects/drug_target_agents/src/asof/local_model.py:53>), [current fallback](</D:/Projects/drug_target_agents/src/asof/workflow.py:192>).

## What can safely be claimed about efficiency and threshold discrimination?

### Takeaway

The strongest immediately identifiable redundant computation is repeated fingerprinting of a frozen task within one compiler invocation. Repeated filesystem verification needs a more careful lifetime argument. Threshold criticism must preserve the difference between omitted facts, wrong assertions, per-group granularity and averaging across groups. [Frozen task](</D:/Projects/drug_target_agents/src/asof/study/source_fact_sources.py:217>), [task hashes](</D:/Projects/drug_target_agents/src/asof/study/source_fact_sources.py:486>), [group-average scoring](</D:/Projects/drug_target_agents/src/asof/study/source_fact_evaluation.py:164>).

### Cited Findings

- The retained compiler probe instruments real reads and fingerprints while keeping production logic intact. For 32 records/128 fields, a 1,052,280-byte fictional JSON file is read 32 times, totaling 33,672,960 logical bytes; the same task is fingerprinted 131 times. Instrumentation itself additionally canonicalizes task values to count logical work, so its elapsed values are not clean performance estimates. The constants are measurement of that fixture, not disk I/O or a production speedup. [Probe](</D:/Projects/drug_target_agents/research_notes/TETHER efficiency and comparative value/runtime/probe_accounting_and_compiler.py>), [result](</D:/Projects/drug_target_agents/data/cache/comparative-audit-20261102/runtime-mechanics-v1/results.json>).
- `_selected_json` reads and parses the whole document for each record pointer. Those calls occur within a shared `stable_files` scope; on Windows that scope holds file read/share-read handles and no-delete directory handles. A within-invocation cache therefore has a substantially stronger source-stability rationale than reusing hashes across later processes. It still needs a bounded-memory design and equivalent deadline/validation behavior. [Whole JSON parse](</D:/Projects/drug_target_agents/src/asof/study/source_fact_sources.py:234>), [per-record invocation](</D:/Projects/drug_target_agents/src/asof/study/source_fact_sources.py:423>), [lock scope](</D:/Projects/drug_target_agents/src/asof/study/stable_read.py:113>).
- The outer hash witness does not run a child, and explicitly adds the second verification that the outer launcher would execute. Preparation includes original-source checks and copied-control verification, which itself calls `load_snapshot`; the launcher repeats that verification before dispatch. This accurately identifies repeated work but does not test optimized equivalence or races between checks. [Probe](</D:/Projects/drug_target_agents/research_notes/TETHER efficiency and comparative value/runtime/probe_runtime.py>), [prepare verification](</D:/Projects/drug_target_agents/packages/tether/src/tether/_catalog_binding.py:208>), [load snapshot](</D:/Projects/drug_target_agents/packages/tether/src/tether/_catalog_binding.py:303>), [outer repetition](</D:/Projects/drug_target_agents/packages/tether/src/tether/_presentation.py:263>).
- For one group, 80% requires every answerable field when group size is 2, 3 or 4: the greatest incomplete fractions are 1/2, 2/3 and 3/4. The 60% threshold separates 3/4 and 2/3 from complete coverage. For two four-field groups, scores 3/4 and 4/4 average 7/8, which passes 80% but not 100%. This arithmetic follows the exact-fraction implementation and limits the native equivalence claim. [Threshold implementation](</D:/Projects/drug_target_agents/src/asof/study/source_fact_evaluation.py:164>), [one-group operational probe](</D:/Projects/drug_target_agents/data/cache/comparative-audit-20261102/pipeline-attempt-03/result.json>).

### Inferences

For a future version, compute the frozen task fingerprint once, investigate one parse per shared JSON path inside the existing locked interval, then measure separately. Only after defining a source-stability lifetime should redundant outer verification be consolidated. Keep independent post-run verification and historical/frozen artifacts unless an explicit replacement proof justifies changing them. This orders engineering work by strength of the existing evidence, without claiming measured gains. [Repeated immutable computation](</D:/Projects/drug_target_agents/src/asof/study/source_fact_sources.py:486>), [existing stability lifetime](</D:/Projects/drug_target_agents/src/asof/study/source_fact_sources.py:403>), [post-engine check](</D:/Projects/drug_target_agents/packages/tether/src/tether/_presentation.py:278>).

### Gaps

No optimized code, correctness comparison, cold-cache benchmark, physical-I/O trace, concurrent mutation experiment or model/candidate rerun was produced. The source compiler measurements and original five-hash observation were independently inspected rather than rerun here; the three defect families above received fresh tiny controls. This peer round is a focused counterexample audit, not a complete code review, literature review or new scientific experiment. [Peer control scope](</D:/Projects/drug_target_agents/data/cache/comparative-audit-20261102/peer-controls-v1/START.json>), [runtime instrumentation scope](</D:/Projects/drug_target_agents/research_notes/TETHER efficiency and comparative value/runtime/probe_accounting_and_compiler.py>).
