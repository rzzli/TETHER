# TETHER comparative systems and discriminating evidence

## 1. What do the closest systems actually contribute and evaluate?

### Takeaway

TETHER's demonstrated endpoint is exact, policy-controlled reporting from a selected source frame. Its closest competitors already offer tool orchestration, evidence-linked statements, corruption experiments, or reproducible execution; other comparators test substantially harder scientific decisions. The defensible position is a bounded implementation of an explicit eligibility and replay contract, whose incremental practical value still needs measurement. This conclusion refers to baseline commit `b8d107059c781bb96ab27807f857f1127ed09608`, verified on 2 November 2026, and the dated working paper, not a new experiment. [Dated manuscript](<D:/Projects/drug_target_agents/paper/revisions/20261102/manuscript.md>)

### Inferences

- **The strongest direct conceptual competitor is Alvessa, while the strongest implementation comparator is the pinned Virtual Biotech.** Their comparison roles differ: Alvessa constrains the claim of novel evidence checking; Virtual Biotech constrains the claim of novel execution auditing. R2E constrains claims about time-aware evidence-driven target prediction. BiomniBench/TxBench constrain evaluation design. This is an interpretation of the source cards, not a performance ranking.
- **A single leaderboard would be misleading.** TETHER's 12/12 exact reports, Alvessa's multiple-choice accuracy, R2E's AUROC, and process/decision scores measure different units and contracts. An informative table compares endpoints, required operations, evidence exposure and guarantee scope.
- **TETHER may complement these agents rather than replace them.** A useful architecture is a generator-independent evidence admission and output-checking layer. That positioning becomes empirical only after showing compatibility with independent producers and measuring benefit/cost under the same task.
- **The current scientific result is not a new therapeutic conclusion.** Exact reproduction can preserve upstream error; declared applicability checks cannot establish undeclared study context. The current manuscript acknowledges this correctly. Its strongest value proposition is reducing particular forms of reporting and provenance error.

### Gaps

- No competitor's omission of artifact-level role policy, exact hypothesis scope, transitive time checks, or negative-result retention is inferred from an unreviewed feature. These are comparison questions for a future documented implementation audit.
- Science full texts for Virtual Biotech and Biomni returned 403. Alvessa PMC opens returned a challenge. BiomniBench direct version/full-text opens returned 403, although indexed primary excerpts supplied additional methods. Pinned Virtual Biotech `run_manifest.py` and run-organization skill raw URLs returned cache misses.
- No outcome labels, protected local clinical derivatives, historical human responses, model weights or benchmark datasets were read or acquired. Public paper methods and aggregate results are bibliographic evidence, not a newly admitted benchmark.
- Citation counts were not collected. No forward snowballing or broad search expansion was performed. Search was restricted to resolving named seeds, their primary records/repositories, and directly relevant workflow mechanisms.

## 2. Which parts of TETHER are distinguishable, and which are established engineering?

### Takeaway

The potentially useful specialization is an executable policy for the **declared evidence graph and intended use**, joined to typed facts and replay. Provenance graphs, immutable artifacts, hashes, recorded execution and cached recomputation are established ideas; assembling them is a contribution only to the extent that it solves a concrete unmet problem at an acceptable cost.

### Cited Findings

- W3C PROV-DM already models entities, activities, agents, derivation, quotation, revision and primary-source relations. It deliberately does not decide every real-world derivation relation: recording provenance is not automatically discovering all provenance. [PROV-DM, Recommendation 30 April 2013](https://www.w3.org/TR/prov-dm/)
- Nextflow's current official documentation describes task caching keyed by code, environment, inputs and other execution attributes, with resume requiring retained outputs. Default file keys use metadata; `deep` includes file content, while `lenient` uses less metadata. These are different trust/performance choices, not interchangeable guarantees. This is a current documentation observation, not a historical benchmark against TETHER. [Cache and resume](https://docs.seqera.io/nextflow/cache-and-resume); [cache modes](https://docs.seqera.io/nextflow/reference/process/directives/cache)
- TETHER 0.5.0's explicit schema-2 path binds artifact/use/release/time/parents and checks its compatibility projection against actual engine inputs. Direct legacy aliases do not enforce schema 2. Its policy path currently supports offline extractive execution, not model/replay/scorer control. Raw files remain external, and some import commitments are inherited from retained receipts rather than freshly hashing every raw file. [Artifact policy authority](<D:/Projects/drug_target_agents/docs/TETHER-CATALOG-POLICY.md>)
- The frozen study uses a contemporary cutoff, lacks qualified study/variant identity, and does not establish historically uncontaminated forecasting. It reports a limited fault inventory and later verifier scope corrections. [Manuscript §§2, 3, 5–6](<D:/Projects/drug_target_agents/paper/revisions/20261102/manuscript.md>); [supplement S10–S11](<D:/Projects/drug_target_agents/paper/revisions/20261102/supplement.md>)

**Formalize the contract before expanding the agent architecture.** A compact set of invariants would be more valuable than additional status prose: every emitted fact refers to an admitted artifact; admitted artifacts satisfy use/time/role requirements over all declared parents; the hypothesis scope matches; missingness has the correct type; all attempts terminate in recorded dispositions; replay rederives the named properties. Every invariant should have a named checker, interface/version and counterexample. This is a proposed specification, not a claim that current code proves all invariants.

**Separate content identity from scientific admissibility.** Identical bytes may be eligible for one use and forbidden for another. Conversely, a newly computed result from admissible old inputs may be permitted. Caching byte checks cannot cache an arbitrary policy decision without including its policy version, use, scope, cutoff and relevant ancestry. This is an engineering inference from TETHER's declared policy and standard cache invalidation concerns.

**Separate the harness claim from the wrapper history.** The frozen P06 study, source auditor, P09 portable replay, and 0.5.0 CLI each support different claims. A concise four-row scope table would reduce the temptation to sum their check counts or borrow newer guarantees for older results. The dated manuscript already makes the chronology explicit; preserve it.

**A narrower implementation can be valuable without being algorithmically novel.** A paper can offer an executable contract, reusable fixtures, an interpretable failure taxonomy, and a reproducible analysis of the cost of assurance. It should not imply that the recombination establishes a new biomedical reasoning method. If no incremental benefit over a small extractor-plus-validator remains after matching guarantees, a technical software release may be the most honest outcome.

### Gaps

- This pass did not establish novelty against all workflow engines, provenance standards or policy systems. PROV and Nextflow are deliberately narrow primary-source comparators that prevent overclaiming generic mechanisms.
- The present sources do not establish whether TETHER's entire contract can be expressed more simply in an existing workflow engine. That is an implementation design question, not a literature conclusion.
- No benchmark establishes the overhead required for an equally strong simpler implementation. The strictness of a policy should not be confused with the efficiency of its implementation.

## 3. Which feasible results and analyses would most strengthen the argument?

### Takeaway

The highest-value immediate work is to extract an interpretable cost/coverage/guarantee story from retained records. A future study should test genuinely distinct admission obligations on the same task with a simple matched baseline; increasing model size or adding more literal-copy cases alone would not resolve the central contribution question.

### Cited Findings

- The revised manuscript reports 203.828 seconds production, including 197.812 seconds source verification (97.0485%), and 140,452,303,784 completed logical hash bytes over a 2,866,248,239-byte source frame (49.0021 frame equivalents). Source preparation and independent audit are separate phases. These are retained measurements, not newly timed trials. [Manuscript §4.3](<D:/Projects/drug_target_agents/paper/revisions/20261102/manuscript.md>)
- The study has 11 identity and four measurement fields per unit; 40/48 measurement slots are populated. The four components are not four independent biological observations. With groups of two to four answerable components, the 80% and 100% completion thresholds coincide. All constructed scenarios were exposed before execution. [Manuscript §§3–4](<D:/Projects/drug_target_agents/paper/revisions/20261102/manuscript.md>)
- Five local-model dispatches produced no strict-contract success and no audit-stage call; the experiment did not establish that exact output fit its token cap. This cannot measure critic effectiveness or general model incapability. [Manuscript §4.4 and supplement S6](<D:/Projects/drug_target_agents/paper/revisions/20261102/manuscript.md>)

For the existing analysis, report repeated-check multiplicity by **unique artifact identity and validation epoch**, not merely calls. A high call count can reflect intentional boundary checks, redundant scans, or both. The useful question is which repeated reads are necessary under the stated mutation assumptions. Do not remove a source-boundary check solely because the previous hash matched.

For the control table, distinguish **policy omission** from **implementation failure**. A deliberately weakened policy admits cases outside its restricted definition by construction. The scientific contribution is clearer when the paper specifies a common desired contract and shows which obligations each implementation can enforce, together with false rejections and cost. Current outcomes remain descriptive, and no unseen-fault generalization should be estimated from them.

The most discriminating new suite would keep source bytes and literal answer quality fixed while perturbing admission context: wrong intended action or modality; conflicting tissue scope; a later mapping ancestor under an apparently old record; evaluator-derived data under an intermediate artifact; a new computation from wholly eligible older inputs; and contradictory metadata in used versus unused graph nodes. Each invalid case needs a valid nearby case so blanket rejection cannot win. Expected decisions must follow a frozen common specification. Have the suite specified separately from the implementation before freezing candidates; software collaborators are not independent scientific judges. Report per-family outcomes and resource use, not one aggregate score. Any defect already revealed during this audit becomes exposed regression material and must not be presented as an unseen test.

For an eventual external comparison, use two explicitly different designs: (a) a contract-matched comparison using the same admitted inputs and task, or (b) a full-system capability comparison with each system's documented data/tools and separately reported resources. A prompt adaptation running on TETHER's restricted frame is not a reproduction of the full Virtual Biotech. Prefer the first design to isolate the incremental harness value.

**Suggested manuscript emphasis.** In the introduction, explicitly name the evidence-checking overlap and define the remaining narrow question. In §2, state executable obligations and interface scope. In §4, lead with faithful reporting, designed-fault behavior and verification overhead. In §5, explain why this is potentially reusable infrastructure while incremental usefulness remains unmeasured. Preserve §6's negative model, sampling, clinical, provenance-authenticity and release boundaries. The present revision largely supports this framing; enrichment should make the result informative rather than inflate it.

- No new data collection, model call, competitor execution, benchmark acquisition, code edit or experiment is proposed as already authorized by these notes. The listed future experiments require their own bounded protocol; the present work is analysis and design.
