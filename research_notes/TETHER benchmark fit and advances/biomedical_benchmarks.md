# Biomedical benchmark fit and peer-method advances for TETHER

## 1. Which benchmarks can support a defensible performance claim?

### Takeaway

Use **SciFact first for evidence-supported judgment**, then **one original LAB-Bench family for useful biomedical answering**. Add LABBench2 as a conditional extension, especially SourceQuality, rather than a new prerequisite: its files are gated and both dataset and harness changed in 2026. TETHER currently has qualified source/lineage/accounting controls, not a qualified native solver for these benchmarks. The current authoritative software is TETHER 0.5.1/AsOf 0.3.12; BG02 qualification is in progress and no paired corpus result exists. Earlier research referring to unfixed 0.5.0 defects is historical. [Current scope](<D:/Projects/drug_target_agents/README.md>); [current checklist](<D:/Projects/drug_target_agents/TODO.md>).

### Inferences

- Preserve the current BG03/BG04 order. LABBench2 adds an optional second-generation utility task; accepting its access terms should not delay the ungated route.
- For a harness paper, the central comparison is the **same producer, same questions, same source budget, with and without TETHER**, alongside native accuracy and correct-and-admitted utility. An independent full-policy validator answers a separate engineering question.
- Reject-all, abstention, source-copy and gold-replay controls have different roles. None establishes biomedical answering competence simply by avoiding unsupported assertions.
- SourceQuality is especially informative because it tests whether evidence is scientifically appropriate, which exact source fidelity does not establish. Its exclusion labels are existing benchmark assets; keep them evaluator-only.

### Gaps

- No execution revision/file hashes, actual downloads, full source access, official scorer runs or hardware budgets were qualified here. Some GitHub directory pages and raw fetches were incomplete; successful landing pages are not proof of usable data.
- Current leaderboard service availability, GenomeArena dataset license and TargetBench offline reproducibility remain unresolved. No account terms were accepted or external user material submitted.
- Original benchmark scores would primarily evaluate the attached solver. Broad therapeutic superiority remains unsupported by these component tasks.

## 2. Which biomedical peer methods add something TETHER does not yet demonstrate?

### Takeaway

The largest additions are **semantic support checking**, **controlled tests of evidence use**, and **scientific process evaluation**. TETHER already implements source isolation, bounded retrieval, lineage, deterministic re-verification and failure accounting. Those should be strengthened through discriminating tasks, not described as absent. [Current implementation limits](<D:/Projects/drug_target_agents/docs/TETHER-VERIFICATION-SCOPE.md>); [bounded retrieval](<D:/Projects/drug_target_agents/src/asof/retrieval.py>).

### Inferences

- The meaningful methodological contribution is measured incremental assurance **at comparable useful-answer coverage**, rather than a larger specialist count.
- Methods should transfer as falsifiable interventions. Use an unchanged candidate bank to isolate checking; use matched fresh runs to assess retrieval/generation; report these as different estimands.
- Dependence grouping, failure denominators and provenance already exist. New experimental value comes from external task difficulty, fixed comparison conditions and appropriate question/study clustering.

### Gaps

- Classification is anchored to current local contracts and targeted code inspection, supplemented by the parallel code reviewer; it is not a claim to have exhaustively searched every historical script.
- General analytical competence, calibrated entailment and scientifically valid target ranking have not been established by current implementation tests. Peer results cannot supply a TETHER effect size.

## 3. What changed since the earlier survey, and how should evaluation be strengthened?

### Takeaway

The most consequential newly identified method is the **very recent preprint “Identity or Evidence?”**, which distinguishes dependence on named entities from use of supplied evidence. Adopt the diagnostic design, with its own cautions, rather than reading a blinding gap as proof of memorization. It supplements TETHER's existing isolation controls. [Canonical v1, submitted 27 October 2026](https://arxiv.org/abs/2610.36510v1).

### Cited Findings

- Brilli and Georgila vary identity and evidence separately, with recall/placebo/positive controls. For 96 LitQA2 questions the named-minus-blinded gap rises from 0 with full passages to 0.135 under complete passage redaction; the reported redaction slope is 0.147, p=0.004. This is one-model, one-mask evidence, not a universal benchmark effect. Blinding DbQA can remove the database lookup key; identity changes can remove scientific context. Deletion/placebo clinical controls are explicitly inconclusive about content use. The paper acknowledges incomplete isolation/serving control and clustered calls. Treat it as a **recent preprint**, not established consensus. [Full v1 and limitations](https://arxiv.org/html/2610.36510v1).
- TETHER already has executed source-only input/reference separation, neutral arm-label projections, explicit literature/perturbation removal masks and a toy feature-removal response test. The parallel code review did not locate a qualified native answering experiment crossing target identity, evidence redaction, placebo, recall and positive controls. Therefore the missing piece is the **qualified joint intervention**, not all masking or all evidence safeguards. [Source-only input implementation](<D:/Projects/drug_target_agents/src/asof/study/source_fact_inputs.py>); [neutral projection](<D:/Projects/drug_target_agents/src/asof/study/baselines.py:211>); [development masks](<D:/Projects/drug_target_agents/tools/framework/compare_development.py>); [mask tests](<D:/Projects/drug_target_agents/tests/test_development_comparison.py:171>); [feature-removal fixture](<D:/Projects/drug_target_agents/tests/test_framework.py:379>).
- Documented citation links are: SciFact repository → MultiVerS; LABBench2 paper → original LAB-Bench and BixBench; Identity/Evidence paper → Biomni/LAB-Bench plus partial-input and intervention-interpretation literature. Alvessa/R2E/TETHER similarities above are methodological comparisons, **not assertions that one project cited or derived from another**. [SciFact](https://github.com/allenai/scifact); [LABBench2 references](https://arxiv.org/html/2604.09554v2); [Identity/Evidence references](https://arxiv.org/html/2610.36510v1).

### Inferences

1. Keep the planned sequence: independent equal-policy conformance, native SciFact, then one original LAB-Bench family. Gated LABBench2 remains optional.
2. Before the native answering study, define paired named/blinded and supplied/absent/irrelevant-evidence arms, but retain an identity-required DbQA task as a distinct stratum. Include a source-change positive control proving the selected instrument can respond to evidence.
3. Keep the native published task score separate from intervention scores. Redaction, oracle passages, restricted sources and deterministic replacement graders create declared derivatives, not unchanged official protocols.
4. Measure all scheduled-case native accuracy, correct-and-admitted utility, false acceptance/rejection, abstention, operational/grader failures and full cost. Use paper/capsule/task clusters where cases share sources or calls; do not treat repeated decisions as independent scientific units.
5. Keep a leakage audit of actual retrieval/files/tool use. Instruction-only restrictions and release dates alone do not establish isolation or historical model knowledge.
6. For SourceQuality, compare TETHER admission with scientific appropriateness as separate labels. A source may be eligible and faithfully copied while unsuitable for the research question; that distinction could support a much stronger paper than more source-copy ceiling results.

### Gaps

- This research adds no experimental result, new expert requirement or authorization for a paid/hosted run. Existing public benchmark labels are optional evaluator assets under the project's already accepted rules.
- A stable public supplement/code release for Identity/Evidence was not independently located; the canonical abstract/full text were verified, but its experiment was not reproduced.
- No new clinical-prediction claim is justified. Source chronology, outcomes, censoring and model knowledge remain separate prerequisites even when a benchmark publishes labels.
