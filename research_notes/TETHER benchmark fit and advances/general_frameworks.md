## Which general benchmarks and framework comparisons would add the most useful evidence?

### Takeaway

Use **Inspect as the closest framework comparator**, **ALCE as the strongest general citation-quality extension**, and **CRAG as a conditional selective-answering stress test**. AgentDojo and the tau family become meaningful only when the evaluated system can perform interactive tasks; CheckList and ARES are primarily method donors. These rankings are project-specific judgments, not peer-reported TETHER results. The currently planned SciFact and LAB-Bench work remains a better first biomedical utility route than widening to a broad assistant leaderboard. ([Current stages](<D:/Projects/drug_target_agents/TODO.md:26>); [Inspect](https://inspect.aisi.org.uk/agent-bridge.html); [ALCE](https://aclanthology.org/2023.emnlp-main.398/))

### Cited Findings

| Priority / object | Concrete task, metric and access | Fit and what a result would not establish |
|---|---|---|
| **1. Inspect AI: equal-policy implementation, not a benchmark dataset** | Public framework supports custom solvers/scorers and integration of external agents. Current bridge documentation includes tool approval and execution once per model proposal with matching arguments. Build the same TETHER obligations and input archive in Inspect, then measure admission/observable agreement and retained execution evidence. [Bridge contract](https://inspect.aisi.org.uk/agent-bridge.html) | Most relevant architectural comparator. A successful replay shows implementability and conformance, not answering ability. Adding the missing domain policy is part of the comparator's implementation cost; generic Inspect logs alone are not transitive historical lineage proofs. |
| **2. ALCE: cited answer generation** | ASQA, QAMPARI and ELI5; released question/retrieval data and automatic fluency, answer-correctness and citation metrics. Supplied retrieval outputs permit a bounded generation experiment without rebuilding full indices. Full retrieval is separately expensive. [Release](https://raw.githubusercontent.com/princeton-nlp/ALCE/main/README.md); [paper](https://aclanthology.org/2023.emnlp-main.398/) | Isolates the gap between cited bytes and citation support. Use identical supplied passages, solver and generation budget across wrapper arms. Learned entailment scores have judge error; they do not prove biology, causal effect or temporal eligibility. |
| **3. CRAG: abstention and dynamic-fact QA, conditional** | Public factual QA with supplied search results/mock APIs. Native automatic evaluation combines matching and LLM judgment: correct +1, missing 0, incorrect -1. License is CC BY-NC 4.0. Dataset schema includes query times. [Release/evaluation](https://github.com/facebookresearch/CRAG); [schema](https://raw.githubusercontent.com/facebookresearch/CRAG/main/docs/dataset.md) | Tests error versus useful-answer coverage after a capable QA component exists. Query times are not complete source-release/annotation ancestry; adding TETHER historical checks creates a declared derivative evaluation. The native utility score does not by itself calibrate confidence. |
| **4. AgentDojo: security versus benign utility, later** | Original paper describes 97 user tasks and 629 security cases; tool-return prompt injections are evaluated in dynamic environments. Measure benign task success, task success under attack and attacker success separately. Code and example runner are public; executions require a tool-using agent. Counts describe the paper, not an unpinned current checkout. [Paper](https://arxiv.org/abs/2406.13352); [runner instructions](https://raw.githubusercontent.com/ethz-spylab/agentdojo/main/README.md) | Relevant if retrieval/tool text can influence actions or admitted claims. An inert verifier or reject-all system cannot establish useful security by declining every action. Static payload detection or retained-trace checks must be labeled component tests, not AgentDojo agent performance. |
| **5. tau-bench / tau2 successors: repeated interactive reliability, later** | Original tau-bench tests policy-constrained API interactions with simulated users, evaluating goal state and reliability across repeated attempts (`pass^k`: all k succeed). tau2 adds a shared environment where both user and agent act. [tau paper](https://arxiv.org/abs/2406.12045); [tau2 paper](https://arxiv.org/abs/2506.07982) | Useful method donor for end-to-end policy compliance and failure attribution. Customer-service success does not establish biomedical evidence quality. TETHER currently lacks the corresponding interactive solver/environment bridge, so transcript verification is not task execution. |
| **6. CheckList: behavioral test design, immediate method donor** | Public toolkit organizes capabilities against minimum-functionality, invariance and directional tests. Its paper demonstrates finding model failures missed by conventional accuracy evaluation. [Paper](https://aclanthology.org/2020.acl-main.442/); [toolkit](https://raw.githubusercontent.com/marcotcr/checklist/master/README.md) | Strengthens policy-boundary coverage and valid-neighbor testing. It supplies methodology rather than an external TETHER score. Expanded authored cases remain exposed synthetic controls and do not establish natural fault prevalence. |
| **7. ARES: component judges and error correction, conditional method donor** | Separates context relevance, answer faithfulness and answer relevance. Its original method trains judges with synthetic examples and uses a small human-labeled set for prediction-powered inference. Public code exposes gold-label paths. [Paper](https://aclanthology.org/2024.naacl-long.20/); [implementation](https://raw.githubusercontent.com/stanford-futuredata/ARES/main/README.md) | Valuable decomposition, but its uncertainty guarantees cannot be recreated by replacing the labeled calibration sample with agreement among LLMs. Existing public benchmark annotations can support task-specific qualification; no new expert recruitment is proposed. |

Current tau resources require unusually careful version labeling: the old repository warns its tasks are outdated and points to a successor labeled tau3, while current `tau2-bench` main and running documentation describe tau-bench 2.0. Current released `text-v1` has six languages × three domains × 50 tasks = 900 conversations per trial. Documentation treats subsets as custom runs without official scores and specifies simulator/judge API access. Choose a corrected pinned release and exact manifest rather than mixing old paper counts and new main. This is a later, nonzero-compute dependency, not an immediate offline benchmark. ([Old repository warning](https://raw.githubusercontent.com/sierra-research/tau-bench/main/README.md); [current release description](https://raw.githubusercontent.com/sierra-research/tau2-bench/main/README.md); [current execution contract](https://raw.githubusercontent.com/sierra-research/tau2-bench/main/docs/running-the-benchmark.md))

AgentHarm is a different threat model: its original 110 malicious tasks (440 with augmentations) measure completion of directly requested harmful multi-step activity, alongside refusal. This does not substitute for AgentDojo's indirect tool-output injection setting. It is lower priority for TETHER's evidence-governance claim. Broad assistant exams such as GAIA or AgentBench are also lower priority in this project's current state; no native integration or matching utility claim was established in this research. ([AgentHarm primary announcement](https://www.aisi.gov.uk/research/agentharm-a-benchmark-for-measuring-harmfulness-of-llm-agents); [TETHER scope](<D:/Projects/drug_target_agents/docs/TETHER-VERIFICATION-SCOPE.md>))

### Inferences

- The strongest paper comparison is **same policy in TETHER versus independently implemented policy in Inspect**, followed by **same answering component with and without the evidence gate**. A generic framework with no domain checks is a weaker-policy diagnostic, not an architectural peer. This is a proposed causal design; none of these peers has demonstrated an improvement on TETHER. ([Local policy](<D:/Projects/drug_target_agents/planning/review-assets/tether-equal-policy-20261102/POLICY-SPEC.md>))
- Rank benchmark readiness separately from domain relevance: public code is not a qualified installation; labels are not agent inputs; a pretrained model is not automatically a qualified solver; native scoring must be retained alongside any derived policy metric. ([Inspect evaluation guidance](https://github.com/UKGovernmentBEIS/inspect_evals/blob/main/BEST_PRACTICES.md))

### Gaps

- No benchmark archives, weights, live task environments, exact commits, costs or execution compatibility were acquired/qualified here. Public documentation supports candidate access, not successful local execution.
- No inspected general benchmark jointly supplies TETHER's complete temporal, hypothesis, artifact-use and transitive-lineage policy. That is a bounded inspection conclusion, not proof of uniqueness across all frameworks.

## Which peer methods would improve the scientific argument, and how should they be tested?

### Takeaway

The missing evidence is primarily **semantic correctness at useful coverage and bounded cost**, rather than additional provenance machinery. Preserve the current separation between deterministic consistency and scientific validity. A traceable or quoted statement is not automatically supported; a semantic judge is not formal proof. ([Local interpretation contract](<D:/Projects/drug_target_agents/src/asof/study/diagnostic_codec.py:603>); [ALCE evaluator](https://raw.githubusercontent.com/princeton-nlp/ALCE/main/eval.py))

### Cited Findings

- **Citation entailment and counterevidence:** ALCE's evaluator tests whether cited passages entail generated sentences and examines multi-citation support; it uses a learned NLI model, not a theorem prover. SciFact explicitly scores support/contradiction labels and rationale sentence selection, with empty evidence allowed. Therefore quote identity, valid citation IDs, entailment, contradiction and insufficient evidence are distinct measurements. [ALCE code](https://raw.githubusercontent.com/princeton-nlp/ALCE/main/eval.py); [SciFact official schema/scoring](https://raw.githubusercontent.com/allenai/scifact/master/doc/evaluation.md)
- **Selective prediction:** Xin et al. study abstention on low-confidence examples and improve confidence estimation with error regularization. This supports measuring risk as coverage varies; it does not establish calibration of TETHER's current null real-data predictions or an LLM's self-reported confidence. [Primary paper](https://aclanthology.org/2021.acl-long.84/)
- **Scorer failure is not model failure:** Inspect distinguishes a wrong answer, an exception during scoring, and an unscored judge result. Errors and unscored values can be excluded from reported accuracy; default epoch averaging can retain a success while hiding an unscored repeat at the aggregate level. All epoch records remain available. [Current scoring policy](https://inspect.aisi.org.uk/scoring-policy.html)
- **Budgets need explicit boundaries:** Inspect documents sample/scoped token, time, turn and cost limits; token-based cost requires configured price data, and asynchronous time cancellation occurs at yield points. These mechanisms are not the same as TETHER's pre-dispatch reservation and adapter-reported/estimated accounting. Comparison requires specifying each boundary. [Current limits](https://inspect.aisi.org.uk/setting-limits.html); [TETHER workflow](<D:/Projects/drug_target_agents/src/asof/workflow.py:153>)
- **Repetition and dependence:** tau's all-success `pass^k` addresses reliability rather than a best-of-k success. Inspect exposes clustered uncertainty metrics and can retain separate judge scores for agreement analysis. Repeated attempts on one case and multiple claims from one article are not independent scientific cases. [tau paper](https://arxiv.org/abs/2406.12045); [Inspect metrics](https://inspect.aisi.org.uk/metrics.html)
- **Existing semantic labels still matter:** ARES's PPI corrects judge error using labeled observations. The user-retired expert route cannot be replaced by relabeling AI consensus as external truth. Use existing relevant benchmark gold labels where licensed and applicable; report a new domain's unresolved validity separately. [ARES paper](https://aclanthology.org/2024.naacl-long.20/)

### Inferences

These are proposed TETHER experiments, not gains demonstrated by the cited peers:

| Proposed method | Concrete implementation/evaluation | Falsification or acceptance condition |
|---|---|---|
| **Evidence-quality decomposition** | For each answer retain source existence/hash, authorized use, temporal/hypothesis eligibility, citation span, semantic label, reference label, grader identity and grader failure separately. Report wrong-but-admitted and correct-but-rejected counts. | No semantic-benefit claim from exact quote/hash success alone. Native benchmark correctness remains separate from TETHER policy success. |
| **Counterevidence retrieval** | Retrieve support and contradiction candidates, preserve evidence polarity/context, score with SciFact labels/rationales. Compare full evidence, no evidence and irrelevant-evidence controls on a frozen split. | A gate that merely agrees with its generator, ignores contradictory evidence or succeeds only with privileged gold passages fails the intended independent-support claim. Gold-passage runs are a distinct ablation. |
| **Risk–coverage curves** | For a qualified answer-confidence score, freeze thresholds on development data. On untouched evaluation data report coverage = answered/scheduled, semantic risk = incorrect/answered, correct-and-admitted/scheduled, plus abstention and operational/scorer failures. Plot semantic risk at matched coverage and area under the curve; stratify by task/source difficulty. | Reject-all has no useful answer coverage. Do not count a timeout as a well-calibrated abstention. No conformal or probability-calibration claim without the method's assumptions and suitable held-out labels. |
| **Utility–cost frontier** | Hold model, supplied inputs, tool access, token budgets and task schedule fixed; vary only the gate. Report native task score and useful admitted answers against measured total tokens, all participating model costs, wall/CPU time and peak memory. Include import/preparation/verification and retain unsuccessful attempts. | Excluding judge/retriever cost, reporting only successful calls, or comparing unequal policies makes an efficiency conclusion invalid. Dollar estimates need pinned pricing and remain distinct from actual billing. |
| **Trajectory constraints** | Score legal/illegal state transitions, evidence visible before dispatch, argument authority, repeated side effects, reservation/accounting and unresolved attempts independently of the final answer. Use deterministic environment checks where available; label model-derived error attribution as secondary. | A correct final answer with forbidden actions remains a policy failure. Offline trace checking cannot prove that the reported actions were executed or prevented. |
| **Reliability and generalization** | Once a stochastic solver is qualified, execute independently scheduled repeated trials and report all-success reliability with per-case clustering. Use new valid neighbors, combined faults and capability × test-type coverage. | Three deterministic replays of the same archive are reproducibility/timing observations, not three new task trials or held-out policy evidence. |
| **Judge calibration and disagreement** | Qualify an entailment judge on existing relevant labeled data; preserve generator and judge versions, raw judgments, uncertainty and failure denominators. Compare at least one independently sourced judge/reference path when feasible. | Agreement among related LLMs does not establish truth. Report bias and transfer limits; do not infer clinical validity from NLP agreement. |

The provenance-related design is a **conceptual combination** of TETHER's existing lineage contract, ALCE/SciFact semantic measurement, CheckList behavioral coverage and Inspect's execution/evaluation separation. No citation genealogy among those works is asserted; no external paper is claimed to have already implemented TETHER's complete contract. ([Local policy](<D:/Projects/drug_target_agents/planning/review-assets/tether-equal-policy-20261102/POLICY-SPEC.md>); [CheckList](https://aclanthology.org/2020.acl-main.442/))

### Gaps

- Formal guarantees for unrestricted natural-language entailment were not established by the inspected sources. Learned NLI should be described as an evaluated semantic instrument, not formal verification.
- No validated confidence function, independent clinical outcomes or applicable study-independence assumptions were established here. Risk–coverage analysis is feasible on a public task once answer outputs exist; clinical calibration remains a different milestone.

### Inferences

1. **Finish the current finite equal-policy gate first.** Retain failures and confirm complete policy-clause coverage; separately report false admission, false rejection, invalid inspection, unsupported and infrastructure errors. This establishes a baseline against which an Inspect implementation can be compared.
2. **Build one shared task/result contract for SciFact and LAB-Bench.** Keep original task keys, raw outputs, parser outcomes, native scores, policy verdicts and costs. Verify the official scorer on small invented records before any native run. Native MCQ answer labels remain evaluator-only even though the option texts must be visible.
3. **Transplant the complete obligations into Inspect.** Compare identical originals, cutoffs, authority and budget constraints; do not compare full TETHER with a bare `Task` and call the difference architectural novelty. Document parity gaps rather than silently excluding hard obligations.
4. **Add semantic and selective-risk panels.** Native accuracy/F1, citation precision/recall where applicable, risk–coverage, correct-and-admitted/scheduled, failures and cost. For task/group uncertainty use justified independent units; repeated outputs and related claims are not extra cases.
5. **Keep the interactive benchmarks conditional.** AgentDojo becomes useful after a live tool-using pipeline exists; the tau family after a user/environment interaction loop exists. Until then, borrow their explicit threat models, state outcomes and repetition metrics without claiming benchmark execution.

These planning recommendations extend the current [BG02–BG05 roadmap](<D:/Projects/drug_target_agents/TODO.md:26>) and preserve its sequential scope. They do not reopen clinical prediction, require new expert responses, authorize paid execution, or turn replay correctness into answering capability.

### Gaps

- Search was targeted to the current workflow, evaluation, diagnostic, facade/experiment paths and roadmap; it was not a new full repository audit or test run.
- Peer source pages and release names can change. Before implementation, capture exact commit, package version, dataset manifest, licenses/terms, native scorer fixtures, model/judge versions and price configuration. Access-date citations alone cannot seal a benchmark.
- Current independently authored benchmark controls are exposed to the developers. They can support finite conformance findings, but a later generalization claim requires genuinely separate constructions or externally authored labeled tasks.
