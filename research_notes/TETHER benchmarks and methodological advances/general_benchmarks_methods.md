# General benchmarks and transferable methods

Research date: 2 November 2026. Scope: primary-source review of general grounding, verification and agent-assurance benchmarks; no benchmark, model, evaluator or download was executed. Repository absence/implementation judgments belong to the separate code-gap review. The current project scope is established in the [previous audit](<D:/Projects/drug_target_agents/reports/TETHER efficiency and comparative value.md>).

## Which external benchmarks would actually measure relevant performance?

### Takeaway

The strongest shortlist is **SciFact, ALCE, CRAG and AgentDojo**, in that order for relevance and adaptation cost. None of the inspected benchmarks jointly tests TETHER's information-availability cutoff, hypothesis scope and transitive lineage contract. A custom conformance suite remains necessary for that specific claim; calling a modified subset an official benchmark result would be misleading. Public evidence/labels can support evaluation without recruiting new human experts, but native benchmark metrics need a genuine task-solving component. Copying gold labels into packets would test transport only.

### Cited findings

| Candidate | What the original measures and what is available | Critical fit and proposed use |
|---|---|---|
| **SciFact (EMNLP 2020 release)** — first public semantic evaluation candidate | Approximately 1.4K expert-written scientific claims with evidence abstracts and rationale annotations. Train/dev labels are public; the documented test set is unlabeled and uses a submission route. Claims/evidence annotations are CC BY 4.0; abstracts are ODC-By 1.0 via S2ORC. [Paper](https://aclanthology.org/2020.emnlp-main.609/), [repository](https://github.com/allenai/scifact), [exact license distinction](https://raw.githubusercontent.com/allenai/scifact/master/LICENSE.md). | **Adapt, then run offline with a qualified semantic component.** This evaluates evidence selection/entailment, not clinical correctness or causal genetics. TETHER alone currently preserves and validates structured information; that is not a SUPPORT/CONTRADICT predictor. Existing public dev labels avoid a new expert gate. Hold gold labels outside the agent-visible manifest. A deterministic replay of supplied candidate predictions is useful for engineering, but is not predictive SciFact performance. |
| **ALCE (EMNLP 2023)** — first general citation-quality candidate | ASQA, QAMPARI and ELI5 questions, retrieved passages, generation baselines and evaluation code are released. Supplied retrieval allows an initial fixed-context evaluation instead of rebuilding a large index. Repository code is MIT; that does not establish identical licenses for all upstream datasets, passages and checkpoints. [Repository](https://github.com/princeton-nlp/ALCE), [data/retrieval instructions](https://raw.githubusercontent.com/princeton-nlp/ALCE/main/README.md). | **Adapt, later than structured conformance.** Report answer quality and citation quality separately. Citation existence or exact quote replay cannot establish that the citation supports a novel generated statement. Use the same generator/passages with versus without TETHER, and retain an unmodified original-ALCE result separately from any TETHER-specific derivative. |
| **CRAG, Comprehensive RAG Benchmark (2024; current public dev_v4 files)** — useful temporal/abstention stress test | 4,409 factual QA pairs overall, with mock search/KG APIs; the public schema supplies query time, static/dynamic categories, question types, retrieved HTML, and validation/public-test indicators. Current documented files have `dev_v4` names; do not assume the entire original private challenge frame is public. Project license is CC BY-NC 4.0. [Paper](https://arxiv.org/abs/2406.04744), [schema and downloads](https://raw.githubusercontent.com/facebookresearch/CRAG/main/docs/dataset.md), [repository/license](https://github.com/facebookresearch/CRAG). | **Adapt conditionally.** It is the best shortlisted source of real query-time and changing-answer variation. However, query time and a page's last-modified field do not establish complete historical availability or ancestry. A temporal-lineage corruption overlay would be a derivative suite, with original QA scores reported separately. Benchmark permissions and original-page rights must be retained separately. |
| **AgentDojo (paper v1 and current repository kept distinct)** — security/utility transfer | Public simulated tool environments, tasks, attacks and defenses; MIT repository. Paper v1 has 97 user tasks and 629 security test cases. Utility and attack outcomes use deterministic checks over environment state. Current counts can differ; pin a commit before execution. [Paper v1](https://arxiv.org/html/2406.13352v1), [repository](https://github.com/ethz-spylab/agentdojo). | **Later full benchmark; methodological transfer now.** TETHER's strong current route is offline and has no matching interactive action environment. A static packet verifier cannot claim AgentDojo performance. First borrow paired benign/adversarial evaluation and deterministic policy checks; full execution requires a deliberately scoped tool-action adapter, qualified model and simulated environment. |

**SciFact scoring detail matters.** Official abstract scoring requires a correct evidence document, label and complete rationale set, and counts only the first three predicted rationale sentences; sentence scoring counts every predicted sentence and requires complete sets. Use the official precision/recall/F1 implementation rather than inventing a permissive “contains a correct quote” score. Its data schema distinguishes source cited-document IDs from annotated evidence, so the former must not be treated as gold evidence automatically. [Scoring guidelines](https://raw.githubusercontent.com/allenai/scifact/master/doc/evaluation.md), [schema](https://raw.githubusercontent.com/allenai/scifact/master/doc/data.md).

**ALCE is not a model-free grader.** The inspected evaluator uses a T5-XXL NLI model for AutoAIS and other task-specific checks. Automatic citation precision/recall is a learned measurement with error, unlike a deterministic source-row identity check. Its paper distinguishes correctness, citation quality and fluency; do not reduce all three to a single safety score. [Evaluator source](https://raw.githubusercontent.com/princeton-nlp/ALCE/main/eval.py), [paper](https://aclanthology.org/2023.emnlp-main.398/).

**CRAG explicitly rewards abstention differently from errors.** Its auto-evaluation uses correct=1, missing=0 and incorrect=-1, with exact matching followed by model assessment. The available evaluator includes provider calls/retries; merely installing the scorer would not preserve this project's $0/offline execution boundary. A pinned local evaluator is possible only after separate qualification; substituting one changes the evaluation procedure and must be disclosed. [Repository metrics](https://github.com/facebookresearch/CRAG), [evaluation source](https://raw.githubusercontent.com/facebookresearch/CRAG/main/local_evaluation.py).

**AgentDojo has no universally comparable leaderboard.** Its official results page says configurations have not all been attacked with the same attacks/defenses. Comparing TETHER to one selected row would confound model, attack and defense. The same-model, same-task, same-attack comparison is essential. [Official results policy](https://agentdojo.spylab.ai/results/).

### Inferences

- **Immediate technical evaluation:** independently specified TETHER conformance cases, including valid near misses and controlled bad ancestry, with a simple policy-equivalent validator. This is a proposed benchmark and must be named as such; it is not external evidence of generalization yet.
- **First imported benchmark:** SciFact dev/cross-validation is the best bounded semantic extension. Project effort estimate, not a measured implementation schedule: roughly several engineering days for a clean adapter/scorer/provenance boundary, plus separate model/evaluator qualification. The available labels eliminate new annotation recruitment, not contamination or domain-transfer concerns.
- **Next generalization checks:** ALCE with fixed supplied passages; CRAG Task 1 with fixed HTML and independently audited query times. Both require useful generation/retrieval behavior beyond current literal reporting. They should not precede the three known correctness fixes.
- **Current model-free option:** ingest public candidates and independently check their source/citation identities, receipt lineage and failure accounting. Such a result measures the verifier, not the original task's answer quality. It must not be presented as “TETHER achieves X on SciFact/ALCE.”
- Public train/dev exposure and old benchmark publication raise contamination risk for contemporary models. Pin the exact split, register development exposure, hold out untouched cases, and keep content-level performance distinct from fresh conformance perturbations. Existing exposed defects are regression examples, not an unseen test frame.
- Apparent temporal information in CRAG can enrich test design, but adding invented publication/annotation ancestry converts the case into explicitly synthetic metadata. Do not claim historical truth for that overlay.

### Gaps

- No inspected off-the-shelf benchmark jointly certifies all of TETHER's temporal, hypothesis and complete-lineage requirements. This is a scoped finding about the inspected sources, not proof that no such benchmark exists anywhere.
- Exact disk/expanded-model sizes, download integrity and successful scorer execution are unverified. No download was performed. Bibliographic versions and mutable repository paths are recorded; execution requires immutable commit/data hashes.
- SciFact leaderboard service availability was not tested. Public development scoring is available as a documented route, but it is not blind leaderboard test performance.
- ALCE's upstream dataset/passages/model-weight permissions require product-level verification; MIT repository metadata is insufficient to infer them.

## Which peer methods are worth transferring, and what would make the comparison credible?

### Takeaway

The most valuable transfers concern **measurement and enforcement**, not additional specialist-agent roles: paired utility/safety testing, behavioral relations, reliability across repeated trials, complete failure denominators, independent semantic scoring and explicit policy events. Whether each is absent or only partly implemented must be resolved against the code-gap review; this note does not equate missing documentation with missing code.

### Cited findings

| Method and primary source | What the peer actually contributes | Proposed TETHER improvement and limitation |
|---|---|---|
| **CheckList: minimum-functionality, invariance and directional tests** | A capability-by-test-type matrix tests behaviors beyond aggregate accuracy, with input perturbations and custom expectations. [ACL paper](https://aclanthology.org/2020.acl-main.442/), [official implementation](https://raw.githubusercontent.com/marcotcr/checklist/master/README.md). | Make a contract matrix for target/action/modality/tissue, publication/annotation/retrieval time, lineage depth and evaluator ancestry. Label-preserving transformations should retain decisions; policy-relevant transformations should change them in a declared direction. Apply only justified relations: action changes are not automatically evidence contradictions. Freeze unseen families before implementation tuning. |
| **AgentDojo: utility and attack success as separate dimensions** | Deterministic state checks avoid relying only on an LLM judge exposed to malicious text. Defenses can suppress legitimate utility; the paper reports this tradeoff. [Paper](https://arxiv.org/html/2406.13352v1). | Report valid-case retention, invalid-case admission and task completion jointly. A reject-everything policy must visibly lose. For evidence packets, use a fresh benign counterpart for each adversarial change. This transfers the experimental method; it does not turn packet mutation tests into AgentDojo results. |
| **τ-bench: repeated-trial consistency** | `pass^k` estimates success in all k trials, unlike `pass@k`, which estimates at least one success. The estimator averages task-wise combinations; the original paper also notes that correct final database state need not establish all trajectory-policy requirements. [Paper v1](https://arxiv.org/html/2406.12045v1). | If stochastic generation is reintroduced, retain every trial and report pass^1/pass^k with per-task aggregation and complete accounting. Repeating a deterministic offline run is reproducibility, not stochastic reliability evidence. Do not infer intermediate compliance merely from final-state equality. |
| **AgentSpec (Wang, Poskitt & Sun, 2025)** | A runtime DSL separates triggers, predicates and enforcement actions; events include before-action, state-change and finish. Policies can stop execution. This is distinct from a separate 2026 embodied-composition work with the same name. [2025 primary paper](https://arxiv.org/html/2503.18666v1). | Make policy transitions explicit and versioned at each action boundary if TETHER grows tool execution. Current temporal admission may already cover part of this need; the incremental improvement would be consistent policy-event semantics and coverage, not merely renaming guards. Prefer deterministic stop/abstain where prescribed; no new human-review gate or model-written policy authority is implied. |
| **Inspect: scorer outcomes and denominator discipline** | Incorrect model output, scorer errors and unscoreable cases have different retained outcomes and denominator effects. Partial scorer outputs survive another scorer's failure. [Scoring policy](https://inspect.aisi.org.uk/scoring-policy.html). | Preserve both conditional scientific score among scoreable cases and operational success over all scheduled cases, with error/unscored counts explicit. A benchmark adapter should not silently drop parser errors or confuse an unreliable judge with a wrong model answer. Do not adopt automatic retries without the project's no-duplicate-dispatch accounting contract. |
| **ALCE and ARES: separated quality dimensions** | ALCE distinguishes answer correctness from citation quality. ARES separates context relevance, answer faithfulness and answer relevance, using labeled calibration with prediction-powered inference for judge correction. [ALCE](https://aclanthology.org/2023.emnlp-main.398/), [ARES](https://aclanthology.org/2024.naacl-long.20/). | Add separate retrieval, source-binding, semantic-support and answer-quality measurements. Existing public benchmark gold may support calibration within that benchmark; self-generated model judgments are not an independent reference. Do not claim ARES-style confidence intervals without its reference-label/statistical assumptions. |
| **SAFER: calibrated abstention under bounded sampling** | The 2026 ICLR method calibrates sampling requirements under a cap, abstains if the target cannot be met, then calibrates filtering. It does not assume every open-ended item has a correct sampled answer. [Proceedings](https://proceedings.iclr.cc/paper_files/paper/2026/hash/582e9771ac8527cb6390e5e9444a0fee-Abstract-Conference.html). | Later: evaluate risk versus retained-answer coverage using a disjoint labeled calibration set and an explicit error definition. Current evidence-coverage thresholds are not statistical uncertainty calibration. The paper's guarantees cannot be transferred to therapeutic correctness, shifted biomedical distributions or unverified labels. No scorer training or probabilities are proposed for the current literal workflow. |

### Inferences

**Recommended paired experiment, not a leaderboard mismatch.** Run two layers, keeping their estimands separate:

1. **Verifier-only replay:** freeze an identical candidate-output stream and exact input bytes. Compare TETHER, a simple independently implemented policy-equivalent validator, a diagnostic hash/schema-only variant and an always-reject sanity baseline. Measure invalid acceptance, valid rejection, diagnostic correctness, proof completeness, CPU/wall time, memory, bytes hashed and recoverability. Oracle decisions must come from a separate written contract and independently constructed fixtures, not the candidate's own serializer or predicates.
2. **End-to-end intervention:** only after a model/tool route is qualified, pair the same base model, task/source snapshot, prompt, attack or corruption, retrieval budget and generation budget under each wrapper. Randomize or counterbalance run order; retain all attempts and their realized costs. A wrapper may legitimately alter future actions, so do not demand identical later trajectories. Separately show original task score, correct-and-admitted outputs, abstentions, unsafe admissions and operational failures.

Use the task/case as the resampling unit; do not treat many fields, citations or repeated draws from one task as independent samples. If task families share papers or source records, report their dependencies and consider clustered intervals. Report counts alongside rates, paired outcome tables and tradeoff curves, not only a composite score. With no statistical study yet, these are design recommendations rather than attained guarantees.

**A concrete three-panel paper extension:** (a) valid and invalid cases by failure family, with full-policy/simple-policy-equivalent/weak-baseline outcomes; (b) semantic quality versus retained coverage on an external labeled task; (c) end-to-end cost versus source size and lineage depth, including cold/warm runs. Improvement means fewer errors at comparable utility/cost, or lower cost at identical assurance. If both full-policy validators are correct and the simpler one is faster, TETHER's architecture claim must narrow.

**Risk controls are not replacements for provenance.** A highly confident entailment score cannot repair a late annotation ancestor; conversely an impeccable receipt and matching hash do not imply semantic truth. Preserve two independent axes rather than combining them into a confidence number.

## What should be deferred or rejected, and how strong is the source evidence?

### Takeaway

Avoid broad agent leaderboards unless their environment and success definition match the component being evaluated. Also avoid importing an apparently deterministic metric while ignoring its hidden policy assumptions, judge model or changing release. A short, qualified benchmark portfolio is stronger than many incomparable scores.

### Cited findings

- **Original τ-bench tasks are now explicitly outdated.** The original official README redirects users to the `tau2-bench` repository. Its current README describes version 2.0 and says its English runs are not input-identical or comparable with 1.x; it includes changed task replacements, prompts and judges. Use the 2024 paper for the reliability concept, not an unpinned current leaderboard claim. [Original warning](https://raw.githubusercontent.com/sierra-research/tau-bench/main/README.md), [current repository README](https://raw.githubusercontent.com/sierra-research/tau2-bench/main/README.md).
- **GAIA requires a different system and access arrangement.** The official card describes tool-augmented tasks and gated file access, with private test answers/metadata and a restriction against crawlable redistribution. It is useful for a future research assistant, not the present offline evidence validator. No access was requested and the benchmark files were not read. [Official dataset card](https://huggingface.co/datasets/gaia-benchmark/GAIA).
- **FEVER is a possible broader-domain robustness supplement, not first priority.** It has Wikipedia-derived support/refute/not-enough-information claims and evidence sentences with public labeled development data. Its data/claims do not establish biomedical validity or complete temporal ancestry. SciFact is the better first semantic bridge for this project. [Official dataset page](https://fever.ai/dataset/fever.html).
- **AgentBench is broad agent capability infrastructure.** Its official repository is Apache-2.0 and supplies environment/task evaluation code. Current TETHER is not a drop-in participant; broad scores would principally reflect a new agent implementation rather than isolate the evidence contract. [Official repository](https://github.com/THUDM/AgentBench).
- **ToolEmu is a useful methodological contrast, not the recommended primary judge here.** AgentDojo's primary paper explicitly contrasts its deterministic checks with ToolEmu's model-simulated/evaluated environment and explains why an injection could also affect a model evaluator. The attempted `osunlp/ToolEmu` URL did not fetch and is not treated as the verified official repository. [Inspected primary comparison](https://arxiv.org/html/2406.13352v1).

### Inferences

- Reject generic MCQ/assistant scores as the sole evidence for TETHER's assurance contribution. They can establish competence of an attached solver, not the usefulness of the harness intervention.
- Do not reward a framework for refusing every task, preserving only easy successful traces, replaying supplied gold answers, or comparing against a baseline missing the very rules under test.
- Use **existing benchmark annotation**, where permitted, without reinstating external expert recruitment. If a proposed novel biomedical endpoint lacks independent labels, say it is unqualified instead of creating circular AI-only truth.
- If bounded offline operation and $0 provider spend remain binding for the next experiment, begin with deterministic conformance and fixed recorded-candidate replay. The shortlisted original end-to-end benchmarks remain proposals until their adapters, compute and reference evaluators are qualified.
