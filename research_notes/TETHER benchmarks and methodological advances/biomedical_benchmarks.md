# Biomedical benchmark choices and method transfers

## 1. Which external biomedical benchmarks fit TETHER?

### Takeaway

No inspected biomedical benchmark is executable as its original scientific task through TETHER's current qualified offline extractor without a new adapter or producer. The most proportionate first choices are LAB-Bench literature/database QA and GenomeArena; RAGPPI is a promising evidence-grounding extension, R2E provides a future ranking endpoint, and BixBench supplies a later computational-analysis endpoint. A source-normalization/replay test derived from their files is an engineering test, not an official benchmark score. This assessment uses the current capability boundaries in the [prior audit](<D:/Projects/drug_target_agents/reports/TETHER efficiency and comparative value.md>).

### Inferences

- **Performance needs two axes.** An unchanged official QA task measures answer capability; an accompanying harness experiment measures whether TETHER rejects forbidden context, binds claims and replays sources. A higher refusal rate can improve conditional accuracy while worsening task success; report both. A derived temporal corruption suite measures the new suite, not an official benchmark's historical eligibility guarantee.
- **A two-producer paired design is more informative than another named agent.** After fixing known TETHER defects, run identical producer outputs through (a) simple policy-equivalent validation and (b) TETHER. Hold evidence, outputs and budget fixed. Then, separately, evaluate full answering systems. This isolates harness effects without making all performance differences the model's fault.
- **Prioritize a small qualified slice, not favorable cases.** Before reading answers, choose by metadata a fixed set of task domains/source availability and publish exclusion reasons. A suggested first feasibility scope is 20–30 cases; that is engineering capacity planning, not a powered statistical sample. Estimate final sample size only after defining an effect and paired disagreement rate. Cases sharing articles/capsules are clusters.
- **No new human gate is needed.** Existing benchmark labels can be used with their documented limitations. An ensemble of LLM judges is not independent scientific adjudication, and public labels already viewed cannot become an unseen test by moving folders.

### Gaps

- No original benchmark was run. No source snapshot, benchmark item count, package environment, grader reproducibility or complete working-storage estimate was locally qualified. Dataset landing-page accessibility is not proof all artifacts can be acquired.
- Current main-branch pages need pinned commits and content receipts before execution. Missing metadata/license is explicitly unknown; no claim of competitor capability absence follows from inaccessible pages.
- BixBench README asks for Hugging Face authentication, while its card is publicly readable. Full anonymous archive access was not tested. No claim that auth is strictly required for every capsule.
- RAGPPI abstract says4,420 while the card/code and500+3,720 sum give4,220. Treat4,220 as the documented release total pending actual row enumeration; do not propagate the abstract arithmetic error. [Publication record](https://aclanthology.org/2026.eacl-long.203/)

## 2. Which peer methods are worth transferring?

### Takeaway

The best transfers strengthen the evaluation design: separate evidence retrieval from evidence checking, test valid answers as well as faults, use source-level perturbations, separate final answer from analytical process, and account for repeated tasks. More agents, more self-critique loops or unconstrained memory do not establish a methodological improvement. The following are candidate gaps to reconcile with the parallel code-gap audit, not assertions of absence based only on keyword search.

### Cited Findings

| Peer mechanism | What it establishes in the peer | Useful TETHER extension / limitation |
|---|---|---|
| **Alvessa: statement-level verification against retrieved records, with revision** | Official README describes a claim-check/revision loop. Prior primary-source review identifies an evidence/no-evidence corrupted-answer comparison separate from MCQ accuracy. [README](https://raw.githubusercontent.com/ksenia007/alvessa_agent/main/README.md); [prior methods audit](<D:/Projects/drug_target_agents/research_notes/TETHER efficiency and comparative value/comparative_systems.md>) | Current constructed technical faults do not establish natural-language entailment. Add source-visible/source-hidden critic arms on a fixed response bank, with true statements and misleading-but-literal statements. Score detection, false rejection and repair regressions. Separate this from identity/hypothesis admission, which is already TETHER's aim. |
| **R2E: masked entity evidence, evidence-level attribution and frequency correction** | Paper's ranker represents candidates through masked evidence; evaluates evidence attribution and gene-macro ranking, and tests frequency correction. [Paper](https://aclanthology.org/2025.acl-long.167.pdf) | A future scorer could test evidence dependence with candidate-name masking, shuffled evidence and evidence deletion. Report performance by study/popularity strata to expose memorization. Start with controlled deletion; full Shapley is costly and not causal biology. No ranking endpoint means no meaningful score attribution yet. |
| **BiomniBench: process and output dimensions** | Card grades full trajectories using task-specific reference rubrics, not only answers; published abstract distinguishes grounding from method selection/interpretation. [Card](https://huggingface.co/datasets/phylobio/BiomniBench-DA); [primary preprint](https://www.biorxiv.org/content/10.64898/2026.05.12.724604v2) | Keep machine-checkable provenance separate from scientific method and interpretation scores. Add process checks only when there is an analytical task. A model judge is a measurement instrument with bias, not a replacement for source checks or a new human truth label. |
| **BixBench: multiple replicas, refusal and agentic/zero-shot contrasts** | Runner documents five-replica voting, refusal-option variants, zero-shot versus tool execution and custom rollout formats. [Runner](https://raw.githubusercontent.com/Future-House/BixBench/main/README.md) | Test tool/retrieval contribution with the same base model when a producer is feasible. Report accuracy/coverage and total cost across retries, rather than selecting the best attempt. Existing TETHER abstention is not absent; the new value would be calibrated risk–coverage analysis on external tasks. |
| **TxBench: task-grounded endpoints, hidden deterministic graders and clustered repeats** | Paper excludes shortcut-solvable tasks, retains malformed/failed attempts as failures, and computes uncertainty over task-level rates. It varies harnesses as well as models. [Paper](https://arxiv.org/html/2606.19245v2) | Audit whether a source task requires analysis rather than copying; preserve failed-attempt denominators and group repeated runs by task. TETHER already retains failures, so the missing extension is a qualified external analytical endpoint and matched harness experiment, not merely another journal field. |
| **RAGPPI: atomic claim decomposition plus evidence comparison** | Public evaluator decomposes answers and uses similarity/low-support features before ensemble decisions. [Code](https://github.com/youngseungjeon/RAGPPI) | An optional semantic layer could localize unsupported mechanistic statements while leaving deterministic admission authoritative. Test negation, direction, intervention versus association and context mismatch. Do not treat cosine similarity as entailment or auto-labeled silver as independent truth. |

### Inferences

- **Most important methodological addition:** a paired, policy-equivalent benchmark. The prior TETHER audit already recommends it; literature strengthens why a weak hash/schema baseline alone is insufficient. Incremental harness utility is not demonstrated by comparing TETHER source copying with a peer's scientific agent score.
- **Second:** evidence dependence and source-context stress tests, including an eligible but irrelevant evidence set, duplicate evidence, contradictory conclusions, wrong tissue/action, and new computation from valid old inputs. Keep real-source semantic tests separate from invented corruption controls.
- **Third:** bounded evidence repair. A verifier may propose one repair, but a fixed response-bank experiment should first show that repairs improve unsupported-claim rate without introducing new errors. Account for every attempt; no live model call or closed experiment restart is authorized by this recommendation.
- **Fourth:** shared-source sampling discipline. Partition by paper/capsule/study or disease/target where the estimand requires it. Score macro performance and retain clusters. A public benchmark's `train` label is often a packaging name, not permission to train on its answers before testing.
- **Do not adopt blindly:** self-evolving memory can carry evaluator information into later runs; majority voting can multiply correlated errors and cost; model judges can reward their own stylistic preferences; more retrieval can increase source leakage. Each candidate needs a fixed-input ablation and a falsification condition.

### Gaps

- This biomedical pass did not inspect every current TETHER execution function. The final report must use the parallel code-gap audit to classify each candidate as implemented, partial, absent or intentionally excluded. Absence of a published result is not proof the software lacks the feature.
- No performance benefit is predicted numerically. Peer gains on another task cannot supply a TETHER effect size or justify a resource budget.

## 3. How should these results be used without overstating evidence?

### Takeaway

Recommend one external biomedical component benchmark and one independently specified conformance suite first, with unchanged producer outputs for the harness comparison. Defer broad analysis and clinical prediction until the corresponding capabilities and data are qualified. The current audit's three pending correctness defects remain prerequisite engineering work, not newly solved by finding benchmarks. [Current open findings](<D:/Projects/drug_target_agents/reports/TETHER efficiency and comparative value.md>)

### Cited Findings

- The user-prioritized seeds have verifiable backward relations: R2E cites attribution and retrieval predecessors; TxBench cites LAB-Bench/BixBench/BiomniBench. Those relations were retained in the prior primary-source audit. RAGPPI was a targeted adjacent discovery from target-identification benchmark searching, **not** asserted to be an ancestor of TETHER or the other seeds. [Prior citation ledger](<D:/Projects/drug_target_agents/research_notes/TETHER efficiency and comparative value/comparative_systems.md>)
- Public task/rubric separation is explicit in BiomniBench-DA; public/private contamination split is explicit in LAB-Bench. Their distinction reinforces that dataset availability does not remove answer-isolation obligations. [BiomniBench-DA card](https://huggingface.co/datasets/phylobio/BiomniBench-DA); [LAB-Bench card](https://huggingface.co/datasets/futurehouse/lab-bench/raw/main/README.md)

### Inferences

Suggested staged route (not execution):

1. Correct pending receipt/accounting/unused-node defects; qualify a new version.
2. Select a benchmark by the desired endpoint: literature QA → LitQA2; database tool answering → GenomeArena/DbQA; claim entailment/mechanism → RAGPPI gold; target ranking → R2E; computational analysis → BixBench.
3. Freeze release, licenses, source/label split, case-selection rule, budgets and adapters. Store evaluator material separately with enforced role policy, not just folder names. Audit that the minimum valid answer fits the output budget before any model use.
4. Run deterministic baselines and an independent equal-policy validator first. Replay a fixed response bank through both validators to isolate framework behavior. Those are component tests, not an official end-to-end answering score.
5. Only after task-capable producers exist, run original benchmark scoring alongside TETHER-specific admission/replay/resource metrics. Keep unmatched source restrictions and derivative subsets explicit; include invalid/malformed/refused attempts in denominators.
6. Interpret success narrowly. QA accuracy does not prove historical eligibility; integrity does not prove entailment; entailment does not prove causality; known-target retrieval does not prove future clinical benefit.

No new user-supplied files are needed to choose and specify this route. BiomniBench file access and some source licenses may need account actions later; do not request them before selecting that branch. Existing public benchmark expert labels do not require reinstating external expert recruitment.

Main-branch revision hashes were not invented. GenomeArena ZIP, all benchmark datasets/capsules and model weights were not downloaded. No API execution, local protected clinical/human files, production code, old research notes, TODO or memory were changed.

Answers are deliberately not reproduced in this note. Before any locked study, exclude or mark those exposed items, and keep a full acquisition/exposure manifest. Existing public accessibility never guarantees a model has not seen the remaining items.

This is a bounded seed-driven feasibility and methods review, not a complete systematic benchmark survey or legal license determination. Counts and repository feature descriptions are source observations; rankings, effort and proposed TETHER changes are analyst judgments.
