## Executive summary

AsOf is two different things sharing one repository:

1. **A small, well-built core framework** (`src/asof`, about 3,950 lines). It provides date-bounded evidence admission, an immutable claim ledger, hash-chained journals and receipt-based re-verification. The code is careful and its contracts are tight. It is the strongest asset in the repository.
2. **A much larger body of study-specific research code** (`tools/`, about 21,000 lines in 97 modules, not packaged). It drives a long sequence of feasibility studies, sealed reviews and pilots. This layer grew by addition, not refactoring. Run, seal and verify machinery is re-implemented in many places, and the code hard-codes evidence-store and drive paths.

The engineering is sound: [exec] core validation passes (see §0). The scientific programme has drifted far from the stated thesis. H1–H4 (clinical discrimination, baselines, popularity and genetics ablations) are untestable with the current data. Since 24 October all effort has gone into qualifying a model-written interpretation of **one previously seen IL6R record**, using a **14B 4-bit local model at a $0 provider budget**. That has produced three successive failed pilots, each wrapped in heavy review and backup work. The main bottleneck is no longer infrastructure. It is the following, each needing an explicit owner decision:

- model capability,
- the lack of independent (human) scientific references,
- the lack of qualified clinical outcome labels.

The highest-value corrections are:

- **(a)** an explicit decision on model and budget,
- **(b)** consolidating the duplicated research infrastructure into a small number of packaged modules,
- **(c)** narrowing or re-scoping the H1–H6 claims to what the data can support,
- **(d)** cutting the per-step governance overhead so experiments can iterate.

[read/exec] The core is about 16% of the Python code. The wheel (`asof-target-agents`) and the installed-wheel validation cover only that 16%. Everything that produced the reported scientific results lives in `tools/`. Those modules are imported by tests through `tools.science.*` (and `tools/` has no top-level `__init__.py`), so they work only from a checkout root.

## 1.2 Strengths worth keeping

- **Temporal admission is enforced at every layer.** `Availability.exclusion`, `InputGraph.exclusion` and `observation_exclusion` are reused for both admission and semantic verification (`src/asof/chrono.py:53`), so the verifier can't drift from the runner. [read]
- **Strict decoding.** `serde.decode` rejects unknown fields, bool-as-int, non-finite numbers, duplicate JSON keys and naive timestamps. All contracts are deeply frozen dataclasses. [read]
- **Re-verification over trust.** `verify_run` re-admits the original sources, rebuilds features and predictions, reconciles budget accounting from the journal, and rejects any mismatch (`src/asof/artifacts.py:183`). Scientific validity is reported separately as `not_established`, which is honest. [read]
- **Budget accounting is conservative.** Unmeasured failed calls are charged at their quoted upper bound, and the semantic checker refuses any dispatch that exceeds the reservation (`src/asof/semantics.py:336`). [read]
- **Clear evaluator/agent separation.** Catalog roles block evaluation-only datasets from agent inputs, and `evaluation.py` is imported only by the `evaluate` command. [read]
- **Honest negative-results culture.** Failed runs are retained, and no result is silently repaired. [read]

## 1.3 Drifts

### D1 — Thesis drift: from "beat Virtual Biotech at predicting clinical success" to "qualify one interpretation of one record"

[read] The project thesis (`planning/Beyond the Virtual Biotech Tooling Gaps and Project Plan.md`, §Project thesis) defines **H1** (AUROC gain over Virtual Biotech on a locked post-cutoff test set) as primary, with H2–H4 as clinical-prediction corollaries, H5 for dossier quality and H6 as a re-analysis. Measured state:

| Hypothesis/task | Status | Blocking cause |
|---|---|---|
| H1/H2/H3 (T1 discrimination) | Untestable | No qualified outcome labels (Science 4: all 36 endpoints unresolved). Prospective registry route stopped at 0/12 joint-ready. B0 coverage 53% against a 90% gate. All probabilities `null`. |
| H4 (genetics ablation) | Deferred | No MR/colocalization features; regional inputs, LD and ancestry unqualified. |
| H5 (dossier quality) | Partially explored on **one exposed case** (IL6R), using AI-built references | No blinded human panel. Interpretation layer failed three times. |
| H6, T2–T5 | Not started | Gated on T1 prerequisites. |

[judg] Each pivot was locally reasonable and well documented, but taken together the project now answers a different, much narrower question than its title claims. README, TODO and memory still frame the work against Tasks 6–8 / H1–H6. The thesis should be re-stated or explicitly re-scoped (see §1.5).

### D2 — "Agent" drift: the core agent is a lexical-prefiltered ID selector

[read] `agents.SpecialistRequest` → `Selection(observation_ids)`. The only model act in the core is choosing **at most 3** observation IDs (`local_model.validate_selection_cap`). It chooses from a set already pre-ranked by **literal token overlap with the case JSON** (`retrieval.bounded_request`, `src/asof/retrieval.py:511`) and capped at 12 records or 12 kB. The dossier then copies source statements verbatim. No reasoning, synthesis or new computation is part of the core contract.

[read] That design explains the observed parity with simple baselines:

- the 18 Oct comparison matched lexical top-3 selections 11/11;
- the 23 Oct harder T6 challenge scored 6/8 for AsOf, 6/8 for adapted Virtual Biotech and 5/8 for lexical.

[judg] When the retrieval prefilter is lexical and the model only picks a subset, parity with the lexical baseline is the expected result, not evidence about agent quality.

The interpretation work (October 25) adds generated prose. It does so as **sidecars in `tools/science`**, not as a core capability, so the packaged framework still cannot produce the H5 artefact the plan describes.

### D3 — Code-placement drift: framework vs. study scripts

- [exec] 84% of the code is unpackaged `tools/`. [read] Those modules hard-code evidence locations. Examples:
  - `tools/science/comparison_workflow.py:25` reads its role policy from `planning/review-assets/science-prerequisites-20261018/item7/...`;
  - `tools/science/registry_content_workflow.py:30,185` and `outcome_extract.py:25` pin `E:/projects_data/...`;
  - `tools/framework/prepare_local_model.py:22` pins a model directory on E:.
- [judg] Code that reads its configuration from a dated evidence folder can't be reused for a new study without editing. The "evidence" folder has become a runtime dependency.
- [read] `tools/review/probe_framework.py` is described as **temporary** v2 review probes (README project map), yet `tools/validate.py` makes it a required gate.

### D4 — Append-only code policy has become code accumulation

[read] Planning documents repeatedly require that "original module bytes remain unchanged" and that repairs be "separately versioned". The interpretation capability now exists in **four generations** of parallel modules:

1. `local_interpretation.py`
2. `bounded_interpretation.py` and `run_interpretation_development.py`
3. `interpretation_questions.py` and `question_interpretation_{render,local,runtime}.py`
4. `run_question_development.py`, with a fifth generation (wire v2) planned in `planning/Question Pilot Failure Closeout and Contract Repair 2026-10-25.md`

[judg] Byte-preservation is a property of **sealed artifacts** (which receipts and code hashes already protect). It doesn't have to be a property of the **live source tree**. Git history plus per-run code hashes (`receipt["code"]`, `executed-source.py`, `code_paths`) already make old runs reproducible. Keeping every superseded module live multiplies maintenance and review surface.

### D5 — Duplicated research infrastructure

[exec] Measured duplication:

- 19 modules write or read their own `seal.json`;
- 67 modules use `RunJournal` directly;
- 5 modules implement their own code-closure or executed-source capture;
- the identical llama-server launch recipe (`--ctx-size 16384 --parallel 1 --n-gpu-layers 99 --threads 8`) is copied into **7 modules** (`run_comparison.py:329`, `comparison_evaluation.py:152`, `run_interpretation_development.py:130`, `run_question_development.py:208`, `t6_challenge.py:308`, `t6_topone_evaluation.py:145`, `framework/run_local_pilot.py:78`);
- local `sha`/`write`/`load` helpers are redefined 6–7 times each.

[judg] Each copy got its own peer-review findings: the TODO records repeated accounting, cleanup and race fixes in separate modules. A single shared "sealed study run" library would turn N reviews into one.

### D5b — The core leaks study-specific knowledge

[read] Three examples:

- `artifacts.write_run` and `verify_run` special-case the string `'local-structured-selection-v1'` and lazily import `local_model` and `retrieval` (`src/asof/artifacts.py:125,228`). Backend-specific verification should be a protocol method on the backend, not an `if` in the artifact writer.
- `ingest.py` embeds the 10-hypothesis `PILOT` case pack (`src/asof/ingest.py:50`) in the runtime library.
- `local_model.selection_payload` hard-codes a ChatML (Qwen) prompt template (`src/asof/local_model.py:202`), which ties the "model-independent" core to one model family.

### D6 — Governance overhead now dominates throughput

[exec] Of 137 commits, **28 are backup-verification commits** and 24 are fail/stop/closeout commits. Since 24 October, `planning/` grew by 3,780 lines, `tools/` by 2,330, `tests/` by 2,046 and `memory/` by 1,723.

[read] The cycle for each micro-step is:

1. specify;
2. two independent AI reviews and a third adjudication;
3. implement;
4. focused, full, isolated and no-site validation;
5. ZIP and Git-bundle backup with per-entry SHA-256;
6. freeze;
7. a single model call;
8. two reviews and an adjudication;
9. closeout;
10. a second backup.

Example: the last pilot was **one native call of 4,650 input / 601 output tokens**, wrapped in at least four commits and a multi-page closeout.

[judg] Rigor is appropriate for a final locked evaluation. Applied to exploratory development on an already exposed case, it prevents the iteration needed to find a working interpretation design. The planned wire-v2 repair has only **51 bytes of prompt headroom** at the 14,200-byte cap, which signals that the model and context budget, not the contract, is the binding constraint.

### D7 — Model and budget constraint is undeclared as a scientific variable

[read] Every native call uses a local Qwen2.5-14B Q4_K_M at 16k context and $0 provider spending. Three interpretation attempts failed on contract compliance and usefulness.

[judg] It is unknown whether the interpretation failures come from the task design or from model capacity. The design never separates the two: no attempt has used a stronger model (local or API) as a capability ceiling. This is the cheapest experiment available to resolve D1/D6. It needs an explicit owner decision because it changes the $0 boundary.

- [read] `README.md` (25 kB) opens with about 200 lines of reverse-chronological checkpoint notes. "What AsOf is" only starts at line 206.
- [read] `TODO.md` (54 kB) mixes the live checklist with history.
- [read] `memory/project-goals.md` is 84 kB, too large to be useful as a memory entry.
- [read] Systematic formatting artifacts drop the space after numbers ("passes1,262", "Tasks6–8", "throughc425225").
- [exec] README links to `reports/IL6R dossier scientific audit.md`, which `.gitignore` excludes, so the link is dead in a clean clone or on GitHub.
- [read] `docs/` holds a mix of stable reference docs (`FRAMEWORK.md`, `V02_MIGRATION.md`) and dated per-study notes (`QUESTION_*`, `T6_*`) without an index.

### D9 — Portability and off-machine durability drift

- [read] Receipts store absolute paths. `inputs.json` records `snapshot_base` and source proofs record absolute `path`. `verify_run` re-admits from those paths, so runs can't be verified after relocation (for example a different drive letter on a restore machine).
- [exec] With 65 unpushed commits, the only off-machine copy of four days of work is the user's E: bundle procedure.

## 1.5 Recommended architectural corrections (priority order)

1. **Owner decisions first** (these unblock everything else; see Part 3, phase P1):
   - (a) authorize a capability-ceiling run with a stronger model;
   - (b) decide whether to recruit at least 2 human domain reviewers for H5;
   - (c) re-scope H1–H4 to a dataset where outcomes can be qualified, or formally drop them from this phase.
2. **Split "framework" from "studies" explicitly.**
   - Promote reusable pieces into packaged sub-modules (`asof.study`): sealed run directory, journal-backed controller, code-closure capture, owned llama-server lifecycle, AACT read-only session, bounded HTTP transport.
   - Leave per-study `tools/studies/<date-name>/` folders containing only a frozen config plus a thin driver.
3. **Replace "preserve module bytes" with "preserve run evidence".** Delete superseded live modules after their runs are sealed. Rely on git tags (e.g. `study/question-pilot-v1`) and the per-run code hashes for reproducibility.
4. **Make backend verification a protocol method** (`Backend.verify_execution(trace, configuration, archive)`). Remove the hard-coded backend IDs from `artifacts.py`. Move the `PILOT` case pack out of `ingest.py` into data.
5. **Make runs relocatable.** Store paths relative to a declared root (`snapshot_base`, `raw_root`), with the root supplied at verify time.
6. **Use proportional governance tiers.** Exploratory or development tier: tests, a single self-review, one commit. Confirmatory tier: the full freeze, dual review and adjudication, plus backup. Write the tier into each plan.
7. **Rewrite the top-level docs.** README covers purpose, quick start, architecture and a current-status table, and links to a CHANGELOG. TODO holds only open items. Move history to `docs/history/`. Fix the number-spacing artifacts. Add a `docs/INDEX.md`.
