# TETHER — Frozen question development pilot controller

TETHER (Target Evidence Tracking Harness for Evaluation and Reproducibility) is the current project name. The `tether-target-agents` 0.4.0 package in `packages/tether` supplies the `tether` CLI and import namespace over the frozen AsOf 0.3.11 engine. See [installation and compatibility](../README.md#installation-and-compatibility). Historical version/arm names, module commands, source paths and wire IDs below remain unchanged; the rename does not reactivate retired study or expert-review branches. Direct API aliases preserve legacy outputs; only the separate `tether._presentation` CLI layer wraps `demo`/`run` in the [TETHER run layout](../README.md#tether-cli-run-layout). Delegated source inspection, snapshot construction and evaluation keep their engine layouts.

freezes requests, payload hashes, conservative reservations, model configuration,

Execution requires an explicit plan SHA256. Its exclusive execution directory
prevents silent resumption or duplicate generation after an interruption. It
verifies local acquired assets before launching its own loopback server with no
web UI or network model acquisition. It checks listener ownership, revalidates
the plan before each task and uses the durable question runtime with its explicit
native verifier callback. Failures stop the version; no generation retry or source
replacement occurs. Usage is reconciled from individual task journals, with
unresolved reservations retained as conservative estimates.

The task-start journal binds effective budget and declared elapsed case time.
Verification rebuilds remaining calls, input/output, cost and retry limits from the
default plan and prior measured/conservative usage, and derives the time allowance
from nonnegative, monotonic elapsed time below300 seconds. Task configuration must
match exactly. These are consistency checks, not independent clock attestation.

both tasks pass source-inclusive mechanical verification and the process stops

## Actual attempt

The frozen version stopped after the first native call (4,650 input /601 output
tokens, $0 provider spending). It emitted partial status with no reason and two
paraphrased source_report claims, violating the existing response contract. The
second question was not dispatched; no success receipt/predictions seal was written.
The owned server stopped and its PID was independently observed absent. Original
native bytes, accounting and source admission were checked offline; the response
was never repaired. The failed candidate seal and two40-leaf scientific reviews
are retained under data/benchmark/labels/question-development-review-20261026/attempt-v1/.
Third adjudication preserves proposal credit, treats qualified specificity as
ambiguous with major omission, and retains citation/applicability and usefulness
defects. It rejects a critical unequivocal-denial charge. Scientific qualification
fails independently of contract rejection. All40 leaves/13 clauses/12 source
passages and decoded UTF-8 spans replay. The native guide omits the verbatim meaning of
source_report, and the schema leaves state/reason and report/quote constraints
unenforced; these interface gaps are recorded separately from content quality.
