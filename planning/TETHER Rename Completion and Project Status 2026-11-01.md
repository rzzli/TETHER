## Corrections found while implementing the new interface

Independent review reproduced new-wrapper defects before accepting the release:
unbounded/unstable metadata and journal reads, and incomplete owned-child cleanup
after non-interrupt process errors. The corrections are confined to TETHER code.
Metadata/journals now have explicit 64 MiB bounded stable reads; dossier reads have
a separate 256 MiB bound. Inspectors consume checked journal snapshots. Process
errors preserve their primary cause and attempt bounded cleanup/reaping without
redispatch. All original failing-before probes now pass, and earlier evidence
remains retained. No frozen engine file was changed to obtain these results.

The standalone guide's first work-directory example would have created work
inside the read-only packet. It was corrected before freezing the qualification;
work/source/build/demo paths now live in a fresh sibling tree. One paper
preparation inverse assertion initially had incorrect replacement order and
stopped before writes; its corrected inverse and prior failure note are retained.

## What intentionally retains the old name

TETHER/TETHER names remain in frozen code, old distribution/contract identifiers,
datasets such as `tether_normalized_packets`, temporal snapshot-date fields,
source paths, original experiment arm labels, receipts, READY files, PDFs/ZIPs,
original proposals, dated research logs and review evidence. Rewriting these
would invalidate provenance or misrepresent what actually ran. They are
compatibility/history names, not a second active project identity.

The old `TETHER` command/imports still work. TETHER's new distribution owns only
its own namespace and has its own genuine launcher/version proof; it does not
forge old metadata or claim coverage by old code inventories. Current CLI
commands create a separately sealed TETHER presentation around the unchanged
engine result, rather than editing a completed receipt or its dossier.
