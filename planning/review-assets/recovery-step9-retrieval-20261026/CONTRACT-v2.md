# Prospective bounded-retrieval preparation bridge

Status: superseding v2 contract only; v1 and its independent review are preserved. Implementation requires accepted 0.3.4 and independent review. No runtime, tests, resources, data, native process or model is changed by this draft. Human submissions are not required to test these deterministic engineering mechanics; scientific evaluation remains a separate unfinished gate.

## Finite purpose and track identity

Bind a prospectively declared, fully qualified collected-corpus candidate universe to deterministic whole-record retrieval and a source-complete interpretation request. Name the track `bounded_collected_corpus_preparation`; do not call it unrestricted end-to-end retrieval, a new clinical benchmark, or original Virtual Biotech tool reproduction. Fixed-evidence artifacts, existing two-fixture allowlists and all previous receipts remain separate and unchanged.

First implement one new invented, hash-authenticated six-record source-only corpus with a single category and question. Include equal-ranked records with reversed input order, one irrelevant/unknown-context record, a high-overlap oversized whole record, sufficient small records to hit the count cap, and negation/Unicode in source text. No answer key, expected scientific judgment, scores, hidden labels or known real case is a prompt resource. Expected engineering selection IDs belong in tests/evaluator fixtures outside source resources.

A real universe expansion is optional later and needs a new prospective external authority: explicit universe IDs, one category, same case/question, complete original mapping/evidence row replay and raw/receipt pins. The one-source14b7 authority is not permission to enumerate or select additional real rows. If no separately approved expanded universe exists, report synthetic mechanics plus a pending real-source qualification gate.

## Authority before ranking

New source universe authority contains version/track, case and question binding, one explicit category, sorted unique candidate observation IDs (maximum16), candidate grounded fingerprints, method/source profile, source-preparation receipt and its independent authority SHA, package/resource authority, strategy policies and limits. An output-local self-consistent hash or caller-supplied record dictionary cannot authorize a candidate.

For real sources, reuse source_preparation with its declared observation selection equal to the **entire candidate universe**. It performs whole-snapshot kernel admission, raw/receipt/role/temporal checks, full mapping replay and whole method2.2 Observation reconstruction for every candidate. Require exact candidate-ID membership and fingerprints in its returned request/audit before retrieval. Raw-qualify excluded as well as selected ranking rows: a changed excluded statement can change the result. Missing source, failed QC, foreign case, unapproved namespace, evaluator ancestry, unsupported normalization, nonempty features or failed original-row reconstruction blocks qualification of the declared universe. Record the failure without substituting another candidate or silently ranking a surviving subset.

Synthetic originals are complete typed invented Case and GroundedObservation records with synthetic methods, citations, lineage/resource identities and a pinned package resource. Qualify by exact resource equality, decoded contract validity, case identity, empty features and every grounded-record fingerprint. Use an explicit invented/demo authority profile. Do not fabricate Open Targets method2.2 records, HGNC mappings or public-download receipts. These records undergo synthetic structural authentication, not contemporary raw-source admission. Both branches produce a deeply immutable `QualifiedUniverse` carrying the exact external authority and parent receipt/resource anchors plus every candidate grounded fingerprint. A Python type, frozen instance, private-looking constructor or authority_kind label is not authority. Every public retrieval/compilation entry must reauthenticate the approved external anchor and parent bytes/resource and recompute full candidate identity; a caller cannot construct or copy a universe with altered selected or excluded records. Approved external anchors are explicit caller capabilities, never learned solely from output-local metadata. Replay requalifies the entire declared universe.

Before reading any input, reuse approved root/component and protected evaluation-path guards. Source and receipt locks remain held through qualification/ranking/compilation when real sources are involved; verified request-buffer hashes and parent anchors are rechecked before returning the derived artifact. Generic replay must not import old tools, read gold/outcomes, spawn tokenizers automatically, or fetch missing sources.

## Two explicit deterministic policies

1. `literal_case_overlap_then_id_v1` delegates to existing `retrieval.bounded_request` and `RetrievalPolicy`. It ranks by unique `[a-z0-9_]{3,}` tokens in the **case JSON** intersecting statement tokens, then ascending observation ID. It does not use the interpretation question, provider score or biological evidence strength. The algorithm can retain zero-overlap records; preserve that documented behavior rather than borrowing the separate lexical baseline's zero-match rejection rule.
2. `id_order_v1` ranks ascending observation ID and applies the same whole-record greedy count/serialized-byte constraints. Implement only the small rank-order adapter and reuse the same request serialization/size policy and audit format; do not pass a falsified empty case into bounded_request to trick it into ID sorting. If a narrow reusable rank-order selection helper is necessary, version it explicitly without altering old bounded_request behavior or its traces. Do not describe different caps as different algorithms.

Both use max_records2, max_request_bytes12,000 and canonical wire encoding initially. All candidates remain whole. At each ranked position, retain a record only if the exact existing SpecialistRequest serialization fits and the count cap permits it. Skip an oversized record with an explicit reason and consider subsequent records; no scientific string clipping, field dropping or patching. Preserve exact rank/tie order, selected order and exclusion reason/order. Duplicate IDs/ambiguous records fail before selection. Base case/instructions exceeding the byte cap is a preparation failure, distinct from a valid empty universe or all-records-over-cap result.

Only one category per question is supported initially. This avoids inventing unreviewed cross-category allocation/quotas. More categories require an explicit later policy; no category receives a hidden full independent budget.

## Original fields, views and interpretation compilation

Use `agents.make_request(case, category, original_grounded_records)` for the existing transient retrieval input. It can clear out-of-scope numerical features/add feature_applicability in its EvidenceView; the initial qualified source profile already rejects nonempty features, but even so the view is not an authoritative scientific record. After selection, resolve IDs back to original qualified GroundedObservations. The real branch continues through unchanged source_preparation.compile_request and diagnostic_codec.bind_question. The synthetic branch uses a separately named synthetic compiler that reuses pure source-copy/coverage/bounds/instruction literals and the existing question binder while preserving the invented profile, snapshot, synthetic methods and citations. Never replace DEMO with CONTEMPORARY to pass the real compiler. Its legacy admitted_sha256 field represents a grounded fingerprint only, with an explicit synthetic-structural-authentication notice outside and inside its invented input instructions; it does not assert real admission. Verify every original scientific_record/citation/statement/grounded fingerprint unchanged. Never serialize the transient view into the interpretation evidence or use it to bypass whole-record equality.

The existing compiler emits evidence in deterministic category/store order, which may differ from retrieval rank. Preserve both orders explicitly: selection ranking is in retrieval audit; compiled source alias order is in the bound request/pointer table. Do not silently relabel aliases to reflect rank. Quote pointers resolve only within the actual compiled subset; excluded IDs and prior selections cannot become citations.

Coverage records original admitted availability, declared candidate-universe size, raw-qualified size, selected IDs/count, omitted IDs/reasons, collection missingness and selection scope. Add bridge-specific coverage as a separate versioned manifest rather than changing the original compiled request fields and claiming14b7 parity. Distinguish empty universe, all whole records too large, count-cap exclusions, ineligible/corrupt universe failure and unknown collection coverage. None is biological absence or a scientific negative. Retain zero-source outputs without replacement; the scientific-answer status is not_attempted until a genuine recorded/inference response has been validated.

Current source_preparation authority requires a nonempty selected source set. Do not weaken it just to encode an empty universe. Empty-universe authority must be a prospectively pinned case/question and intentionally empty candidate declaration, distinct from the six-record positive fixture. A failed qualification cannot be silently converted into empty success. The new bridge's explicit empty-universe result is a terminal coverage artifact bound to that case/question/universe authority; it performs no nonexistent raw-row replay and does not masquerade as a valid nonempty source-preparation receipt. An all-over-cap result starts from a valid nonempty qualified universe and similarly produces empty selected coverage. A separately labeled recorded abstention fixture can test state propagation without inventing evidence.

## Minimal APIs and artifact composition

Proposed one new `study.retrieval_preparation` module, plus a tiny installed fixture writer only if required:

- `qualify_universe(authority, external_sha, source_receipt, roots, deadline) -> QualifiedUniverse`: real full-row qualification or exact invented source-pack authority. No candidate JSON bypass. For real inputs, call source-preparation verification under the external source receipt/authority anchors, then bounded-read its exact request buffer and prove the buffer hash against the verified receipt before recovering typed Observation and Citation objects. Construct GroundedObservation and check its whole fingerprint against admitted_sha256, source-audit whole-record identities, the manifest candidate inventory and original case/question scope. This is an internal trusted reconstruction from verified bytes, not an assumption that source_preparation returns a live store. Keep source locks/checks across qualification and recheck parent receipt/buffer identity before acceptance; caller-supplied decoded records are never authoritative.
- `retrieve(universe, policy, approved_anchors) -> immutable RetrievalResult`: reauthenticate the universe/resource or externally anchored parent preparation, then original IDs, rank inputs/scores where applicable, policy and request fingerprints, byte counts, ordered exclusions and complete universe binding. Deterministic, zero provider/model calls.
- `compile_retrieved(universe, result, approved_anchors) -> interpretation request or explicit empty coverage`: reauthenticate all original records and recompute the policy result, then resolve originals, compile and bind same question, produce exact quote table and source equality report. Reject foreign/mutated result policies/IDs/universe hashes.
- `prepare_retrieval(..., output=NEWDIR)` / `verify_retrieval_preparation(path, receipt_sha, approved_authorities, roots, deadline)`: reserve once, reuse RunJournal/atomic/proofs, retain source authority/proofs, rank inputs/audit, selected request/payload-preparation links, common four-arm access manifest and terminal status. Verification recomputes qualification/ranking/compilation with bounded reads and exact resource mapping; never starts a process automatically.

No new scheduler, backend protocol, source database or cache subsystem. Compose current source_preparation/source_rows, existing retrieval serializer, compile_request, diagnostic contracts and code/resource proofs. A richer generated-response controller is outside this slice.

## Interpretation integration and the four arms

For each policy, all four arm preparation records share exactly the same allowed universe, retrieval policy limits and resulting visible source packet. This is a common-access preparation test, not evidence that four independent agent systems retrieved or interpreted well. Keep AsOf and explicitly adapted VB labels honest; original VB MCP retrieval remains unreproduced. Deterministic extraction/lexical are not model calls and their empty generated interpretation remains distinct from a scientific answer.

Do not call existing baseline/fixed_evidence public APIs with renamed retrieved fixtures or monkeypatch their authentication. This slice need not fabricate four arm outputs: retain access/preparation manifests for all four, and add **one recorded interpretation-consumer integration cell per policy** using the existing StudySession, RecordedBackend and an explicit new retrieval-receipt verifier. Authenticate the new invented corpus, original selected records, actual payload, scripted response and parent retrieval receipt. The authoritative parent retrieval/preparation receipt must bind each child case, corpus, policy, selected original IDs, request and payload. The consumer verifier checks that independently anchored relationship and exact scripted transport stimulus, not merely a child self-signed request hash. Two cells demonstrate a retrieved input can enter the interpretation contract; they do not reproduce the full AsOf1/VB5 role-chain comparison. A full four-arm authority-aware execution composition remains later work.

Recorded response fixtures are evaluator-only transport stimuli, never source evidence. Preserve exact as-emitted fixture content and apply existing strict response validation with dynamic min(3,original max_claims) limits. Source_report copies exact original text; authored inference/caution is separate and must carry limitations. Empty selected coverage can exercise an explicit validated abstained fixture, with a reason bound to access/size conditions rather than biological absence. No repair, generated selection feedback, native call, model quality or clinical probability is introduced.

## One shared budget and preparation resources

One unchanged Budget per invented case covers both strategy preparations and both recorded integration cells together: 16calls,32,000input,8,000output,$0,300seconds,max_retries1. No arm/policy/stage budget reset. Parent reservations and child elapsed/fixture usage reconcile against one monotonic absolute case deadline, including both retrieval preparations. The second cell must fail before dispatch if the shared budget/deadline is exhausted. Children cannot expand remaining allocations or establish a new parent budget through local receipts. Pure retrieval/raw qualification/pure baseline preparation use zero model reservations and measured CPU time. The two recorded cells use declared fixture usage separately from actual model usage0, no automatic retries, common output cap1,024 each. Count every complete serialized prompt/history frame in preflight; existing StudySession byte+32 capacity remains in force for these invented cells. If their combined quotes exceed a shared cap, preserve the failure rather than silently selecting smaller sources, changing the corpus or inflating budget. Full native token-aware dispatch remains stopped.

The real optional route ends at source/retrieval/interpretation-preparation receipts and token-aware sizing if explicitly requested, with its own prospectively declared case preparation budget; it has zero recorded/native interpretation by default. Do not misreport a tokenizer quote as a generation or model usage. Exact hypothetical source-ID histories are sized only for their actual bytes; they do not prove a universal BPE upper bound.

Resources include the new immutable source-only invented corpus and versioned retrieval policy/schema. Source fixtures contain no expected selections/answers. Exact case/question and candidate membership are frozen before selection; maximum16 is a declared scope limit, never a claim of complete snapshot availability. Evaluator response stimuli and assignment metadata remain outside reviewer/source bundles. Record exact code/resource inventory and external anchors; test every semantic layer under resealed tampering, not only byte corruption.

## Regression-first acceptance and limits

1. Six-record fixture gives nontrivial policy behavior; ties, reversed input order, zero overlap, count cap and oversized record exclusions match declared semantics.
2. Any changed selected **or excluded** candidate statement, context, source reference or grounded fingerprint invalidates qualification/replay before ranking. Real original-row mismatch cannot pass because its final selected record happens to be valid.
3. Case/namespace/role/temporal/proof-root failures precede source access; evaluator/foreign IDs rejected; synthetic profile cannot claim real admission.
4. All selected original fields and exact citation pointers survive compilation; transient feature_applicability mutation never enters original records; nonempty features fail.
5. Empty/unavailable/over-cap states produce distinct truthful coverage; no replacements, implied absence, fabricated scientific answer or baseline-as-model usage.
6. Ranking/query/policy/universe/request/resource/source-audit tampering is detected after a malicious internally consistent reseal, including extra/missing members and resource name/path substitutions.
7. Two recorded consumer cells share one budget/deadline and preserve one-attempt failure records; duplicates, interruption, write failure, expired deadlines and concurrent output reservations leave no success receipt or duplicate dispatch.
8. Public forged-universe/result, changed external anchor, fake synthetic/contemporary profile, substituted parent request bytes and tampered grounded-citation fingerprints fail even when internally self-consistent.
9. Installed verification and relocation retain explicit approved-root semantics; no archived imports, subprocess/network invocation during retrieval replay, or changes to old fixed-fixture authentication. Earlier accepted installed replays remain valid.

Acceptance establishes bounded collected-corpus engineering only. Full end-to-end source access, real generated comparisons, native reopening, stronger-model control, scientific references and R08 exposure/reviewer qualification remain unresolved. Human availability is not a blanket blocker for this finite implementation; none of its tests substitutes for human scientific adjudication.
