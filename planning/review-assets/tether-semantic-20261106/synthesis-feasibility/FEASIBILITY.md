Do not conflate these statements: future archive validation must establish the authoritative count, ordered IDs, uniqueness, missing-reference conditions, and GTR/DPR/oracle ID joins. ### Memory, download and compute envelope

AutoAIS source checkpoint files total **45,492,657,356 B**; all repository files total 45,495,926,988 B. The index reports logical tensor storage **45,624,074,240 B**; half of that is **22,812,037,120 B (21.25 GiB)** as a BF16 tensor estimate. Serialization and tied-tensor accounting explain why these measures should not be treated as identical. None is measured runtime peak. Its 24 encoder/24 decoder layers and `d_ff=65536` make layer placement and activation memory significant. [Pinned model/index](https://huggingface.co/google/t5_xxl_true_nli_mixture/tree/aa6cfe1dd4257853bfdd772992045f41bfc14988).

On 16 GB GPU / 32 GB RAM, unchanged BF16 weights with CPU offload are plausible, not yet qualified. Unload the answer model; use low-memory shard loading and an explicit measured GPU/CPU allocation, reserving OS, activation and shard-loading headroom. A roughly 10 GB FP32 shard can coexist with CPU-resident BF16 weights during loading; that peak must be tested. Native `get_max_memory` does not itself establish a safe host-RAM cap. Do not replace the model, change precision or quantize to make an unmeasured budget seem feasible. A placement/backend change needs fixed-input tokenization and entailment parity checks, numerical comparison where available, and a retained manifest. [Native memory utility](https://raw.githubusercontent.com/princeton-nlp/ALCE/246c476a4edfc564266b7346b6e29ef4861ae937/utils.py).

The full README command additionally uses RoBERTa QA and GPT2-large MAUVE. Metadata pins are retained: RoBERTa `02bcd9fab9c9d84a346389074e0bcdf770c5141b`, model file 1,417,412,145 B; GPT2-large `32b71b12589c2f8d625668d2335a01cac3249519`, choose exactly one format (native PyTorch file 3,247,202,234 B). Retain tokenizer files, package/model notices and bootstrap/MAUVE seeds. RoBERTa's tiny model card has no explicit license metadata; its redistribution/use terms remain to be established. Sequential evaluator lifetimes avoid summing all GPU allocations. [QA model](https://huggingface.co/gaotianyu1350/roberta-large-squad), [MAUVE feature model](https://huggingface.co/openai-community/gpt2-large).

For N questions, one answer is N generation calls; one critique plus one repair is at most another 2N. A shared initial answer permits baseline versus repair with at most 3N unique generation calls and 2N distinct final answers to score. Score raw and structurally admitted identical text once, retaining the exact join. For S output sentences and at most three citations, native citation scoring takes at most **7S NLI calls**. At 948 answers averaging eight sentences, that is a scenario ceiling of **53,088 NLI calls per answer condition**; one second/call is 14.75 hours, ten seconds is 147.5 hours. These are arithmetic scenarios, not measured throughput or a guaranteed upper bound on sentence count. After outputs seal, deterministic sentence/citation enumeration can give a tighter exact work bound without looking at gold scores. All-three-family execution is therefore not an implicit cheap extension.

Before any full run, root must freeze an output-token cap, maximum wall time, byte/memory ceilings, failure handling and complete-family rule using invented length-boundary controls and measured evaluator throughput. A deadline leaves unfinished scheduled cases explicitly unfinished; it does not justify reporting only a convenient prefix. Provider charge can be $0 with existing local hardware; wall time, electricity, storage and network transfer remain costs. No benchmark tuning or inference was done here.

### Native endpoints versus a feasible local changed condition

**Citation support:** the pinned Scholar implementation actually loads **`osunlp/attrscore-flan-t5-xl`**, BF16, and accepts literal `Attributable`; the Google TRUE implementation is commented out. Its two source weight files total **11,399,225,634 B**, while its index logical FP32 tensor storage is 11,925,413,888 B; the corresponding BF16 logical estimate is 5,962,706,944 B. This is a materially smaller native judge than ALCE's. It still needs loading, tokenization, source alignment, invalid/empty citation and numerical controls. Reusing ALCE's judge here would change the evaluator. [Pinned citation code](https://raw.githubusercontent.com/AkariAsai/ScholarQABench/95e6fc52b0a8a0ce0a74956029991e3bb00c38b9/scripts/citation_correctness_eval.py), [AttrScore model](https://huggingface.co/osunlp/attrscore-flan-t5-xl).

**CS rubric correctness:** the native evaluator defaults to GPT-4-turbo and scores expert properties on 0–10. It also handles expertise, evidence, citations/excerpts and length, so a count of one judge call per answer is incorrect. For K properties and E conditional evidence checks, its principal call envelope is approximately 2 + K + E per answer; exact branches/counts must be frozen from actual test configurations. The runner skips missing responses and can deduplicate repeated prompts: separately reconcile all scheduled IDs and annotation units. A local replacement is a changed judge condition, not native published rubric-score equivalence. [Rubric implementation](https://raw.githubusercontent.com/AkariAsai/ScholarQABench/95e6fc52b0a8a0ce0a74956029991e3bb00c38b9/scripts/scholarqacs_rubric.py), [runner](https://raw.githubusercontent.com/AkariAsai/ScholarQABench/95e6fc52b0a8a0ce0a74956029991e3bb00c38b9/scripts/rubric_eval.py).

**Multi quality:** the official recipe uses Prometheus-BGB-8x7B for organization/coverage and Prometheus-8x7B for relevance. Each has 46,702,792,704 BF16 parameters and **93,405,713,504 B** of safetensor files. Each exceeds combined 16 GB GPU + 32 GB host RAM before activations; disk offload would need separate large-storage/latency qualification. The BGB card's license field explicitly remains unspecified. Neither a small active-expert compute estimate nor a quantized substitute makes native full-weight residency fit. [8x7B model](https://huggingface.co/prometheus-eval/prometheus-8x7b-v2.0), [BGB model card](https://huggingface.co/prometheus-eval/prometheus-bgb-8x7b-v2.0).

The official **Prometheus2-7B** is a credible prospective $0 local alternative: 7,241,732,096 BF16 parameters and **14,483,498,000 B** of safetensors. Its authors describe 16 GB VRAM use and publish both absolute and relative grading formats. Model-card metadata is Apache-2.0, with an additional generated-training-data terms note to retain. Use its proper Mistral template and reference/rubric inputs; do not invent a smaller BGB variant. Small-batch BF16 plus CPU offload may be needed for long references. Windows support of the repository's vLLM path is unqualified; its alternate hardcoded Llama loader is not evidence of Mistral compatibility. A separately qualified Transformers backend must use the correct architecture. [Official variants](https://github.com/prometheus-eval/prometheus-eval), [7B model/template](https://huggingface.co/prometheus-eval/prometheus-7b-v2.0), [Scholar judge code](https://raw.githubusercontent.com/AkariAsai/ScholarQABench/95e6fc52b0a8a0ce0a74956029991e3bb00c38b9/scripts/prometheus_eval.py).

Recommended candidate: whole Multi108, native AttrScore citation metrics plus **explicitly labelled Prometheus2-7B quality scores**. Three aspects require 324 judge calls per answer condition; a 512-token judge output ceiling gives 165,888 generated judge tokens. Two answer conditions require 648 calls / 331,776 ceiling tokens, excluding qualification and citation entailment calls. Avoid self-consistency or automatic retry unless separately budgeted. The 7B native 1–5 format is well aligned with Multi's scale; it is not a drop-in CS 0–10 scorer and must not be silently doubled.

Qualification should use released references and rubrics, plus fixed invented matched controls for missing required content, unsupported addition, irrelevant but fluent text, citation mismatch and output-format failure. Test score direction, criterion isolation, deterministic repeatability, parsing, truncation, answer-order bias and reference copying. Distinguish these checks from human-judge agreement: expert reference answers are not human scores for every candidate response. The public [expert-evaluation repository](https://github.com/AkariAsai/OpenScholar_ExpertEval) documents an annotation interface, not proof that all underlying human ratings are released. Retain unresolved agreement evidence; no new expert-recruitment requirement is introduced. Do not tune the answerer or thresholds using these benchmark answers. No qualification can establish native GPT/8x7B equivalence without direct evidence.

### Evidence-route blocker and stage boundary

OpenScholar publishes a link to offline retrieval results, a more plausible local route than rebuilding a 45-million-paper datastore. Its [README](https://github.com/AkariAsai/OpenScholar) links a [public Drive folder](https://drive.google.com/drive/folders/1lOloYPOveKesD-37lD4Dlju96tc0XIm9?usp=sharing). This review did not establish file IDs, immutable hashes, sizes, passage rights, complete question joins, date cutoffs, or whether retrieval/reranking was independent of gold rubrics/answers. Public link availability alone is insufficient. A future fixed-source experiment can use a qualified question-only released retrieval pool; otherwise a bounded independently obtained source collection is a changed retrieval condition. A gold-paper supplied-source diagnostic must stay separate from end-to-end retrieval.

Before SC06/SC07 execution, unresolved items are: (1) archive/subset ID and rights validation; (2) source-pool independence and date/rights manifests; (3) native evaluator/backend, loading and numerical qualification; (4) frozen local-judge changed-condition controls; (5) measured full-family runtime/storage budget; and (6) complete scheduled-output/failure reconciliation. These are preparatory technical checks, not a request for new human experts. No full-stage preparation or benchmark success is claimed.
