# SC04–SC05 LitQA2 feasibility from retained assets

Prepared 6 November 2026. **Preparatory only:** no model execution, benchmark acquisition, new experiment implementation, answer-key calibration, or baseline modification was performed for this note. SC04 execution follows completed SC03. The analyzer for SC01 remains unchanged.

The useful next experiment is a small factorial comparison of question-only semantic query expansion and passage reranking, with one common answer producer. The archived baseline already retrieves and answers; adding retrieval or another reviewer role is not itself a new capability. A separately labelled supplied-source condition can help distinguish source access from interpretation, but cannot count as ordinary retrieval performance.

## Proposed controlled SC04 conditions

Freeze a 2×2 design over every original 199 question before new candidates:

| Arm | Two search queries | Passage selection | Maximum model calls charged per question |
|---|---|---|---:|
| L/O | Retained lexical query rule | Frozen lexical overlap selector | 1 answer |
| E/O | Question-only semantic expansion | Same lexical selector | 1 expansion + 1 answer |
| L/R | Retained lexical query rule | Bounded semantic reranker | 1 rerank + 1 answer |
| E/R | Same semantic expansion | Same reranker | 1 expansion + 1 rerank + 1 answer |

All four new arms have the **same maximum total allowance**: three model calls, 768 generated tokens, the same per-call context/prompt limit, two metadata requests plus three full-text attempts, identical response/time/byte caps, and at most eight raw passages/8,000 selected bytes for the final answer. Actual usage differs and must be reported; equal ceilings do not mean equal consumed compute. Do not pad arms with meaningless calls. Keep one common final answer prompt/model/option order across new arms. The old 199 outputs remain a historical control if source time, allocation, prompt or producer qualification changes.

Question expansion receives only question text. It emits exactly two bounded structured query descriptions, without options, answer identity, DOI/source hints, benchmark names, or source-derived feedback. A deterministic serializer escapes query syntax and adds the same date/license filters. Preserve named entities, organism, measurement, numerals and negation; expansions may propose aliases but are retrieval hypotheses, not established equivalences. Parsing failure is a retained failure or a prospectively defined lexical fallback with its own counter, never an unrecorded retry. Do not allow the model to retrieve or invent a benchmark answer page.

For new search branches, a deterministic round-robin allocation can reserve one full-text slot from each query before the third, deduplicating article IDs. Apply this identical rule to lexical and expanded queries. This addresses the first-query priority mechanically but changes the historical route; it must be frozen as a shared new-arm component and not credited to expansion alone. An exact legacy-allocation comparison would be a separate condition, not a quiet implementation detail.

For each search branch, freeze the same original full-text bodies, extraction, chunk boundaries and lexical shortlist **before** comparing O versus R. The ranker receives the question and complete raw candidate chunks only: at most 16 candidate IDs and 10,000 candidate-text bytes, filled by a deterministic shortlist rule. It returns an ordered subset of valid IDs, with no generated replacement evidence or relevance-probability claim. A full prompt still must pass the 14,000-byte and exact tokenizer limits; excluded candidates and overcapacity are explicit. Keep complete chunks rather than silently showing only a preview. Select at most eight ranked chunks within the common 8,000-byte final budget. Ranker and lexical conditions use the same permitted candidate pool, even though their selected contexts differ.

Thus O/R comparisons have exactly the same acquired source bytes within each query branch. Expansion comparisons necessarily can retrieve different documents; they share the same eligible source universe, acquisition time window and resource caps, not identical realized evidence. Claiming a query effect while forcing identical realized documents would conflate retrieval with a closed-corpus diagnostic. Seal both search branches before answer generation, and report source identity/rights/extraction coverage separately from selected-passage and native-answer outcomes.

This local listwise reranker uses a pretrained model through a fixed prompt; it is not a newly trained cross-encoder, PaperQA2 reproduction, or learned Self-RAG reflection policy. Summarization and citation traversal remain later controlled conditions. Raw original spans remain the answer evidence.

## Separately labelled supplied-source diagnostic

Use the already audited DOI annotation projection as trusted diagnostic control data, opening no answer or key-passage fields in the answering process. Resolve the 190 unique DOI identities through supported metadata routes, verify exact article identity/version, acquire only explicitly allowed reusable full text, and preserve attribution/license evidence. There are at most two annotated papers for any current question, so the existing three-article cap is sufficient for annotated identities if eligible. Do not infer availability from a DOI, abstract, HTTP 200, benchmark license, or annotation. Record unavailable, ambiguous, restricted, unparsable and missing-section outcomes for all 199.

At one metadata resolution and one full-text attempt per distinct DOI, the proposed ceiling is **380 HTTP attempts**, plus at most 199 answer generations/tokenizations and 50,944 generated tokens. With 1 MiB metadata and 2 MiB article caps, the response-body reservation is at most 570 MiB before any tighter global bound. This is only a Europe PMC route estimate; a missing result does not authorize an arbitrary publisher scraper or imply permanent unavailability. Reuse an already captured exact body when its identity and rights verify. No acquisition is authorized by this note before the stage gate.

The primary diagnostic supplies annotated papers and uses a question-only frozen passage selector under the same context cap. It does **not** supply the annotated key passage. A further key-passage/rationale-only diagnostic would be explicitly privileged and needs separate rights/normalization and role checks. Building a union of annotated papers and hiding their per-question mapping is still a privileged benchmark-derived corpus. Report all-scheduled and eligible-source denominators, paper identity, extractable/selected passage coverage, native correctness and operational status. Differences from ordinary retrieval are diagnostic interventions, not a causal estimate of real-world retrieval gains. Supplied paper identity does not certify answer entailment.

## SC05 repair, uncertainty and genuinely held-out opportunities

Prospectively freeze one-pass, critique-only and one bounded repair. Begin from the identical first-pass candidate and captured evidence. Critique-only can flag insufficiency or induce a declared abstention; it cannot manufacture a new correct answer if the substantive answer bytes are unchanged. Repair gets at most one critique and one additional answer, with any refined retrieval explicitly charged. If refinement adds one metadata query and one article, every arm's common access ceiling must account for those two extra requests; unused allowance and actual cost stay visible. No gold source hint, correct choice, key passage or evaluator feedback enters the critique or refined query.

Shared execution costs at most **597 generations** for 199 first answers + 199 critiques + 199 repairs, or **398 new calls** if an eligible, prospectively specified sealed first-pass artifact is reused. A repeated 199-item public evaluation remains exposed. Count repaired wrong answers, damaged correct answers, new/lost substantive coverage, retained unsure, parse/operational failures and selection loss for each paired question. If summaries are introduced, retain raw spans alongside them, and separately test raw-versus-summary under identical context and total caps; do not treat a model's self-assessment as independent citation verification.

No eligible LitQA2 calibration set has been qualified in the inspected assets. The retained `github/LitQA2/litqa-v2-splits.json` lists **199 public IDs and 49 private IDs**; it does not provide those private question/source/answer records or authorize their use. All 199 public answers have already been evaluated. A newly selected random subset of them does not restore an untouched calibration/evaluation split. The reserved 69 SciFact claims are a different native task and cannot establish LitQA2 risk calibration.

Concrete future opportunities are: (1) an actually available separate literature-QA training/calibration release, after source/article/version and near-question overlap screening against the 190 annotated DOI identities and all exposed tasks; (2) newly constructed factual MCQs from prospectively sampled, rights-qualified publications outside those source groups, with independently verified keys and a separately frozen evaluation cohort; or (3) the private original task only if legitimately released/available, which is not presently established. Fictional or synthetic controls can tune mechanics but do not by themselves justify real-question risk guarantees. These opportunities still require source availability, task comparability, rights, label quality and dependence checks; no external source has been acquired or certified here. Until one qualifies, use fixed predeclared abstention settings and descriptive risk/coverage plots only, without a calibrated-risk claim or threshold selection on these 199 answers.

## Primary-source peers already in the saved report

The following are inherited references from [the saved comparison update](../../../../reports/TETHER%20benchmark%20comparison%20update%202026-11-06.md), not a fresh literature survey or new verification of current upstream code:

- [PaperQA2 methods and ablations](https://arxiv.org/html/2409.13740v1): query-conditioned retrieval, relevance processing, contextual summaries and citation traversal motivate the ranking and raw-versus-summary controls. Its use of LitQA2 during system design and different source/model budgets rule out treating its headline score as a matched control.
- [OpenScholar paper](https://www.nature.com/articles/s41586-025-10072-4) and [implementation](https://github.com/AkariAsai/OpenScholar): feedback-guided retrieval refinement and answer repair motivate the bounded SC05 comparison. A local prompted approximation must identify what was transferred and what was not reproduced.
- [Self-RAG paper](https://arxiv.org/abs/2310.11511) and [official code](https://github.com/AkariAsai/self-rag): learned retrieval/critique signals motivate conditional retrieval and abstention; a prompted Qwen critique is not the trained Self-RAG method.
- [ERASER](https://aclanthology.org/2020.acl-main.408/): evidence removal, rationale-only and irrelevant/conflicting-context controls test evidence dependence. Native ERASER probability-based metrics require their own prerequisites.
- [ALCE release](https://github.com/princeton-nlp/ALCE): separates answer correctness from citation support/completeness. Existing source hashes, source identity and self-judged support are insufficient replacements for qualified semantic evaluation.

The [original LAB-Bench paper](https://arxiv.org/html/2407.10362v1), retained task README and [dataset](https://huggingface.co/datasets/futurehouse/lab-bench) define the upstream family. Its original tool-free setup differs from every proposed source-assisted route. Rights checks for source bodies remain distinct from dataset/code/model terms.
