## Proposed exact profile boundary

Use a distinct `--unicode-controls` mode with nine arguments including the executable: EXE, mode, pinned runtime directory, exclusive output directory, new Unicode pack, pinned CPU basename, and three explicit model shard paths. The exact EXE and new pack are unbound until separate verified build/preparation gates. ABI version remains `0.7.0-dev`; ABI module policy `807995…` is preserved. Recognition phase policy remains `4d5e09d70d0f6e4cec6c1754dbbec1add6b2985754ead811128a27eb6a138713`: pre-CPU forbids CPU; post-CPU requires the one exact eligible pinned CPU plus self/core4. Trusted platform reports are lexical context, never child-serialized image authenticity.

All 84 cases occur once, in frozen ordinal order. The 78 declared native-byte-eligible cases receive document tokenization and singleton grammar observations. The six declared raw-byte harness exclusions have ledger `null`, native membership `null`, the exact declared reason, and zero per-document native calls. Unexpected token bounds/EOG/roundtrip/row-cap problems are QC unknown, not an extra declared exclusion or false membership. Authored generation expectations, semantic eligibility, observed membership, QC and harness disposition remain separate fields.

Full token IDs, byte lengths and lowercase piece hex arrays are retained for every QC-valid eligible case, including nonmembers and nonpopulation cases. Empty pieces remain at their original token indices. No piece is decoded as standalone UTF8. Concatenation must equal the frozen raw document. The parent reconstructs all boundaries using the accepted analyzer and compares compact counts/matrix/zero-piece totals rather than trusting child classifications.

Population membership is the frozen conjunction of native-byte eligibility, authored generation membership and semantic eligibility (68 cases); observed membership cannot filter it. Only after the whole corpus scan, select the first `(case ordinal, original token ordinal)` for each of width2, width3, width4 and same-piece complete-scalar-plus-pending classes, then de-duplicate equal boundaries. At most four unique selected prefixes get fresh grammar samplers. Prefixes use original counted token prefixes, never re-tokenization. Missing/unknown required coverage remains negative. Case mismatches remain visible and do not stop a safe whole-corpus scan or remove geometry candidates; unknown native returns/ownership or hard limits stop further native work and leave the tail unknown.

The mixed interval and matrix units are exactly the accepted analyzer contract: a wholly contained complete scalar interval in the final piece before its pending scalar, not merely completion of an earlier-piece scalar; each boundary contributes once per distinct contained complete width. A boundary may satisfy several classes. Selected witness rows retain all labels and earliest interval per distinct width.

## Proposed new pack framing

Use new eight-byte magic `R09NU01\0` and little-endian u32 version1, never the old `R09NC02` format. Header binds the immutable profile/wire semantic fingerprint, corpus and stage metadata hashes, with exact counts 4 stage instances, 2 grammar records, 84 case records and 4 implicit coverage classes. Distinct grammar order is first appearance in frozen stage order; stage records preserve their original payload hash and grammar reference. Cases preserve original ID, ordinal, stage index, stratum, raw byte count/hash/bytes, separate authored ternary expectation dimensions, harness disposition and derived token cap. No observed IDs, selected cuts or favorable case list enter the pack. Grammar bytes are bounded by the existing 65,536-byte grammar ceiling; raw documents by the stricter profile 1,024-byte ceiling. Full consumption/no trailing bytes, exact record ordering and all hashes are mandatory. Final field widths/enums still require the machine contract.

## Rows, calls and finite arithmetic

The proposed result sequence is: fixed setup/source/module/version/CPU/shard/vocab events; exactly 84 `unicode_before_case` / `unicode_case_result` pairs; one whole-population coverage summary; zero to four unique selected-prefix result rows; cleanup result; batch-returned/footer/normal-completion. Failed paths retain their partial acknowledged prefix and independent failure marker, never a complete footer. Exact event schemas and stage-native-call schedules are still pending; old 189/6 counters cannot authorize this profile.

Every result row has a strict schema version, contiguous row sequence, event, elapsed milliseconds and bounded native attempted/returned/state snapshot. Native reservations precede calls; returns/side effects are captured before post-call checks/publication. Current result snapshots exclude their own successful-written increment, witnessed by the next/final frame. Unknown killed tails and unknown creation/free dependencies preserve the existing no-retry cleanup barriers. No per-hot-call JSONL flush is added.
