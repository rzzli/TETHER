# Fictional file-port fixtures

The current suite is `FILE-PORTS-FIXTURES-v3.json`, bound to closed schema v3. It has 84 fictional cases: the 16 required fault families, one limited composition baseline and 15 supplemental signed-BOOL controls. Raw BOOL preserves the exact signed32 value: zero fails, any nonzero succeeds, including `+2` and `-1`; Python `bool` and out-of-range inputs are rejected by the prospective normalizer's control cases. No platform export was added.

`file_port_fixture_script_v2.py` supplies the callable fake API, clock and fault-hook sequence. It returns only literal planned raw observations, checks exact arguments and before-dispatch diagnostic projections, and fails on missing or extra calls. It does not implement file identity, hashing, ownership, cleanup, path admission, source loading, graph validation, readiness or any verifier gate. Its tests echo supplied script steps to check interchange and exception identity. Expected port states are separately authored data, not results produced by a port.

The baseline composes a fictional namespace, reservation/journal write and flush, one three-byte original read/hash/capture, and known closes. It is not a complete verifier, first-clock entry, actual journal proof, 13-checker pipeline or terminal-seal success. Its `terminal_ack` and every qualification flag remain false. Primitive cases may start with explicitly fictional owned slots or readiness; a future harness must mint test-local objects rather than accept serialized labels as operational authority.

The cases distinguish known versus undefined read/write counts, namespace ownership versus readiness, once-only correct closers, work cutoff versus hard deadline, late returned bytes versus pending hashes, and raw metadata versus accepted traversal. No scripted API dispatch occurs at or after 300 seconds. The two-root fixture counts C and D once each. Astral paths explicitly contain 4,096 and 4,097 UTF-16 units, independently of Python character count.

Plan fixtures are a narrow arithmetic interface, not a real source roster. Non-target values are coherent with `E=6N+2B+2M+4S+161`, per-file read bounds and conservative `derivedE+412` write allowance. E/read/write negative cases deliberately forge derived claims. Guards receive actual plan or facts references, never fault-name selectors. DAG facts contain fictional node paths/pins, direct edges and operation states; a same-path case actually aliases two paths. This does not authenticate those descriptors.

Schema v1/v2, literal v2, its callable v1 proof, the root BOOL finding and Native's finite precheck are preserved. Schema/data v3 correct only that test-domain and input-data preparation; API scripts and authored expected byte/close outcomes are unchanged from literal v2. The ten current methods check encoding, literal consistency, caps, signed types, sequence matching and mock immutability. Actual port conformance, complete bootstrap/loader/checker composition, real roster/resource/time fit and any live qualification require separate reviewed implementation and root authorization.

No CPU, model, old pack, actual archive, original source closure or filesystem path named by a fixture was opened. There is no ctypes/SDK/API dispatch or port implementation in this stage.
