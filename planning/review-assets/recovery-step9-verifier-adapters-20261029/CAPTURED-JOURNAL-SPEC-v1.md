# Captured-byte journal checker: contract before implementation

The actual native parent uses `RunJournal(kind="build")`. Its envelope is the accepted writer's sequence/event/details/previous-digest/digest record, serialized as canonical compact sorted UTF-8 JSON plus ASCII LF. Its event policy is **not** the application-run dispatch/usage policy. Source inspection is a format reference, not a fresh identity check or an execution of the old SDK/parent.

The [machine contract](CAPTURED-JOURNAL-CONTRACT-v1.json) separates a generic writer-chain check from an explicit `detached-recognition-parent-v7-known-launched-journal-v1` source-order check. Chain-only results never establish native order, resource correctness or profile eligibility. Valid early/prelaunch failures fall outside the known-launched completeness scope; an intact prefix cannot be promoted through the generic check. A new Unicode parent needs its own future source/event-policy version.

Both APIs accept exact captured bytes, never a path, stream or handle, and require an injected owner deadline callback. Path strings inside records are compared as expected metadata without filesystem operations. Checks occur around bounded hash chunks and each bounded parse/canonical/hash/reference step. Deadline exceptions propagate; no new clock is started or reset.

Framing requires nonempty strict scalar UTF-8, no BOM, no blank/CRLF rows and a final LF. Split only ASCII LF, preserving raw U+0085/U+2028/U+2029 inside JSON strings. Each row must be canonical, with exact field names, strict integer sequence, no duplicate object names or nonfinite numbers, and a recomputed pre-digest SHA-256 linked to the previous row. Bounds are 8 MiB total, 64 KiB JSON per row, 2,048 events and nesting64. Iterate bounded line positions before allocating row objects; do not split millions of empty lines first.

The native policy follows the source: `build_reserved`, recognition attempt, initial ordered file lease/hash triplets, empty Job, suspended creation, assigned-before-resume identity, one resume, bounded running snapshots, terminal observation reservations, final matching file triplets and one final recognition terminal. Hashes alone cannot permit reordering, a duplicate launch or an application event name. Captured configuration/report/reservation values provide exact reference bindings. Raw resource decoding remains another gate.

Synthetic fixtures use source-format records and explicit expected reference projections. They are not admitted real execution configurations or model files. Correct and deliberately invalid chains are fixed before the checker is implemented. Rechained semantic attacks distinguish source-order checks from hash checking. The old failed experiment and incomplete external verifier remain unchanged.

This source-only contract and its fixtures authorize no implementation until root reviews them, and no file/SDK/native/model/tokenizer/compiler work at any stage here. A pure checker pass concerns only its exact envelope/policy/reference domain; it is not live verification or scientific evidence.
