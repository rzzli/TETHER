# Same-owner engine continuation: finite integration gap

This review reads only the accepted new `deterministic_verifier_v2.py` and `verifier_bootstrap_interfaces_v2.py`. Both remain pure injected prototypes. No source, input, lease, namespace or clock was exercised, and neither file is changed.

The immediate gap is concrete: `Handoff.claim()` returns an `EngineContinuation` referring to the existing `BootstrapOwner`, but that continuation exposes only check, snapshot and close. `run_once()` instead samples another clock value, constructs a new `_Owner`, mints another token and registry, calls an output factory and reserves output again. Calling it after handoff would lose the original start and state. Passing a numeric old start alone would still leave two owners, monotonic latches, registries and cleanup authorities.

The smallest prospective wiring is a separately reviewed continuation entry accepting the exact claimed continuation, not a serialized start or ready marker. It needs these six changes, without replacing the ordered gate engine:

1. **Adopt one time domain and identity.** Retain the same `Origin` object, nonce, start, monotonic last sample and 295/300-second ends. Engine time/check/report operations must delegate to that shared source-owned state rather than independently sample and maintain `_Owner.last_time`. Reconcile `WorkExpired` versus engine `Deadline` into explicit timeout bookkeeping while retaining the original exception identity. The existing `run_once` fresh-owner path is unsuitable for adoption.

2. **Adopt the live registry and output.** Carry the same source port, sink, output identity, reservation state, events, primary errors and actionable slots. Bootstrap `LeaseSlot` and engine `_Lease` have different interfaces; copying them would duplicate close rights. Engine reporting may use views, while one registry owns each closer and its once-only attempt. `reserve(ack)` and `reserve(key,ack,end)` are also incompatible. Adoption must not call either again. The current bootstrap echo acknowledgment does not establish a real namespace, output-file identity or reservation readiness; that requires the pending source-bound file/sink adapter.

3. **Adopt exact early bytes, then hash only the remainder.** Match each early source claim to an exact full-roster software/capture specification by canonical identity, role, size, digest and capture policy. Require the current `_fresh_context` identity/nonce and still-live inspected/hash-complete slots. Carry immutable captured bytes, digests, observed/hash counts, pending states and time/events already spent. Do not reopen or hash the early subset again, or translate a saved `hash_complete` flag into authority. Construct the full engine `CapturedContext` under the same nonce only after all remaining originals are freshly covered; only then may the hashes gate complete.

4. **Continue the same source loader and journal.** Factories and actual checker adapters must come from the same captured-byte `CapturedLoader` and closed dependency map, not ordinary imports or own-module cache fallback. Continue one journal sequence and admission reservation, including early identity/compile events; do not reset the 128-event prototype counter or engine 2,048-event counter independently. Reconcile event shape and the full joint plan before remaining opens. Keep the existing ordered owner-local gate proof discipline. Bare `CheckerPorts`/`CheckObservation` objects remain trusted test ports until their actual captured-format adapters are implemented and bound.

5. **Retarget finalization to the shared owner.** `finish()` currently closes originals before invoking one opaque `sink.seal(candidate,ack,end)`. The prospective file/sink composition needs candidate write/flush/close before original cleanup, then cleanup artifact, final journal flush/close, receipt close, seal close and final same-origin acknowledgment. Neither a seal return token nor an earlier output-owned boolean proves those observations. Never let engine and bootstrap finally blocks independently close copied leases. The pure engine's reporting-only `sink.failure()` after a deadline cannot dispatch real I/O after the hard cutoff; retain an in-memory failure when publication is no longer allowed.

6. **Keep the raw FFI boundary separate.** Engine `port.open()` returns `OpenReturn` only after the port has done its work, and engine `ReadReturn` already contains copied bytes. Those return objects cannot preserve a raw handle/count lost during identity queries, copying, allocation or a late clock inside the port. The real adapter must receive a preallocated central slot, register the Python-visible raw result/defined count immediately, then perform identity, clock, hash/capture and normalization. Bootstrap's slot-observer pattern provides the pure seam, not proof of an atomic native-to-Python transfer. Output/search slots need the same owner lifetime. Fictional `RawReturn` scripts do not close the actual FFI gap.

The first real entry must still sample its origin before importing either helper or reading/validating source. `start_injected()` is explicitly a synthetic entry, not that bootstrap. Existing path bounds also differ: the bootstrap prototype checks Python character length, while the prospective file-port contract requires explicit UTF-16 units. Do not silently promote either prototype spelling rule into a platform guarantee.

No implementation is proposed here beyond that finite adoption seam. Real entry/FFI/sink code, exact source roster and event arithmetic, actual archive/journal/resource/Unicode checker binding, and integrated positive completion remain pending separate source/pure review and root decisions. This note neither repairs the old timeout nor authorizes another original-input pass or runtime.
