# E08 external manifest policy contract

The [contract](E08-EXTERNAL-MANIFEST-POLICY-CONTRACT-v1.json) and [structural schema](E08-EXTERNAL-MANIFEST-POLICY-SCHEMA-v1.json) specify one prospective same-Core entry-policy successor. They are frozen metadata, not an implementation or an E08 runtime pass. Source3 and its 50-pass/three-deferred proof remain unchanged.

The trusted setup supplies a separate kernel-defined immutable ManifestPolicyBinding. Its constructor detaches bounded ordinary containers while deferring scalar semantics to the after-Core validator. The original clock, Origin, nonce, Core, Registry and raw store exist before validation. The envelope cannot select its own current IDs, trusted roots, mode or expected input basis. No output callback, original open, helper import or continuation precedes the policy check.

AUTHORING accepts explicit planned/unbuilt INPUT or CONSUMER nodes with null pins and reasons, returns AUTHORING_ONLY and stops before FileSpec/output work. EXECUTION requires exact static pins, binds ordered basis IDs to independently selected actual EntryPlan file pins and then proceeds through existing file/hash/lease/output barriers. Neither report status authenticates the launcher, admits fresh files or creates native authority.

Content-pin edges point from dependents to prerequisites. Static INPUT/CONSUMER ancestry cannot reach the current decision/output; global self/mutual cycles are refused. Downstream current decision/output provenance may refer to static inputs. Root IDs/pins are bound out of band; a role label or ready flag cannot confer trust.

An immutable report that returns before a late clock or issuance failure remains retained as noneligible prepared data. The public report stays absent and work remains barred; cold reads cannot retry or heal. After a genuinely issued execution report, an unrelated later work/accounting error does not revoke known close rights. Cleanup retains the original hard-clock and once-only rules.

Metadata limits are 256 nodes, 4096 edges, 128-byte IDs, 256-codepoint reasons, 14 current outputs and 131072 canonical combined UTF-8 bytes. The illustrative 74-slot construction starts from the retained 48-resource staging record; its unresolved selections and external provenance remain unknown. These are finite metadata refusal limits, with no original7/physical cap lift, roster-fit or RSS claim.
