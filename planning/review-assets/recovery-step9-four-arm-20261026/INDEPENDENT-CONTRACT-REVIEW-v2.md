# Independent four-arm contract review v2

2026-10-26. Read-only review of CONTRACT-v2.md/JSON against the current installed-source APIs. **Conditional approval for the narrow tests-first implementation**, subject to the concrete API conditions below. This is design acceptance, not acceptance of unimplemented code, scientific validation, or permission for native generation. The retained current-0.3.5 quotes establish sizing only.

## Required API conditions

1. **Replay deadline must be explicit.** Use `verify_study(..., capacity_policy=None, deadline=None)`. An absent policy and absent deadline preserve legacy behavior. Token-mode replay requires a caller-supplied finite absolute deadline, passed to capacity verification and `verify_tokenization(..., deadline=None)`; check it around cooperative proof/file/verifier work. Live finalization passes the remaining original case deadline. Independent offline replay gets a new caller-selected verification deadline and must not compare today's monotonic clock to the recorded execution clock. No per-cell renewal of 300 seconds inside a shared run.
2. **Quote acquisition and allocation checking are distinct.** The new adapter's `quote()` must authenticate the externally anchored token receipt and derive exact `Usage(count + 32, n_predict, 0)` before Session has a quote to validate. Share a small authenticated reservation helper inside `token_capacity.py`; then `TrustedTokenCapacity.verify(request, payload, caps, quote, budget, deadline=...)` checks the actual allocation and exact reservation equality. Do not invent a Budget inside `quote()`, accept an unverified integer, or infer the policy from a backend ID. The descriptor may omit its physical locator for relocation; it must retain the four external SHA anchors and trusted implementation identity. Bind `caps.tokenizer_identity` to the verified spec SHA.
3. **New-mode ordering preserves failed attempts.** Persist immutable request/payload before fallible token-quote work. Only after quote and capacity binding pass may configuration2 and `study_prepared` be written, followed by dispatch reservation. A rejected quote retains a readable preflight failure, zero dispatches, no measured usage and no fabricated complete configuration or success receipt. Existing schema1 ordering stays unchanged. Recompute the binding before finalization and replay.
4. **One-use consumption gets the final time check.** `RecordedBackend.generate()` dynamically invokes `self.quote()`, so a token-quoted subclass is compatible with its document semantics. However, checking time only before delegation is insufficient: quote verification may consume the remaining time. Follow the existing `DeadlineRecordedBackend.generate()` boundary: quote, validate document, check the absolute deadline, then mark consumed and return/raise the scripted outcome. Ordinary RecordedBackend remains unchanged. The explicit `verify_recorded_execution(..., capacity_policy, case_deadline, interface)` helper must authenticate the actual subclass and its exact provenance/document/fixture usage; `case_deadline` is recorded execution provenance, not the offline replay deadline.

These are finite implementation conditions, not reasons to stop authorized engineering. A small versioned contract addendum or the implementation acceptance record should pin them; preserve CONTRACT-v2 bytes if already pinned.

## Compatibility and composition assessment

The proposed configuration2/receipt2/report1 tuple, sealed descriptor plus binding and `capacity_sha256`, is sufficient without changing the required output file set. Require explicit policy in execution and replay; reject policy-on-schema1 and schema2-without-policy. `_capacity`, ordinary RecordedBackend and the old two-fixture public gates retain their current semantics. No schema name, class-name string or archived code may instantiate a policy. Preserve all existing physical byte, output, context, response, zero-cost and allocated-budget bounds; replace only the input byte-proxy lower bound with authenticated exact token count plus 32.

The proposed source wrapper and pure-baseline wrapper are appropriately narrow. Requalify the current-package retrieval parent and all original candidate fields; preserve the complete selected request and distinguish GroundedObservation from Observation fingerprints. Reuse pure selection logic only after authority validation. The lexical query, normalization, tie order, whole-quote caps, empty interpretations and neutral-view recomputation are specified adequately. A parent retrieval receipt cannot be replaced by caller-provided JSON or a synthetic allowlist alias.

Six scripted cells plus two pure arms share one original Budget and one deadline, including source/proof/spec/tokenizer setup, pure work, child execution and final sealing. Actual source-ID history must come from verified accepted same-run/same-arm predecessors before each payload's quote. The six hypothetical sizing payloads are not upper bounds on arbitrary BPE histories. Fresh current-package quotes are mandatory after code freeze. No additional model calls, policy grid, new data or source replacement follows a failure. Tokenizer CPU work, quote reservations, fixture-reported usage and zero actual model calls remain distinct.

## Permitted implementation surface

- `src/asof/study/tokenization.py`: optional caller deadline on read-only verification; absent preserves current behavior. Replay creates no child and opens no model assets.

- New `src/asof/study/authority_four_arm.py` and narrowly needed versioned source-only/stimulus resources: authenticated one-policy composition, actual-history payload rendering, pure wrappers, journal/accounting/receipt replay using existing helpers.
- Focused new regression tests; normal version/package-proof/profile updates and frozen-old-version verification are parent-owned release work.

No changes to ordinary RecordedBackend, old baseline/fixed-fixture admission gates, existing study controllers, scientific admission rules or native runtime are needed for this slice.
