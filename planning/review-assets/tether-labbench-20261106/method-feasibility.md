# BG04 methodology and source feasibility

Reviewed 2026-11-06. **Proceed with the owner's selected all-199 public LitQA2 protocol: question-only search, eligible full-text retrieval, a fixed local answerer and native multiple-choice scoring.** This choice was made before candidate performance. It is a defensible tool-assisted public-family evaluation, conditional on source/runtime qualification, not a reproduction of the 2024 model setup. DbQA remains a technically viable alternative; it is not categorically account-blocked. This review opened methods, dataset/scorer documentation and local engineering metadata; it did not inspect LAB-Bench answer rows or score candidates.

## Family choice and the original-task boundary

The public card lists 520 DbQA and 199 LitQA2 questions, with a CC-BY-SA-4.0 dataset license. Public files use a split named `train`, but they are benchmark questions, not automatically authorized training supervision. LitQA2 additionally contains source links and `key-passage`; these fields are privileged for the main answering route. Public exposure and the retained private subset preclude claims of a hidden or contamination-free test. [Official card](https://huggingface.co/datasets/futurehouse/lab-bench/raw/main/README.md)

The original paper describes LitQA2 as requiring information beyond abstracts. DbQA spans several databases: its gene-location labels use Ensembl 110 **as collected in MSigDB C1 2023.2**; other tasks involve DisGeNET/OMIM, miRDB, gene-set collections and variant/protein resources. Original model results used no tools, shuffled choices, an insufficient-information option and a parser with an LLM fallback. A local retrieval system therefore uses original questions under a different declared access regime; it does not reproduce those published model conditions. [Original paper, §§C.8 and D](https://arxiv.org/html/2407.10362v1)

| Route | What is feasible now | Unresolved before execution |
|---|---|---|
| DbQA, gene location | Deterministic version-specific lookup can produce actual answers without a generative model. Question/option parsing and independent coordinate/band checks are technically modest. | Verify the exact release, symbols and band semantics. Ensembl 110 coordinates alone do not prove equivalence to MSigDB C1 membership. Do not substitute a current chromosome collection. |
| Full DbQA | Public question release is available; the official public MSigDB 2023.2 archive lists the exact C1/C3/C6/C7 products. Its web interface's registration message is not a blanket access blocker. [Versioned archive](https://data.broadinstitute.org/gsea-msigdb/msigdb/release/2023.2.Hs/) | Per-product access, exact versions and source support remain unqualified across all 520 questions. MSigDB terms are CC-BY-4.0 with additional terms for named collections; respect individual products. [Terms](https://www.gsea-msigdb.org/gsea/msigdb_license_terms.jsp) |
| LitQA2 | Question-only literature search and retrieval are technically possible; an answer selector could be local. | Full-text acquisition and parsing coverage remain unknown. Europe PMC metadata access does not imply that every paper's full text is available. An abstract-only route cannot stand in for this task. [Official API documentation](https://dev.europepmc.org/RestfulWebService) |

A predeclared native gene-location subtask evaluation preserves its original questions and labels, but is **not representative of every DbQA subtask**. If that is the executable scope, report it explicitly and leave broader coverage unproven. Full-family results require the complete frozen denominator, with missing sources and unsupported subtasks retained. Modified questions, substituted source versions, supplied key passages or benchmark-selected per-question source hints require a separately named derivative/oracle condition. A corpus assembled from all annotated target papers is also a privileged closed-corpus regime even if the per-question mapping is hidden.

No source access failure in this review establishes permanent unavailability: some web fetches were blocked by the tool. The source-acquisition agent's retained byte/endpoint checks should decide readiness. No account access or source completeness is invented here.

## Native scoring, isolation and paired comparison

Use correct/total accuracy, correct/answered precision and answered/total coverage. The current Inspect implementation supplies a concrete external mapping/scorer, pins dataset revision `5c77cec648430f30611808808861eb86f81d5eaa`, and distinguishes the explicit insufficient-information choice. It is an implementation to pin and qualify, not proof that the original paper harness has been reproduced. Its precision convention returns zero when nothing is answered; additionally report that denominator as zero rather than presenting it as evidence of good calibration. [Task implementation](https://raw.githubusercontent.com/UKGovernmentBEIS/inspect_evals/main/src/inspect_evals/lab_bench/lab_bench.py), [scorer](https://raw.githubusercontent.com/UKGovernmentBEIS/inspect_evals/main/src/inspect_evals/lab_bench/scorer.py), [metrics](https://raw.githubusercontent.com/UKGovernmentBEIS/inspect_evals/main/src/inspect_evals/lab_bench/metrics.py)

1. Freeze release, source scope, scheduled IDs, parser, resolver/model, budgets and stopping rules before candidates. Qualify strict choice parsing on fictional records. Declare removal of the original paid LLM parsing fallback. Invalid syntax, timeout, input unavailable and valid insufficient-information remain distinct states.
2. The predictor receives `id`, question and neutrally named, shuffled choices; eligible retrieved source rows/passages arrive through a separate manifest. Reference targets, original `ideal`/`distractors` labels, key passages, per-question oracle sources and permutation maps stay evaluator-only. The correct option's text necessarily appears among choices; its provenance must not reveal which option it is. Do not expose a shuffle seed that reconstructs the original always-first ideal position. [External sample mapping](https://raw.githubusercontent.com/UKGovernmentBEIS/inspect_evals/main/src/inspect_evals/lab_bench/record_to_sample_helpers.py)
3. Produce each candidate once. Apply raw and checked projections to those exact bytes with identical source/model/tool affordances. Report accuracy/precision/coverage for both, correct-and-admitted/all-scheduled, correct-but-rejected counts, incorrect-but-admitted counts, explicit abstentions and operational failures. Use a separate denominator for provenance conformance; answer correctness is not inferred from a valid citation hash.
4. Freeze an independent scorer's answer map before evaluation. The scorer opens references only after candidates are sealed. Preserve failed calls and source failures in the scheduled denominator; no silent repair, exclusion, model swap or extra attempt. Native metrics and the operation-status table must reconcile.
5. Retain question ID as the native unit; group dependencies by normalized query/template plus source gene set, cytoband, protein accession or article/version as applicable. Fit/tune/calibration, if used, split groups before training. Report per-subtask/source strata and component IDs. A few source/template groups do not become a large independent sample merely because many questions reuse them.
6. Include an always-abstain control and frozen random-choice controls. With `m` substantive options, uniform forced choice has expected accuracy `1/m`; uniform choice among those plus abstention has expected accuracy `1/(m+1)` and coverage `m/(m+1)`. Report exact case-specific expectations when option counts vary. Keep chance answering, source-backed answering and operational failure distinct. Choice-order perturbations must be paired and predeclared, not selected after observing scores.

## Zero-provider-cost answering feasibility

The structured DbQA route is the clearest immediate candidate: a resolver can identify a source-defined entity, query a pinned table, evaluate all substantive options and abstain on ambiguity or missing evidence. That is genuine task computation, not copying the benchmark key. It still requires source and parser qualification; correct parsing alone does not complete BG04.

Local model storage is available: the existing Qwen2.5-14B Q4_K_M mirror contains three shards totaling about 8.99 GB. The retained hardware inventory reports roughly 32 GiB RAM and a 16 GiB RTX 5070 Ti. These establish resource plausibility, not demonstrated inference feasibility. A new task-specific protocol would need fresh tokenizer/runtime checks and fictional smoke tests, bounded context/output, measured memory/time and a pinned prompt. No historical closed model attempt is reopened. A lexical option ranker could be an explicit weak baseline, but neither its existence nor an untested GGUF is a qualified literature-answering component. [Local resource inventory](../../../research_notes/TETHER%20benchmark%20priorities%20and%20methods/bg03-resource-inventory.json)

All 199 questions are reasonable as the intended denominator, subject to measured fictional throughput. Freeze source-request counts, article/packet byte limits, context/output tokens and global time before execution. Source failures stay scheduled; access to an article does not guarantee that the answer fits the selected context. A hash-selected 64-question sample would also be defensible if declared for a smaller budget, but cannot be expanded after tuning on its answers and then described as an untouched all-199 evaluation. Neither 64 nor 199 is automatically statistically powered; article/source grouping matters.

## Defensible source diagnostics for the selected LitQA2 run

Gold metadata is opened only after candidate outputs are sealed. The predictor's main search uses question text, not the supplied source URLs, key passages or answer identity. Restrict retrieval to publication/database content and exclude benchmark/mirror QA pages; retain unsuccessful searches and exact response bytes. Search success reported by another agent on a nonbenchmark query supports endpoint availability only, not coverage of the 199 questions.

| Diagnostic | Defensible interpretation | What it cannot establish |
|---|---|---|
| Any annotated source retrieved; fraction of annotated DOI/PMID/PMCID identities retrieved | Annotation-relative retrieval hit rate/recall after explicit identifier reconciliation. Report missing/ambiguous identifiers separately. | Exhaustive literature recall; that all listed sources are jointly necessary; that an unmatched source is irrelevant. |
| Full text obtained, eligible license, parsed sections and truncation coverage | Source acquisition and usable-context availability, with all-scheduled and source-available denominators retained. | Scientific relevance or support for the chosen option. |
| Returned quote/span resolves to frozen source bytes and locator | Citation/quotation integrity and exact source linkage. | Entailment, causal validity or whether the quote answers the question. |
| Gold key passage recovered verbatim or under a separately declared normalization | Lexical recovery of an annotated passage; useful to locate retrieval/extraction failures. A nonmatch can remain unresolved because of version, formatting or truncation. | Semantic rationale recall or proof that the answer follows from that passage. |
| Correct option and policy-admitted output / all 199 | Useful native-answer completion under the stated provenance checks. | Faithfulness of reasoning or semantic validation of every cited passage. |

Call these **source alignment and integrity diagnostics**, not an entailment score. Without a separately qualified semantic scorer, retain semantic support as unevaluated. A paid model judge is unnecessary for native MCQ grading and must not be introduced as a hidden parsing fallback. Reference metadata and passages remain evaluator-only even when used to compute these diagnostics.

## What would address SciFact's weak semantics

The reconstructed run retrieved 159/209 annotated document pairs and the full evidence-document set for 147/188 evidence-bearing claims, yet achieved only 27/300 strict cases—26 of them NEI. Improving retrieval alone cannot explain away this gap. The following are future, separately frozen experiments, not changes to the completed run. [Independent result review](../tether-scifact-20261105/reconstruction/ACTUAL-RECONSTRUCTION-REVIEW.md)

| Priority | Peer method to transfer | Why it addresses the observed gap |
|---|---|---|
| 1 | Joint claim/document classification and rationale selection with contextual representations, as in MultiVerS. | Tests negation, relation and full-context reasoning that sparse overlap features do not model well. Pin checkpoint training provenance: an off-the-shelf SciFact checkpoint can violate the project's custom fit/tune grouping. Reusing its reported score is not a comparison. [Paper](https://aclanthology.org/2022.findings-naacl.6/), [checkpoint distinctions](https://raw.githubusercontent.com/dwadden/multivers/main/README.md) |
| 2 | Calibration and selective answering, evaluated at matched coverage. | Train-only negative sampling and a separate calibration partition can address overprediction and unsupported extra evidence. Tune confidence/rationale thresholds without using the now-exposed development outcomes; retain risk-versus-coverage and useful/all-scheduled metrics. This is a proposed intervention, not a promised improvement. |
| 3 | Evidence sufficiency and removal controls inspired by ERASER. | Test whether retained evidence drives the answer: evidence-only, selected-evidence removal and irrelevant-evidence controls. An unchanged answer can indicate weak evidence use, but removal can alter task meaning; controls require explicit interpretation. [ERASER](https://arxiv.org/abs/1911.03429) |
| 4 | Separate answer correctness from citation support/completeness, following ALCE's evaluation dimensions. | A source-valid wrong answer currently passes. For structured DbQA, independent source membership checks can test support directly. For literature, a qualified semantic scorer is still required; source hashes or a model's self-assessment are insufficient. [ALCE](https://arxiv.org/abs/2305.14627) |

Adding more agent roles before these tests would not resolve the demonstrated weakness. The present contribution is an auditable execution/evidence boundary with measured costs; semantic improvement must be demonstrated separately. This note introduces no new expert-input gate, paid call or claim of benchmark completion.
