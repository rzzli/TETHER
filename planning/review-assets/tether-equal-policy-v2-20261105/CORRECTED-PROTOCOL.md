This is a post-result correction of the original 108-case experiment, not a hidden evaluation. Preserve its frozen files, decisions, mismatches and causal diagnostics. The original [policy specification](../tether-equal-policy-20261102/POLICY-SPEC.md) and [execution protocol](../tether-equal-policy-20261102/EXECUTION-PROTOCOL.md) continue to govern the 27 obligations and measurement boundaries. ## Corpus corrections

The new corpus has 109 cases, all classified as `exposed_authored_construction`. The exact changes are in `corpus-deltas.json` and the independently authored cases module. EP023 seals its additional source before testing lineage escape. EP072 and EP097 contain eligible perturbation work after genetics, making the no-later-dispatch check nonvacuous. EP075 retains its deliberately invalid request fingerprint while refreshing the deterministic dossier and seals, eliminating the unrelated table-ordering fault. EP077 correctly expects rejection without recovery observables from a corrupt chain. EP109 is a clean recorded-replay parent with a valid request binding. EP001/EP025 remain two policy views of the same construction; no independence claim is made.

Expected answers come from the normative contract, not agreement between implementations. Corpus construction and materialization never read scored results or invoke a validator to infer an oracle. Their authors know the previous results; every revised result must disclose that exposure. Unit controls establish that new later-work observations are eligible and that repairing only the intended lineage escape makes its neighbor admissible.

## Version-matched experiments

Run two complete four-arm comparisons: original qualified TETHER 0.5.1 / AsOf 0.3.12, then a separately qualified replay-corrected TETHER 0.5.2 / AsOf 0.3.13. Each uses the same 109 semantic constructions, three order-rotated repetitions and the independent validator, hash/schema diagnostic and reject-all control. Each has its own fresh output, native production, freeze, 1,308 scheduled cells and independent reconstruction.

Within each run, all arms consume exactly the same bytes, external anchors and runtime identity. Across versions, native code proofs, provenance, receipts and paths necessarily differ: valid outer archives require matching current installed code. Do not weaken that requirement to put two versions into a common positive outer-artifact arm. Cross-version comparisons are semantic twins with disclosed byte differences, not identical-input estimates. An optional same-byte core replay counterexample is a separately labeled diagnostic; current-code diagnostics must be interpreted relative to the installation.

The new independent entrypoint reuses the original immutable schema, admission, lineage, features, replay and policy helpers. Its versioned outer verifier accepts only the two declared version pairs and still reads actual installed source and distribution metadata on every call. Runtime version support is the only policy adaptation; provenance, permissions and request-binding rules are not relaxed. Report both reused code and new integration code rather than treating the wrapper as the entire implementation.

## Qualification and execution

1. Retain failing-first replay regressions, positive/partial/legacy boundaries, the original counterexample, current focused tests and independent source review. Qualify the patched package and archive compatibility before claiming it is an installed candidate.
2. Validate versioned source construction, native materialization, runtime selection, independent version checks, worker contract and complete-denominator behavior. Pin every transitive original helper and all new execution modules, policy documents, qualification proofs and wheels. Independently pin analysis code.
3. Materialize and freeze separately for each qualified runtime. A failed producer or a missing native case prevents a completed comparison. Preserve failures in fresh directories; never overwrite original attempts.
4. Execute all scheduled cells in fresh isolated workers with unchanged budgets, deadlines, output qualification thresholds and no provider calls. No automatic retry enters an existing comparison. An interrupted or filesystem-failed schedule remains incomplete.
5. Reconstruct all decisions, observables, failures, groups, resources and source/runtime/byte inventories independently. Also audit rejection reasons and valid neighbors so a correct decision for an unrelated fault does not establish the intended obligation.

The hash/schema control remains deliberately weaker and its directory-read error is retained as an error unless a separately declared revision changes that implementation. Reject-all remains a useful coverage sanity control. Neither replaces the independent full-policy arm.

## Reporting and completion

Retain original and corrected results separately. Report false admissions among rejected cases, false rejections among eligible cases, inspect-only agreement, observable mismatches, unsupported/error counts and all scheduled denominators. Repetitions and overlapping policy-family labels are not independent samples. Original exposure classifications remain historical metadata; none of the corrected corpus is described as unseen.

Primary resource boundaries remain import plus operation or complete launcher wall time, with OS lifetime peak memory and explicitly labeled logical input/retained-copy volumes. Instrumented fresh-process timings on a shared Windows host do not establish warm-service performance, physical I/O or general efficiency. Whole installed package source counts include unrelated capabilities and are not a minimal-equivalent validator complexity measure.
