# Science 7 post-seal T6 evaluation design

The evaluator opens arm predictions only after the caller supplies an externally recorded SHA-256 for `predictions-seal.json`. It verifies that digest before parsing the seal, then validates the frozen source-only plan, exact ten-case/six-arm membership, execution report, each arm's output inventory/journal/native-call verification, model/configuration/role-policy bindings and the complete admitted sourceworld. The launcher must have opened no evaluator answers. Outputs go to a fresh directory; errors remain inspectable. No evaluation step invokes an inference backend.

Each arm binds its full model configuration, retrieval recipe and upper budget to the frozen plan even when it made zero calls. The evaluator retains the caller's expected digests rather than repinning a later file version. Case/snapshot, admitted normalized/raw inputs and archived source receipts are rehashed before completion. Evaluation helpers are archived at entry and their live and archived versions are terminally rechecked; reports include that code inventory, and output seals cover nested archived files.

The prediction seal must bind six launcher artifacts: preparation and execution journals, server command, model configuration, and both native output logs. The evaluator validates their paths, bytes and journal hash chains; requires the exact frozen lifecycle and arm schedule, model-verification event, matching started/ready PID and stopped terminal state; and checks the recorded command against the receipt-pinned model/runtime, IPv4 loopback and offline flags. The actual acquired weights, native archive and extracted runtime bytes are independently verified once before any reference join, with file metadata signatures captured before hashing and checked immediately afterward and at completion. This check is distinct from trusting a recorded receipt. These artifacts remain trusted Python launcher records, not independent native attestation. The original-row audit requires the matching completed model-byte verification and revalidates launcher proofs without rehashing all weights a second time.

Each arm's archived `executed-source.py` must match the workflow source in the frozen plan. Every nested file listed in its seal, including native response records and its journal, is individually retained for terminal rehashing, and exact nested inventory is checked again. Planned executing-code archive copies are likewise terminally pinned. A later change to nested bytes cannot be concealed behind an unchanged outer seal hash.

The candidate world is all 10,512 admitted normalized observations from the frozen ten-case source bundle. Retrieval limits are common across arms and recorded per category. The 50 Science 2 Q1 statements are evaluator-only references, **not** the candidate-world definition. Consequently reference overlap may be small. Q2–Q4 later external biology context is not a required sourceworld fact and is not an answer key here.

Each selected claim must exactly match its observation ID, category, full admitted GroundedObservation and fingerprint, including statement, context, source metrics, missingness, source locator/citation, target and indication. These checks establish copying fidelity against the admitted normalized store. They do not establish biological validity or original-row fidelity beyond separately audited rows.

A Q1 join requires the same case, hypothesis, observation identity, exact frozen source build, original-row hash, statement, observed context, source metrics, missingness, source locator and original source artifact hash. In these Q1 records, `version_applicability.snapshot_id` denotes the frozen build-report SHA-256 (`b3f5b4352215bd571159f190799d4ce865999d8bf3d9e51712183d55979124f3`), rather than the per-case `Snapshot.snapshot_id`. The evaluator separately admits each pinned case snapshot. Source-grounded AI references remain labeled agent-adjudicated development evidence. Selected statements with supported or contradicted Q1 annotations are counted separately; uncertain/unavailable and missing/unapplicable references remain explicit. An unreviewed claim is **unknown**, never automatically incorrect. Selection/reference overlap describes conditional source-annotation agreement, not model reasoning accuracy, therapeutic relevance, mediation or clinical truth.

Reports stratify by case, arm and category: full collected-world records, bounded retrieved candidates, selected statements, reference universe and overlap, supported/contradicted/uncertain/unavailable/unreviewed counts, status/missingness, measured versus estimated token usage, physical calls and elapsed resources. Failures, budget exhaustion and provider-score inapplicability remain separate from zero evidence. Collected-scope absence does not become biological absence.

The arms share given sourceworld/case/model and upper ceilings. Adapted Virtual Biotech executes its restricted source-derived role chain; it is an adaptation rather than original-system replication. Ablations are separate executions with categories disabled before retrieval, not masks over an existing output. Source-copy success can be mechanically guaranteed by ID-constrained selection; this outcome must not be sold as demonstrated comparative scientific superiority.

The ten cases can share targets, sources, studies and model errors. Reports contain descriptive counts and paired selected-set overlap only. No P values, confidence intervals, AUROC, Brier, calibration, clinical-success estimates or independent-scientific-truth claims are produced. Clinical evaluation remains withheld under the Science 3–6 decisions.

A separate post-seal original-row audit requires the completed evaluation report and its externally supplied SHA-256, with the exact case-by-arm membership from the prediction seal. It attempts two distinct physical final `asof` selections per case (up to twenty total), with deterministic category/provider/study spread and no provider-score ranking. Physical duplicates are excluded across the complete audit. It uses the original frozen bundle, case pack, catalog copy, archived source receipts and existing SourceAudit/normalization checks. The check reads the original Parquet row using the complete explicit normalization projection, verifies the normalized statement and metrics, and retains context, missingness and mapping lineage. If fewer selections are available, actual coverage is reported without source substitution. This technical audit cannot supply new AI Q1 answers or upgrade scientific truth.

Regression coverage includes an inference-free six-arm sealed integration and invented receipt/Parquet-backed post-seal auditing. Tests reject incomplete or duplicated case/arm sets, paths outside the bound arm, a running-server boundary, source/reference/context drift, changed archived receipts or raw bytes, mismatched evaluated final selections, and case/snapshot/raw/receipt/reference mutation after admission or after the exact parsed answer read. All output directories are exclusive, and failed attempts retain a failure record and output seal.
