# Independent strategic review of the next R09 step

31 October 2026 UTC. **Recommendation: retain the accepted Source5/C79 work, stop expanding the private native-proof stack as the immediate critical path, and close the bounded R09 capability/feasibility account before returning to the scientific prerequisites.** A same-Core CPython native bank is a legitimate optional systems project. The reviewed evidence does not establish that completing it, positive held leases and physical14 is necessary for the project's smallest interpretable T6 comparison or H5 claim.

This is a priority review, not permission for a new model experiment or a reinterpretation of old failures. The full Opus review, controlling recovery plan, phase decision, R07 disposition, current Source5 assessment, latest observed bridge draft, packaged interfaces and retained acceptance metadata were inspected. No subject code, model, compiler, experiment, tokenizer, original biological data, protected outcome or gold answer was executed or read. Current documentation was not edited. Exact input pins and structured findings are in [the companion JSON](R09-STRATEGIC-PRIORITY-REVIEW-v2.json).

## Why the next-step priority should change

Opus identified the binding scientific issues as model capability, independent human references and qualified clinical labels, and warned that governance and repeated infrastructure repairs were overtaking useful iteration. Its proposed critical path leads through a bounded capability control and H5, not through a new native file-I/O authority subsystem. The recovery plan deliberately narrows this further: only shared infrastructure needed by the next consumer should be extracted, R09 is the **smallest interpretable comparison**, and development work should use proportional review. [Opus review](../../../docs/Opus_20261026T050236Z_review.md), lines 18–28, 153–178, 209–222 and 379–387; [recovery plan](../../Project%20Recovery%20and%20Evaluation%20Plan%202026-10-26.md), lines 139–157, 226–236, 262–271 and 379–385.

The same recovery plan says to redesign a task that cannot be represented simply **before another full controller stack**, and not to continue an unbounded converter/grammar search. R07's terminal disposition explicitly stops that native version and twenty-case expansion while retaining the extractive/provenance framework. These stop conditions remain relevant when each successive systems component has a locally valid test. A growing chain of native-cell, wrapper, exception, GC, first-clock, actor, directory, physical-output and child-lifetime obligations does not become a scientific prerequisite merely because it has been written into a later agent-authored next-step paragraph. [Recovery plan](../../Project%20Recovery%20and%20Evaluation%20Plan%202026-10-26.md), lines 213–224 and 238–249; [R07 disposition](../recovery-step7-20261026/DISPOSITION.md), lines 11–22 and 65–77.

The newest bridge proposal would change entry/Core/store/registration/committed-fact/bootstrap/snapshot behavior, introduce three private GC-managed extension types, build fake and subsequently real-linked images, and qualify C exception triples, exports, generation retirement and retained observations. Those are substantive systems changes with their own defect surface. Even a successful implementation would not supply a useful model answer, a fresh source-complete case, a human reference, an efficacy label or power for H5/H1. The draft itself explicitly withholds those claims. [Observed bridge V2 draft](../recovery-step9-native-bank-bridge-20261030/NATIVE-BANK-TICKET-BRIDGE-PROPOSAL-v2.md), sections 1, 4 and 6–9. The file was being authored during review; its pinned observed bytes are not a design-clear or implementation authorization.

The repository at commit `ceab32fd4f6ee7529fc3ed254646e104a465d8bf` contains 6,002 tracked review-asset paths; 3,872 have names in native/preflight/Unicode/entry-route families. This is a reproducible path-count observation, not measured wasted time, a code-quality score or a count of independent experiments. It nevertheless makes Opus's code-accumulation and governance warning materially relevant. Preserving this work is sensible; automatically extending it is not justified by the present scientific bottleneck.

A generic-JSON plus semantic validator could be considered under a separately named contract, rather than proving native grammar as an H5 endpoint; it cannot inherit v3/native-conformance acceptance or revive old cells. 5. **Stop at the actual external scientific gate.** If independent references or an approved useful capability condition remain unavailable after this bounded preparation, report the exact blocker and retain the useful extractive/provenance framework plus negative feasibility result. Do not start unrelated low-level work to keep the session busy. H5 remains open; the project is not complete. Resume only when new evidence or a concrete authorized scope change makes the next scientific step feasible.

## Mandatory stops that survive reprioritization

Stop dependent work for missing source identity/lineage, evaluator contamination, unknown authority, failed archive verification, unavailable execution binding, budget overrun or unknown attempt state. Preserve exact first failures, original source/response bytes, measured and conservative accounting, and pending outputs; never auto-repeat an unknown/potentially billed call. Do not enlarge budgets, silently clip source context, infer biological absence from collection gaps, fabricate human consensus, issue a probability from unvalidated features, or transform old development material into a fresh locked test. If no useful development answer is established, do not expand to twenty cases. If review workload/domain coverage is infeasible, narrow the scientific claim before locking H5. These are the recovery plan's constraints, not optional costs of the native bank.

**Disposition:** a positive C79 or Source5 component result is worth retaining, but a further native proof stack is not currently the highest-value next step. The next major result should resolve or explicitly expose the scientific feasibility decision that Opus identified. If that result is “human/capability prerequisites unavailable,” an honest blocker is progress; more infrastructure cannot substitute for it.
