# Independent preparation-contract review

2026-10-26. Read-only review of CONTRACT-v1, its implementation/closure notes, and existing compiler, admission, ingestion and source-audit code. No runtime changes, source admission, protected outcome/reference reads, tokenizer invocation or generation were performed by this review.

Disposition: the finite preparation slice is implementable after incorporating the conditions below. Human submissions do not block this engineering work. They remain necessary for the independent scientific evaluation, which this slice cannot complete. Tokenization and source preparation may be implemented separately, but a real-input preparation receipt requires both to pass.

## Required source boundary

1. **Add original-row replay explicitly.** `chrono.admit_snapshot` hashes the exact decoded packet and invokes `InputGraph.verify` for complete parent bytes/receipts. Those checks do not compare a normalized observation with its physical Parquet row. The old R07 source-gate reconstruction is therefore useful authority/pin evidence, not a waiver for this new check. `tools/science/reference_packets.py:audit_observation` and `_mappings` contain relevant source-only comparisons; extract their comparisons without importing the reference-selection, answer, adjudication or output workflows.
2. **Compare the whole supported normalization result.** Existing audit logic checks identity, projection digest, statement, metrics, contexts, study/cohort, dates, missingness and lineage, but it is not itself a complete equality reconstruction of every Observation field. For example, it does not explicitly reconstruct every method note/parameter or the `source_kind` field. A supported method2.2 adapter should construct the expected complete Observation from the original projected row, verified mapping rows and source availability, then compare canonical fields with the admitted record. Unknown methods/products must fail unsupported. Do not interpret that as a requirement to rewrite ingestion globally.
3. **Use the correct fingerprint domain.** `EvidenceStore.admitted_fingerprints[id]` hashes the complete `GroundedObservation(observation,citation)`, not only `scientific_record`. Preserve this distinction when checking the request's `admitted_sha256`; separately bind the exact source_ref/citation and encoded observation. A self-consistent source-scope hash in `diagnostic_codec` is structural binding, not admission.
4. **Reject unsupported features before compiling.** Legacy `bounded_interpretation.prepare_input` assigns `observation['features']={}`. The new route must reject an originally nonempty feature mapping rather than delete it. Preserve all other original fields, nulls, context, articles, ordering, instructions, coverage and bounds. Compare the real request against 14b735ef940bde56c04ea964cf145f3f7d1e343b2fe1e35de157cc8a5af2d61a only after independent reconstruction; mismatches terminate without normalization/substitution.
5. **Anchor mappings and scope as inputs.** Add pinned identifier-validation data and approved case definition/explicit scope to the source authority. Replay target/disease rows plus HGNC Approved status/symbol/Ensembl identity, matching namespace hashes, mapping refs and disease name used in the statement. The case supplies intended action/modality/tissue; source data do not establish therapeutic efficacy. A caller-created catalog, locator, receipt hash or case is not its own external authority.

Minimal installed closure: contracts/serde/provenance/chrono for unchanged admission; current atomic/journal/study proofs and path guards for durable authority; a small compiler preserving the legacy request literals/category order/subset coverage; packaged `diagnostic_codec.bind_question`; a versioned method2.2 selected-row reconstruction using ingest's pinned EVIDENCE_COLUMNS, TYPE_CATEGORIES, `_json_value`, `_publication` and normalization version. Use optional pinned pyarrow21 only behind the existing ingestion-extra gate. Do not import tools, execute archived compiler bytes, invoke build_snapshot, or load reference/gold workflows. Keep all additional proof data outside the original prompt request.

Before any kernel IO, prevalidate every declared graph/artifact/receipt path against externally approved roots and prohibited roles/paths. Full eligible snapshot admission can authenticate more rows than the explicit selection; selected-row semantic replay must cover every source actually offered to the prompt. Report these two coverage denominators separately. Bounded Arrow batches must preserve row-group and absolute-in-group offsets and project allowed columns before Python conversion. Authenticate bytes used for replay, not merely a prior path read: use stable handles/locks or immutable authenticated copies. Rehashing after a different unprotected read is detection, not proof of which bytes were interpreted.

## Tokenizer, cache and deadline conditions

- The retained measurement's RESULT hash matches CONTRACT-v1, and it records 24 measurements, six exact old controls and real six-stage reservations 28,241. This establishes a finite feasibility observation, not universal tokenizer equivalence. The aligned two-claim guide changes prompt bytes and requires fresh counts. Old byte-based StudySession capacity remains untouched.
- Root's retained Windows probe supplies practical support for opening the approved tokenizer under held read-only sharing locks. Lock all approved file handles before hashing, keep them through child completion and final checks, and fail if any handle/identity cannot be secured. Maintain directory rename guards and inventory checks. The probe does not establish exclusion of directory additions, adversarial same-user/OS actions or arbitrary DLL loader search paths. Pin/limit the approved working directory and loader/environment boundary; state remaining OS trust explicitly. A compatible lock is not a sandbox or universal no-network proof.
- Cache authority must be an external expected receipt hash tied to a trusted preparation event or supplied approved anchor registry. Never bootstrap that anchor from the cache's own receipt, index or self-authored journal. Bind prompt bytes, exact preprocessing/argv, complete asset authority, implementation/parser version and finalized payload separately. A valid cache hit must not launch a child; a bad/unanchored hit fails without an implicit retry. Raw count/ID agreement alone is forgeable and is meaningful only under that anchored provenance.
- Use one absolute monotonic preparation deadline from before source/asset verification through all six quotes. Check it around long hash/Arrow batches as well as child IO; a final elapsed check cannot enforce the stated bound. Concurrently drain bounded stdout/stderr, bound stdin transmission, save the owned child immediately and preserve primary interruption/errors through cleanup. No server semantics are needed for a one-shot tokenizer.
- The six full-history strings are a measured planning envelope. Calling the largest source-ID list a worst-case token count needs care: BPE counts are not mathematically monotonic in string length. This prep-only receipt may certify those exact six hypothetical payloads. It must not promise all future shorter/different histories fit without separate actual-payload quotation or a justified conservative bound. No runtime generation policy is activated here.

## Finite acceptance probes

Use source-only invented fixtures to reject a resealed normalized statement/metric/article ID, changed raw locator, truncated projection, altered missingness/context, wrong mapping/namespace, nonempty features, changed source_kind/method metadata, and an evaluator/future ancestor before protected reads. Positive fixtures must preserve nulls and exact complete request equality. Check correct GroundedObservation fingerprints, not synthetic-fixture hash conventions.

Tokenization tests should reject an arbitrary executable, additional DLL, changed shard, unanchored cache, changed prompt/schema/spec, malformed/truncated traces, timeout during input/output and cleanup errors that would mask the primary failure. Check no subprocess on offline verification/cache reuse, and deadline expiration during source hashing. Test Unicode/special-token/newline/BOS identity without native generation. Keep the real source-only dry run fixed to the already exposed IL6R input, retain any failure, and make no replacements.

No new data or human response is required to implement these checks. A failed optional-dependency, authority, raw replay, lock, deadline or size check is an explicit technical stop for this finite preparation. Passing them would establish source-bound/tokenizer-bound preparation only; R09 real comparative interpretation, independent review and scientific acceptance remain open.
