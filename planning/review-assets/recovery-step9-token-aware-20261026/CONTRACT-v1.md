## Asset authority and offline subprocess boundary

The authority is the externally pinned existing acquisition and R05 inventory, not a caller-selected executable hash. Require exact approved tokenizer binary, all three local GGUF shards, the complete runtime DLL directory inventory and any explicitly declared existing loader dependencies. Reject extra/unpinned DLLs, missing files, mismatched bytes/version, unknown executable aliases, symlinks/reparse points, path traversal or roots outside the explicit approved model root. Bind all model/code/normalization settings into the spec. Relocation may map one approved logical root to a physical directory; it cannot select different bytes or broaden the authority. System Windows DLLs are OS trust dependencies, recorded as a limitation rather than claimed receipted model assets.

Freshly hash asset bytes and stable identity before first execution in a preparation; recheck inventory/identity at every use and full critical hashes after completion. Any detected concurrent modification fails closed; do not claim ordinary file-stat checks defeat adversarial same-identity mutation. File sharing/locking protections must be specified for Windows so a child cannot consume mutated GGUF/DLL bytes between checks; inability to establish the accepted stable-read boundary is a real technical gate, not permission to execute anyway.

The only argv is the dedicated tokenizer executable, offline mode, exact first shard, no-escape, no-BOS, binary stdin, IDs and show-count. Special-token parsing uses the pinned documented default enabled. No model-download arguments, arbitrary flags, env model overrides, shell, server, HTTP, GPU inference or generation binary. Scrub LLAMA_/HF_/HUGGING_FACE overrides; use explicit offline mode and approved executable working directory. Do not retain environment secrets. No network adapter is introduced.

Use a caller-owned child with exact argv/identity recorded before feeding stdin. Bound stdout and stderr to2MiB each, concurrently drain both to avoid deadlocks, stream exact input bytes without appending a newline, enforce a monotonic total deadline, and kill/wait only that owned child on timeout, overflow or interruption. Preserve primary errors and readable partial raw streams/failure records; no automatic retry or adoption of an existing process. Reuse the current owned-process mechanisms where compatible; add only the missing bounded pipe helper rather than a second process registry. Package/runtime remains dependency-free; no tokenizers package, DLL download or model acquisition is required.

## Token trace, cache and replay

Retain exact prompt bytes, canonical payload hash, stdin hash, stdout/stderr bytes, exit status, process identity/argv, timing, spec/asset authority, implementation/resource proof, ID-list parser version, and count provenance. Exactly one token-ID list and one integer reported count must parse; both must agree; all IDs are nonnegative integers and streams must be complete with exit0. Bound parsed count and IDs to the approved model/tokenizer vocabulary if vocabulary bounds are independently pinned. Never repair token output or accept a self-authored count field as evidence. IDs may be replayed and counted offline; replay must never launch tokenizer, model, network or server automatically.

Cache key = canonical hash of exact prompt bytes hash, exact argv/preprocessing spec hash, full model+DLL/executable authority hash, tokenizer/parser implementation hash and normalization version. Payload-specific binding remains outside the prompt and links each quote to the exact final payload. Identical prompt tokenization can be reused only under this same immutable key, while payload/schema/question/source bindings remain independently checked. Cache files use exclusive no-overwrite publication and external receipt anchors from trusted preparation events; an attacker-controlled self-consistent cache directory is not authority. Verify all inventory hashes, raw ID/count agreement, code/resource authority, prompt/spec bindings and receipt anchor before reuse; wrong or unanchored cache is rejected without automatic recomputation. A trusted execution receipt establishes provenance, not cryptographic proof that the CPU executed correctly; six empirical parity controls have finite scope.

## Proposed acceptance tests and finite stop

Before implementation, peer review must resolve selected compiler/API dependencies, stable asset locking and cache authority. Regression-first tests should cover: arbitrary executable/extra DLL/changed shard; UTF8Unicode/null/special-token/newline/BOS identity; late deadline and stream overflow/interruption cleanup; malformed/truncated or forged self-count traces; wrong external anchor and prompt/spec/cache key; cache read-only replay without subprocess; field-complete request reconstruction, case namespace mismatch, future/evaluator ancestor, receipt and root escape; aligned two/three claim limits; six-stage aggregate32k/context/output accounting; absence of generation/HTTP and no old-policy mutation. Tests use fake children and invented source graphs; optional accepted-local-asset tokenization is explicit qualification, not default test inference.

Dry-run completion requires full source-inclusive preparation, exact request equality where pinned, six aligned new payloads with trusted quotes, and an anchored reproducible preflight receipt. Failure preserves partial evidence and ends the finite experiment. No native run, historical cohort, new data, independent human gold or scientific conclusion follows. R07 generation stop and the human review protocol remain in force for later interpretation.
