Prospective clarification of [revision 1](CONTRACT-v1.md), which remains preserved.
Runtime implementation still requires independent review and the root's recorded
acceptance. The default budget, no-generation boundary and original R07 stop remain.

The [compiler dependency audit](SOURCE-COMPILER-CLOSURE-v1.md) fixes the packaging
boundary: extract only the pure request compilation and source-row comparisons;
use current kernel admission and packaged question binding. Do not import mutable
repository tools, source-reference workflows, gold selection or outcome logic.

The first real source profile is explicitly Open Targets 25.09 normalization 2.2
with its pinned HGNC 2026-10-10 mapping reference. Replay selected original evidence
rows and target/disease/HGNC mapping rows under the existing optional
`pyarrow==21.0.0` gate. Full file hashes and lineage are necessary but do not prove
row transformation. Compare complete projection, row identity, source metrics,
statement, context, publication and missingness; preserve physical locators. Reject
nonempty selected features rather than silently clearing them. Namespace versions
and original source citations must match. `admitted_sha256` fingerprints the whole
grounded observation, including citation, rather than just its scientific record.

Keep fresh input authority outside the request. Anchor case, snapshot, catalog,
identifier-validation manifest, explicit selection, release/recipe and all admitted
parent/receipt bytes before reads. The familiar exposed request hash is only an
output parity check. Unsupported source recipes or missing optional dependencies
fail explicitly. None earns real-source status through a saved prompt or size pass.

The [finite Windows probe](LOCK-PROBE-RESULT.json) establishes compatibility for
held read handles on the 34 approved assets. `CreateFileW` read access with
`FILE_SHARE_READ` denies ordinary write/delete access until closure. Hold those
handles through fresh hashing, the one-shot child and post-hashing. Hold directory
handles without delete sharing to prevent rename of the approved asset paths.
Do not claim this forbids all creation of new directory children or defeats an
adversarial same-user/privileged actor. Reject extra DLLs at both inventory checks;
trust the OS loader and system DLLs explicitly. No weaker-lock fallback is allowed.
The probe used one already-measured prompt, zero generation and no E: writes.

Token receipts require external anchors and trusted current code/resource proofs.
Replay is read-only and never launches a process. Caching cannot turn an arbitrary
self-consistent directory into authority. The implementation may first expose
uncached quotation plus anchored read-only replay; any cache reuse must call that
same full verification boundary. Source preparation and tokenizer quotations remain
separate capabilities until a final preflight binds their exact source, question,
guide, schema and payload hashes.

Independent review adds two acceptance requirements. First, reproduce and compare
the whole supported method-2.2 Observation, including source kind and all method
metadata; the earlier fieldwise audit is useful but insufficient by itself.
Second, a longest source-ID history is not necessarily the largest BPE token count.
The six dry-run payloads certify only those exact hypothetical histories. Any
future execution must freshly quote the actual verified history before dispatch;
this preparation cannot certify all possible histories or authorize execution.

The machine-readable [revision 2](CONTRACT-v2.json) records these boundaries.
Neither revision authorizes native execution, new source acquisition or scientific
acceptance. All whole-R09 and human gates stay open.
