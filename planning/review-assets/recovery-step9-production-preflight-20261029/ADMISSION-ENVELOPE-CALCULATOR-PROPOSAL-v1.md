# Role-aware admission-envelope calculator — design only

One pure `analyze_admission(metadata, *, check)` calculation validates explicit bounded declarations and returns an immutable report. It does not discover, open or qualify an actual roster. Captured software/metadata remain distinct from hash-only bulk, which provides no importable or checker bytes and is not supported by the current V3 runtime.

The closed schema and formulas cover exact per-file reads/calls/events, captured assemblies plus immutable copies, full query witnesses and call records, declared state/index terms, journal retention/join workspace, all five packet kinds and a prospective full canonical report. Representation coefficients are strictly positive declared logical payload assumptions, not measured Python/native memory. Explicit unknowns prevent a positive envelope result; malformed data refuses; known exceedances remain visible even when other dimensions are unknown.

Packets use canonical ordinal file IDs, longest boolean sizing rows and full declared digest arrays. Caller packet limits are compared with that declared bound; the current8192 reference is not replaced or silently lifted. No physical report transport or new runtime output kind is selected. Input metadata is detached before semantic callbacks; cancellation exceptions preserve identity.

[Exact request/result schema, domains, ordering and formulas](ADMISSION-ENVELOPE-CALCULATOR-PROPOSAL-v1.json) are for finite independent review and<=30 pre-code metadata vectors only. Existing N4/runtime caps, failed actual profile and original verification timeout remain unchanged. No calculator or streaming implementation is authorized by this proposal.
