## Token-to-piece: implementation observations, not an imported contract

The public declaration documents no null terminator, `lstrip` and `special`, but **does not document negative required-size returns, overflow or null-buffer sizing** (H:1287–1298). The adjacent detokenize return documentation (H:1300–1313) is a different API and is not used to establish this function's contract. The public wrapper delegates without validation or exception handling (V:4677–4685), through V:4413–4415 to the implementation below.

| Case | Exact observed implementation and limit |
|---|---|
| Ordinary copy/sizing | `_try_copy` rejects original piece size **greater than or equal to** `INT32_MAX` with `GGML_ABORT`, before stripping. It removes up to `lstrip` leading ASCII space bytes, returns negative post-strip size if `length < size`, and otherwise copies exactly `size` bytes with `memcpy` and returns that size (V:3833–3847). No terminator is written. |
| Insufficient capacity | The common copy branch returns negative required bytes **without copying any bytes**. It is not partial output or a generic error code. `-1` can simply mean a one-byte piece needs capacity (V:3842–3846; also PLaMo byte branch V:3924–3932). |
| Zero-size result | `special=false` returns zero immediately for UNKNOWN or CONTROL attributes (V:3825–3829). An empty piece can reach `memcpy(..., 0)` and return zero (V:3833–3846). Zero therefore does not uniquely mean failure or suppression. Unsupported attributes can also fall through to zero when constructing an uncached piece (V:3864–3879, 3946). |
| Zero capacity | With a valid non-null destination and `length=0`, a nonempty common-branch piece returns its negative size; an empty one reaches the zero-size `memcpy`. There is **no general null-destination check**, so a null pointer with zero capacity is not qualified as a portable sizing call (V:3833–3846). |
| Nulls / invalid IDs | No null vocabulary/buffer protection appears in the public wrappers. Attribute lookup happens before the later range branch and calls `id_to_token.at(id)` after an assertion that vocabulary type is not NONE (V:3826, 3357–3359). Cache lookup also uses `.at(token)` (V:3853–3855). Invalid IDs are not safely represented by an ordinary negative size; an exception/assertion/invalid access can occur. |
| Negative capacity | Do not pass it. The uncached RWKV branch casts `length` to `size_t` in its capacity check and then copies; this differs from the signed common helper (V:3903–3912). No uniform negative-capacity safety guarantee follows. |
| Overflow sentinel | The common helper aborts for oversized original pieces; it does **not** return `INT32_MIN`. The uncached RWKV path uses casts to `int` without the helper's wide-size guard (V:3903–3912). Do not advertise tokenize's `INT32_MIN` contract for token-to-piece. A caller should nevertheless classify any unexpected sentinel/size as an error before negating or allocating. |
| Cache behavior | Loading builds one piece per token with `special=true`, then swaps in that cache (V:3194–3206). The cache-building helper tries a real string buffer and retries once on a negative size (V:3519–3533). Once nonempty, public token-to-piece uses the common helper for cached pieces (V:3849–3856). Private grammar piece lookup returns the cached string directly (V:3949–3951, 4409–4410). This is exact-revision behavior, not proof of installed-DLL equivalence or bounded initialization cost. |

`special=false` suppresses UNKNOWN/CONTROL only in this entry path; USER_DEFINED text is rendered (V:3825–3829, 3867–3868, 3884–3885). `lstrip` in the common helper removes ASCII `' '` only, up to its positive count. Uncached RWKV and the direct PLaMo byte return bypass that helper (V:3903–3932); no universal lstrip behavior across uninitialized/cache-building branches is claimed. For a later byte-preserving gate, fix `lstrip=0` and `special=true`: grammar filtering and accepting both read the same special-rendering cache (G:1382, 1405; V:3198–3206).

## Tokenization count and byte preservation

The public contract returns a nonnegative count, negative required token count, or `INT32_MIN` on overflow; its flags are distinct (H:1270–1285). The implementation constructs `std::string(text, text_len)` and performs complete vector tokenization **before** checking output capacity. If result size is **greater than or equal to** `INT32_MAX`, it returns `INT32_MIN`. If capacity is too small it returns negative count without writing output; otherwise it writes that many tokens and returns count (V:4377–4399). The wrapper adds no guards (V:4666–4675).

Reject negative byte lengths/capacities and out-of-policy values before calling; provide live non-null input and output storage even for empty inputs/sizing attempts. A null token pointer with capacity zero is not a documented general contract. This exact implementation avoids token-buffer writes when the required count exceeds zero capacity and performs no loop iterations for zero results, but the recommended procedure avoids depending on null arguments. Check `INT32_MIN` **before** negation and widen signed results before absolute-size arithmetic. The capacity bound limits the caller's output buffer, not the native tokenizer's temporary vector or internal work.

Use `add_special=false` and `parse_special=false`, but require byte equality rather than infer it from those flags:

- `add_special` controls model-dependent insertion; SPM/BPE/WPM paths add different configured tokens (V:3588–3591, 3625–3627, 3645–3647, 3665–3667, 3672–3675, 3692–3695). It does not disable all tokenizer transformations. SPM can prefix a space even with `add_special=false` because `is_prev_special` begins true and `add_space_prefix` is independent (V:3586, 3598–3608).
- `parse_special=false` skips CONTROL and UNKNOWN during special partitioning, but **USER_DEFINED tokens are still prepartitioned** (V:3401–3413; special-cache members V:3177–3188). Their LSTRIP/RSTRIP attributes can discard surrounding whitespace during partitioning (V:3450–3453, 3475–3479). This attribute behavior is separate from token-to-piece's numeric `lstrip` argument.
- WordPiece preprocesses whitespace, drops NUL/replacement/control codepoints, and can strip accents/lowercase (V:869–903). Unigram has optional NFC and additional normalization/space merging paths (V:1018–1037, 1126–1169). The TEST tokenizer deliberately hashes five-byte chunks and renders token IDs as hex, not input recovery (V:3780–3815, 3914–3917). These are concrete counterexamples to a vocabulary-independent byte-roundtrip guarantee.
- BPE piece rendering delegates to Unicode byte conversion; its fallback can emit `[UNK_BYTE_0x...]` text on a caught conversion lookup failure (V:3544–3561, 3887–3895). Definitions of the delegated Unicode helpers are not established here. Do not normalize, strip a prefix, substitute replacement characters or switch flags after a mismatch.

Compare returned pieces as exact counted byte spans against the original input, with checked total length. Do not use C-string length, console display, newline conversion, JSON reserialization, per-piece UTF-8 repair, or detokenize cleanup as that oracle. Pieces may end within a UTF-8 sequence.

## EOG set and grammar lifecycle

`llama_vocab_is_eog` delegates to membership in `special_eog_ids` except the null-token sentinel (V:3330–3332, 4476–4478). The set is populated from configured FIM pad/rep/sep IDs, token spellings, and EOS/EOT/EOM IDs (V:3010–3056, 3085–3099), with later removals for model-specific `<|end|>` and `</s>` conditions (V:3101–3173). EOS/EOT getters return individual configured IDs (V:4231–4237, 4488–4494); they are not the entire set. No concrete loaded-vocabulary IDs or count is established by this source review.

For the later gate, validate a positive, capped `llama_vocab_n_tokens` count and enumerate **every integer ID in `[0, n_vocab)`** with `llama_vocab_is_eog`. The public count delegates via an unsigned internal size cast (V:4121–4123, 4451–4453); enforce an independent reasonable cap rather than rely on count being allocation-safe. Store the complete enumerated set; treat an empty or over-cap set as an explicit qualification failure. Input document token IDs must be checked against that EOG set: grammar applies EOG as a termination event **without consuming its rendered piece bytes** (G:1382–1392). A matching byte roundtrip is insufficient if EOG appears inside the document token stream. Keep document EOG exclusion and end-of-document EOG probes separate.

The public grammar initializer is non-lazy (S:2831–2835). Null or empty grammar text deliberately creates a non-null sampler with `grammar=nullptr` (S:2783–2828); grammar callbacks then do nothing (S:2679–2690). Generic public apply/accept also return quietly for null samplers (S:372–389). Require nonempty, non-NUL grammar bytes, explicit live root `root`, successful initialization, and fixed known positive/negative controls. Non-null sampler and exit zero do not demonstrate enforcement. String grammar parse failure, missing root and detected left recursion return null (G:1224–1237, 1255–1266).

Grammar apply receives a const grammar, tests **every supplied candidate**, and writes rejected candidate logits to `-INFINITY` without advancing grammar stacks (G:1359–1400). There is no finite-logit guard in its candidate loop. A finite starting logit such as `0.0f` is a gate precondition that makes rejection observable, not behavior the implementation enforces. The prior public C API review's phrase “examines candidates with finite initial logits” must be read with that correction.

After an allowed ordinary token, accept consumes cached piece codepoints/token rules, replaces stacks and stores partial UTF-8 state; inconsistent input can throw when no stack survives (G:1476–1527). Apply must precede accept; never accept a rejected ordinary token. EOG apply is allowed when **any** grammar stack is empty, otherwise it receives `-INFINITY` (G:1366–1387). EOG accept returns if an empty stack exists and **calls `GGML_ABORT` otherwise** (G:1449–1455). Completion probing needs only apply; do not accept EOG at all. Filter each EOG independently after full input and at selected incomplete prefixes; apply does not mutate recognition state, so the probes can share the current document sampler.

## Partial UTF-8 and completion limits

The grammar stores a partial value and remaining-byte count (`-1` means invalid), carried across token pieces (GH:52–55, 136–137; G:34–91, 1523–1524). Candidate rejection checks whether an incomplete sequence can match the next character range and rejects partial bytes at an already-empty stack (G:792–840, 1069–1105). Individual token pieces therefore must not be independently decoded or repaired.

This is not a complete strict UTF-8 validator: decoding starts at `src.c_str()` and stops at a zero byte (G:38, 47, 64, 80). Apply filters a non-EOG piece whose **first byte** is zero (G:1388–1389), but it does not explicitly scan the rest of the piece for NUL. A nonempty token piece with an **internal NUL** could therefore have a suffix invisible to that decoder. Whether the future approved vocabulary contains any such pieces is an **untested actual-vocabulary property**; this review makes no claim that it does. The bounded future byte-piece checks should record leading/internal NUL positions and raw byte lengths before any decoding or display, without a runtime vocabulary scan now. Continuing a previous partial sequence checks continuation-byte form (G:47–56), while the loop for a newly started sequence masks following bytes without the same check (G:79–83). EOG apply/accept's empty-stack tests have **no explicit `partial_utf8.n_remain` test** (G:1366–1387, 1449–1455). Do not strengthen this into a guarantee that all malformed UTF-8, embedded NUL suffixes, or partial-byte prefixes are rejected. Exact outcomes depend on token boundaries and grammar alternatives and need future conformance tests.

The later document protocol should require a separate strict whole-input UTF-8 check and reject raw NUL bytes before native recognition; an escaped JSON `\u0000` is ASCII input and is different. Preserve original bytes and hash while checking, and classify prevalidation failures separately from native rejection. In particular, independent UTF-8/NUL prechecks, token-byte roundtrip checks and document EOG-stream exclusion are **harness-layer dispositions**, not native rejection of those documents. The frozen corpus remains unchanged; no failing case is repaired or replaced. Probe token-boundary prefixes that split multibyte characters, including a prefix containing complete earlier characters plus an incomplete next codepoint; record actual EOG results without assuming them from character EOF semantics.

## Bounded proposed admission procedure

This is review material for a later finite protocol, **not authorization to run it**. Freeze numeric caps for document bytes `B`, tokens `K`, per-piece bytes `P`, vocabulary count `Vmax`, EOG count `Emax`, grammar bytes, cases, prefix probes, wall time and process memory before any attempt. Require each relevant cap to be positive and below `INT32_MAX`; require checked multiplication for token storage and checked sums for byte totals/call budgets. The caps must be finite approved policy values; no undocumented automatic expansion is allowed.

1. Preserve exact document bytes; check `length <= B`, strict UTF-8 and absence of raw NUL. Keep non-null input storage even for zero length. No repair/normalization/reserialization. The separate loader/header/resource review must qualify the vocabulary handle and DLL before this procedure is runnable; do not create an inference context.
2. Tokenize with fixed `add_special=false`, `parse_special=false` into **one live token slot, capacity 1**. Check `INT32_MIN` first. If nonnegative, require count in `[0,1]`; retain those IDs. If negative, compute required count in checked wide arithmetic, require `1 < required <= K`, allocate exactly that many slots, and retry **once** with unchanged input/flags. Require the retry to return exactly the first required count. No repeated growth loop. Bounds: at most two tokenization calls per document. A native allocation/time exception/crash remains a separate process failure, not document rejection.
3. Validate every returned ID against `[0,n_vocab)` and reject/document any EOG among input tokens before admitting the document. For each ID call token-to-piece using a **live one-byte buffer, capacity 1, `lstrip=0`, `special=true`**. A nonnegative result must be in `[0,1]`. On a negative result, reject `INT32_MIN`/unexpected values before negation, compute required bytes widely, require `1 < required <= P`, and retry once into exactly that many live bytes. Require exact size agreement. Do not call with null/negative-capacity buffers. Bounds: at most `2*K` piece calls; buffers have explicit byte counts and need no terminator.
4. Incrementally compare each counted piece against the corresponding original byte slice, with checked offsets and `total <= B`; require final concatenated length and bytes equal the original. A zero-piece result or any mismatch must be recorded; never change flags or discard a prefix to force equality. Whole-input UTF-8 validation occurs on the original/full concatenation, not each piece.
5. Initialize a fresh standalone non-lazy grammar sampler for each document after validating frozen grammar/root bytes; require success. For each actual input token, give a singleton public candidate array `{id, logit=0.0f, p=0.0f}`, `size=1`, `selected=-1`, `sorted=false`. Apply; require expected candidate identity/shape and classify `-INFINITY` as rejection, unchanged finite `0.0f` as admission, and any unexpected result as a protocol error. Record the first rejection. Accept only an admitted non-EOG input token, once, in order. No sampler selection, encode or decode call is needed.
6. With the complete enumerated EOG set, apply each ID with a new finite singleton candidate at the end of all document tokens and at a finite list of prefix controls. Record a result for **every** EOG ID. Never accept any EOG. For a complete positive control expect all enumerated EOG IDs admitted by the shared EOG branch; for specified incomplete controls record expected rejection and any mismatch. Prefix probes do not advance state. A singleton gate does not qualify a full-vocabulary production mask or its cost.
7. Emit structured distinct results for prevalidation, token sizing/limits, roundtrip, first-token rejection, all EOG admissions, unexpected native failure, and resource termination; include source/DLL/grammar/document identities and fixed flags/caps. Free every document sampler before releasing its borrowed vocabulary/model owner and DLL. This procedure cannot bound native cache construction or full-tokenization temporary allocations merely by bounding output buffers (V:3194–3208, 4384–4399); the separately reviewed process/resource boundary remains required.

## Tokenizer CLI is contextual evidence only

The tool reads file input in binary but conditionally processes escapes (T:117–138), conditionally processes stdin escapes (T:163–177), derives `add_bos` from model configuration and CLI flags, and delegates to `common_tokenize` (T:180–185). Defaults and wrapper behavior are unestablished here. It loads vocabulary-only **and then creates a context** (T:142–160), so copying this tool's lifecycle would violate the proposed no-context gate. Human output uses `common_token_to_piece(...).c_str()` (T:191–205); its display helper uses C-string lengths/printf and Windows invalid-UTF-8 hex rendering (T:41–91). Displayed text is not an exact counted-byte oracle, and IDs/count output alone is not a roundtrip test.
