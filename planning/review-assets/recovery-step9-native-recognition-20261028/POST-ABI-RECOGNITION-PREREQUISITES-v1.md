## Current prerequisites and two necessary changes

The [source qualification](SOURCE-QUALIFICATION.json) retains the fixed-commit public declarations and loader/CPU/token reviews. The [CPU review](EXPLICIT-CPU-REVIEW.md) supports one explicit pinned CPU registration followed by the public initializer, conditional on exact singleton registry/device checks before and after. The [loader review](DELEGATED-LOADER-REVIEW.md) supports skipping explicit tensor-blob reads on the selected vocabulary-only/no-allocation path. Neither source-to-release build equivalence nor initializer side effects have been proved.

Two existing guards deliberately prevent simply switching to recognition:

1. The compiled [pin header](../../../data/cache/r09-trusted-platform-bridge-preparation-v2-20261029T024601Z/recognizer_runtime_pins.hpp) has `R09_RECOGNITION_ENABLED=false`, an empty expected-version string and an empty pack pin. A new separately reviewed header/build must bind the accepted ABI version, the exact verified pack, the CPU and three ordered shard descriptors. The current ABI executable and receipt stay unchanged.
2. The [trusted-platform contract](TRUSTED-SYSTEM32-MODULE-POLICY-v1.json) is **ABI-only and admits core4**. The current child sets `runtime.recognition=true` and loads the CPU, but its shared module classifier still rejects protected `ggml-cpu-x64.dll` because only core4 are eligible. See `evaluate_module_report`, lines245–259, and `cpu_before_init`/`recognize`, lines533–556, of the [current child](typed_public_c_recognizer_platform_v1.cpp). A new mode-specific policy must admit the exact leased CPU only in its declared native directory, require it at the appropriate post-load stages, and retain rejection of every other protected provider/wrong directory before the platform rule. Child, pure matcher, parent validator, semantic fingerprint, header/build and protocol must agree. The existing ABI policy and its successful/failed evidence must not be reinterpreted.

Do not add a platform-image pin/authentication project, a second census or discovery fallback. Canonical platform-directory reports remain an explicit host-trust assumption; unknown reported image paths are strings and are never opened or hashed. The native self/core/CPU files remain separately pinned and read-leased at their original approved paths.

## Existing finite bounds are not a recognition protocol yet

These are the present child's constants, not newly authorized limits:

| Document bytes / document tokens / individual piece bytes / grammar bytes | 65,536 each |
| Vocabulary count / EOG count | 262,144 / 64 |

| Total admitted token-work budget, including prefix accounting | 1,000,000 |
| Pack bytes / JSONL total / JSONL row | 20 MiB / 8 MiB / 64 KiB |
| Child cooperative clock | 120,000 ms from process initialization |
| Current **ABI parent** limits | 30-second child including cleanup; 60-second parent; 2-second child cleanup and 5-second parent finalization reserves; 256 MiB process/job commit; one active process |

The ABI parent cannot authorize nine-argument recognition, CPU/model input leaves, the larger recognition event stream or a 120-second child simply by reusing its configuration. Its two API calls and strict five-row parser are a different role. A prospective recognition parent must freeze one exact mode, finite aggregate native-call/output limits and compatible work/cleanup/finalization cutoffs before dispatch. Preserve the qualified detached flags, Job assignment before resume, current-process identity checks, strict job accounting, cap handling and failure seals. No timeout, memory or input cap may expand automatically after failure. The 120-second child tick is cooperative and cannot interrupt an in-flight native call; the external owner remains necessary.

At the current token-work bound, piece calls can reach two million and singleton grammar apply work can exceed one million calls; vocabulary enumeration adds up to262,144 queries. These source-derived ceilings do not prove practical fit. Tokenizer output bounds also do not bound its complete internal temporary tokenization or vocabulary-cache allocations. The reviewed GGUF parser allows very large individual metadata objects. Memory and elapsed measurements are required; a preserved limit failure is an informative result.

## Identity hashing, computation and scientific feasibility

The existing three shard descriptors total **8,988,110,496 bytes (8.371 GiB)**. These numbers were read from the approved header/resource report; this review did **not** open or hash a model/CPU payload. The child currently hashes and read-leases every whole shard before the vocabulary load. A future parent's initial/final original-path checks may add complete passes and must account for them explicitly. Vocabulary-only/no-allocation skips the inspected explicit tensor-blob computation/read path; it does not imply no weight-file I/O, cheap initialization, small metadata/cache memory or no DLL initializer effects.

The [resource audit](RESOURCE-PATH-REVIEW.md) derives sixteen complete selected-model hash passes /133.933 GiB of logical hash input on the accepted six-stage successful framework path. That is not measured physical disk traffic or hashing time. Its retained simulation used295.922/300 seconds without real inference, leaving4.078 seconds; the intervals overlap and do not identify a causal bottleneck. Native qualification is therefore necessary but insufficient for an actual six-stage case fitting the unchanged **300-second** scientific budget.

After conformance, use a separately preregistered bounded profiling/correction gate: record nested hashing/package/source-replay/quote/admission/final-verification spans, actual bytes/calls and live lease identities; preserve canonical receipts and independent source-inclusive replay. Reuse must be trusted current-case in-memory capability under live original-path leases, never a serialized `already_verified` flag or a cross-run cache. Do not rerun for favorable timing, raise the scientific budget implicitly or omit final proof work. Model-backed 0.3.12 integration, fresh-source qualification, human scientific review, locked evaluations and biological validity remain later gates even if this experiment passes.
