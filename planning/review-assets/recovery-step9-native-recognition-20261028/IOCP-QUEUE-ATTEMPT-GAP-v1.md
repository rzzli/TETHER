# Queue-attempt accounting: required before future reuse

The consumed diagnostic v1 (`3e31e728…ce6cc1`, protocol `7325c6b8…f1f605`) remains unchanged. Root executed its single authorized attempt before this late source finding arrived. Root reports nine normally returned queue calls, no API exception or interruption, and a negative counter result. The defect below concerns a latent exception path; it is not evidence that the actual nine-call accounting was wrong, and it does not authorize a rerun or change the negative qualification.

`Observer.drain` appends and counts a queue-call row after `api.queue_call` returns. If that method raises or is interrupted after a native dequeue, the outcome can be unknown while the call and any possibly dequeued packet remain uncounted. A subsequent cleanup drain can then use more than the intended conservative allowance. There is also no durable call-attempt reservation for that unknown return.

The [pure counterexample](check_iocp_queue_attempt_gap_v1.py) extracts the exact own-source `Observer` AST and supplies only fake API/time/journal objects. With 1,023 synthetic prior returned calls, its first fake invocation raises `KeyboardInterrupt`; the source retains 1,023 calls and no call row. A second fake invocation is allowed and becomes recorded call 1,024. Thus two fake invocations consume only one recorded slot. No SDK, worker, native runtime or model is executed by the demonstration. [The retained JSON](IOCP-QUEUE-ATTEMPT-GAP-v1.json) separates this synthetic count from the actual consumed attempt.

A future separately versioned implementation should reserve and count the attempt durably before dispatch; distinguish reserved, dispatch-attempted, returned and unknown outcomes; retain null outputs with reasons on exceptions; and stop observation before further PID interpretation. A possibly dequeued packet on an unknown return needs a conservative packet-budget reservation, separate from measured returned packets. Cleanup may use only the remaining allowance and must still release owned handles. Focused interruption/record-write regressions should precede any reuse. Preserve the consumed source, protocol, peer review and actual result; no fix or accounting waiver is applied in place.
