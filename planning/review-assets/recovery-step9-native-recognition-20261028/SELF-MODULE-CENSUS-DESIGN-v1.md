# One bounded self-module census before any policy change

**Design only.** Root selected one snapshot after the same explicit four-library load stage, with no baseline or causation experiment. This proposal authorizes no implementation, compilation, constructor or native execution. The existing module list and all consumed failures remain unchanged. The companion [candidate contract](SELF-MODULE-CENSUS-CONTRACT-v1.json) records the finite scope.

The latest diagnostic reports `apphelp.dll` at `C:\Windows\SYSTEM32\apphelp.dll`, enumeration index5, with complete31-unit path metadata, System32-directory match=true, listed-basename=false and returned diagnostic publication. This identifies metadata in that run; its image bytes were not opened or authenticated. Earlier failures still have no module identity. Microsoft documents Apphelp.dll as providing compatibility-database functions, and documents the Apphelp/Appfix mechanisms separately. These support a Windows compatibility context, not a conclusion about why this instance loaded, which fixes were active or whether its bytes are trusted. [SdbInitDatabase](https://learn.microsoft.com/en-us/windows/win32/devnotes/sdbinitdatabase), [compatibility database](https://learn.microsoft.com/en-us/windows/win32/devnotes/application-compatibility-database).

## Proposed observation

Use a separately versioned own executable/parent role with exactly `NEW_EXE --module-census EXACT_RUNTIME EXCLUSIVE_CHILD_OUTPUT`. A census branch runs immediately after the existing secure `libomp.dll`, `ggml-base.dll`, `ggml.dll`, `llama.dll` loads and **before** constructing `Api`. It publishes census results and returns unconditionally. It resolves or invokes no public target C functions: version, defaults, registry, backend, CPU, model, vocabulary, tokenizer, grammar, context and server calls remain zero by the explicit source policy. DLL/CRT initialization can nevertheless execute during loading; zero explicit queries is not a zero-initialization-effects claim. [DllMain](https://learn.microsoft.com/en-us/windows/win32/dlls/dllmain).

Take exactly one non-inheritable snapshot with `TH32CS_SNAPMODULE | TH32CS_SNAPMODULE32` and this child's `GetCurrentProcessId()`. Do not use process/thread/heap enumeration or other PIDs. Reserve attempts before each call; retain result/error/timing before interpretation. There is no automatic retry: even `ERROR_BAD_LENGTH` closes this finite observation partial, although Microsoft's general guidance describes retrying it. Close the one owned snapshot independently on every path. This API also excludes data-file-style module loads, so completion is limited to the documented snapshot domain. [CreateToolhelp32Snapshot](https://learn.microsoft.com/en-us/windows/win32/api/tlhelp32/nf-tlhelp32-createtoolhelp32snapshot).

Enumerate at most64 entries. For each, retain the bounded snapshot name and a single `GetModuleFileNameW` result in a32,768-WCHAR buffer, including return length/error, reported code-unit length, explicit prefix/truncation/conversion fields and numeric UTF16 code-unit hex. If the API buffer clips, actual full path length is unknown/null; preserve the return count separately. Reuse name256/path2048 prefix bounds and surrogate-safe optional UTF8. Path query failure or clipping remains an explicit per-row limitation; collect remaining entries while budgets permit. No reported path is opened, hashed, resolved through filesystem attributes or used to load/pin a module. Names/paths are metadata strings. Query handles may become stale as modules unload; preserve snapshot-name/path disagreement rather than invent identity. Returned path spelling can differ from canonical spelling and may be truncated at the API buffer bound. [GetModuleFileNameW](https://learn.microsoft.com/en-us/windows/win32/api/libloaderapi/nf-libloaderapi-getmodulefilenamew).

Append/flush raw rows before any classification. After enumeration, classify only the retained metadata against the existing exact four-runtime/16-System32 description; any uncertainty stays unresolved. Classification never changes a list, opens a file or grants API eligibility. Unknown entries do not stop collection. No later entry is silently dropped to manufacture completeness.

## Bounds and completion

Keep the qualified detached launch, one child/active process,256MiB process/Job commit,30s child including2s cleanup,60s parent including5s finalization,64KiB stdout/stderr,40 Job snapshots and16 Job PID slots. Module enumeration is a separate one-snapshot limit. All child structured census artifacts total at most2MiB including framing; reserve64KiB of that for attempt/terminal/error records. Existing64KiB row limits apply. Count and byte limits are independent: if both cannot be satisfied, preserve a partial corpus. No cap is increased after an outcome.

`enumeration_complete` requires the natural `Module32NextW=false` / `ERROR_NO_MORE_FILES` end, not merely64 rows. An extra returned entry at the cap means remaining metadata is unknown. `metadata_complete` requires every retained identity query to return without API/prefix clipping, with all reported UTF16 units retained durably; optional UTF8 conversion has its own outcome. `publication_complete`, `parent_resource_validation` and `sealed_integrity` are separate. A complete census requires all of these, exact planned counts, exit0/EOF and successful owned cleanup. Any API error, interruption, count/byte cap, failed publication or missing terminal record remains partial/failed. A snapshot is time-bounded evidence, not a permanent or system-wide inventory. [Module32NextW](https://learn.microsoft.com/en-us/windows/win32/api/tlhelp32/nf-tlhelp32-module32nextw).

The parent needs a **distinct census validator and status**, for example `module_census_observations_retained_not_ABI_qualification`. It verifies fixed role, source/build/protocol/input hashes, current-child PID, one snapshot, contiguous row IDs/counts, lossless hex-length bindings, completeness flags, known-core load records, bounded outputs and existing Job/lease/receipt conditions. Its positive format is not the five-row ABI parser. Unknown/unlisted metadata is review material even when collection completes; `ABI_eligibility_established=false` remains fixed.

SDK3bf and its ABI-labelled sealer must remain untouched. Propose a separately pinned status-only sealer copy/wrapper using the existing reviewed `make_sealer(sdk)` pattern: identical cleanup/hash/deadline/failure code, only the successful census literal differs. The new parent calls that function directly, without replacing the SDK function or toggling its gate. Prove whole-function AST equality after normalizing that one literal. Existing primary, interruption, late-close, publication and post-seal vetoes still apply. Parent cancellation admits only existing cleanup/sealing, not new observations or eligibility reads.

Before a build, pure fixtures must cover65th-entry/corpus caps, natural-end versus error termination, one-shot snapshot failure, per-module query errors/clipping, surrogate/hex bindings, failed publication, cancellation and both kinds of sealer failure. A complete collection with unlisted names must retain every row and keep ABI eligibility false. The new validator must reject fabricated completeness, duplicate/missing ordinals, count/byte mismatches and ABI/recognition argv; source review must confirm the census branch returns before `Api` construction. These tests are planned, not executed by this design.

## Decision after a complete census

Review the entire reported set once. If exact additional System32 components are justified, propose one separate bounded file-inspection step for that finite set: independently approved canonical paths, no reparse traversal, size/SHA/static PE/version and meaningful offline publisher provenance where available. Do not follow arbitrary reported paths. No such file inspection is authorized here. Pinning AppHelp alone now would leave later unreported entries unknown and would authenticate neither this loaded image nor initializer behavior. A hash identifies file bytes; it does not prove their effects or all API-set/dynamic dependencies.

A future exact policy revision could admit a reviewed finite component set with parent read leases and matching header/manifest changes. It would not turn old failures into passes. A post-core census also does not establish what version/default or later vocabulary calls might load. ABI, document/EOG, resource-fit and scientific gates remain separate. Before any implementation: root and independent peer review this design, then source/pure fault tests, bounded build verification, exact role/protocol review and a separate one-attempt execution decision.
