# Detached parent launch policy: prospective design v1

This is a predeclared source-only design for a new four-case harmless qualification. It authorizes no implementation dispatch, API call, child or ABI run. Consumed Python, compiled-worker and IOCP attempts stay negative and immutable. The new policy is assessed on its own evidence; it does not explain the historical unknown PID or accept a conhost allowlist.

## Exact SDK and role delta

Create a separately named disabled SDK copy from `abi_parent_launch_draft_v3.py` SHA `c111ac5f42209eb61fc49522d4cd6db544987b1c4230577404022e1add6eb2f4`. Its only byte/code delta is CREATE_FLAGS: replace CREATE_NO_WINDOW `0x08000000` with DETACHED_PROCESS `0x00000008`. The composed flags change from `0x08080404` to `0x0008040C`. All other bytes, declarations, methods, checks, capture and cleanup remain identical, including literal `NATIVE_EXECUTION_ENABLED = False`. Do not monkeypatch the old module or its constant. The copy ensures inherited OwnedLaunch journal events describe the flags actually dispatched.

Keep creation suspended with extended startup info and Unicode environment, exact JOB_LIST membership at creation, exactly three inherited stdio handles, a noninheritable Job, no manual assignment fallback, strict identity/limit/PID checks before the sole resume, and previous suspend count exactly1. No CREATE_BREAKAWAY_FROM_JOB, CREATE_NEW_CONSOLE, CREATE_NEW_PROCESS_GROUP, NO_WINDOW bit, console-host exception, new attribute or extra API binding is introduced.

DETACHED_PROCESS changes console attachment; it does not request Job breakaway. NO_WINDOW is ignored when combined with detached/new-console flags, so the new policy removes it explicitly. Microsoft documents separate redirected standard-handle behavior; preserve the NUL stdin and stdout/stderr pipes rather than relying on implicit console handles. Actual capture and cleanup still require the new harmless qualification. ## Four cases, once each

Reserve each case call durably before entering it; remove it from remaining-not-attempted at reservation and preserve unknown-return state if publication or unwinding prevents a return record. The order is resources, overflow, sleep, suspended_abort. Any failed case stops subsequent cases. Each protocol has a new exclusive output subtree and cannot be restarted or reused.

Keep 60 seconds for the parent, at most8 per case with2 reserved for cleanup and5 for parent finalization; 256 MiB process/Job commit; active-process limit1; two streams retained at most65536 bytes each; 16-PID raw buffers and at most40 raw snapshots per case. No IOCP, observer PID opens or queue driver is used. The consumed IOCP v1 has a known pre-dispatch accounting defect and is not reused; fixing that separate driver is outside this proposal.

Resources must exit0, prove the65536-byte allocation control/release, reject384 MiB, and report exactly one rejected same-own-EXE child attempt with error1816 and null child/thread metadata. Overflow must hit the exact cap trigger, retain65536 with observed lower bound greater than65536, then show explicit stop125 and reaping. Sleep must reach the declared deadline trigger, stop125 and reap. Suspended_abort must fail after membership/identity checks before resume, retain no started marker and stop/reap the suspended owned process. Preserve all existing marker/protocol hashes, capture states, primary errors, independent cleanup outcomes, original read leases, final-recheck close errors, post-lease evidence and terminal-seal marker vetoes. Any unexpected child success fails resources even if cleanup succeeds.

## Predeclared resources-only final accounting policy

For **resources / harmless_after_wait / finished only**, the prospective accepted raw tuple is:

`TotalProcesses in {1,2}; ActiveProcesses=0; TotalTerminatedProcesses=0; assigned=listed=0; PID list=[]`.

This replaces the earlier platform-selected exact2 requirement for this new protocol only. It is chosen before any detached attempt. Preserve all successful-query, error, returned-length, raw-buffer and raw/decoded consistency checks before applying this narrow predicate. Never modify raw buffers/decoded values. The final row must identify the selected policy in the journal/report. Its required worker markers and normal exit are independent conditions; count alone never passes the case.

Microsoft documents that a limit-failed **Job association** increments TotalProcesses and can temporarily increment ActiveProcesses. CreateProcessW returning failure does not specify which earlier stage failed or promise that a Job association was reached. Thus final1 is consistent with an earlier rejection; final2 is consistent with one counted failed association. The latter explanation is an inference, not a uniquely established cause. Error1816 describes quota exhaustion and alone does not identify the active-process limit as the failing check. [Job accounting](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_accounting_information), [CreateProcess return semantics](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessw), [error1816](https://learn.microsoft.com/en-us/windows/win32/debug/system-error-codes--1700-3999-).

The frozen resource branch intentionally attempts its rejected child with CREATE_NO_WINDOW|CREATE_UNICODE_ENVIRONMENT, even though the worker itself will be detached. Keep that source/EXE unchanged and disclose the distinction. Null child fields are the worker's reporting convention when CreateProcess returns FALSE, not an identity record of any failed or transient OS process. Without IOCP/identity evidence, total2 cannot distinguish a failed association from another transient contribution. This policy therefore qualifies only the declared harmless resource outcome; it does not prove that only one process ever existed or permit a console-host exception.

All empty/assigned/running and other finished phases retain the unmodified generic SDK predicate: empty means total0/active0/empty; assigned means total1/active1/exact own PID; running-or-finished means total1 with a consistent active0-or1 state; nonresources finished means total1/active0/empty. Active2, an extra current PID, total2 outside the one final resources row, any total0/3+ final resource result, any terminated count or nonempty final list fails. Even a resource rejected-association count observed during a generic running sample fails this strict proposal; no result-dependent timing or predicate change is allowed.

Pure tests must establish exact one-constant SDK byte/AST delta and both disabled gates; constructor binding and actual/journal flag agreement; no incompatible/breakaway bits; one own EXE argc5 role; no IOCP/target route; durable four-case reservations; both resource final totals1 and2 accepted only with every other exact condition; reject0/3+, active1/2, terminated counts, extra PIDs, wrong lengths/raw mismatches and wrong worker fields; generic phases reject total2 and Active2; unchanged overflow125, timeout125 and no-resume abort; primary-plus-late-close and publication failures preserve complete negative artifacts and cleanup.

Pin the original SDK, new copy, qualifier/protocol, own EXE/source/copy/build proof, accepted runtime/System32 candidates, this design/contract, actual negative result25c648, late warningf084 and test evidence. The old sources/results stay verifiable. Exact peer/root review of the frozen new candidate precedes any separate once-only execution decision. A future successful harmless result would apply to this detached architecture and declared checks, never native-target correctness, historical causality or universal containment.

The console policy is supported by formal Microsoft flags/handle documentation and the published [Microsoft console design](https://github.com/microsoft/terminal/blob/main/doc/specs/%23492%20-%20Default%20Terminal/spec.md).
