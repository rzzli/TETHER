Source/pure-test preparation only, 28 October 2026. The original [v2 component](detached_abi_terminal_observation_v2.py), SHA-256 `f910dd6e4075a8e12c78dbe86f278c0e2c4ac42632db596d4c98a80f2c48667a`, [design](DETACHED-ABI-TERMINAL-COMPONENT-DESIGN-v2.md) and [failed exploratory test proof](DETACHED-ABI-TERMINAL-COMPONENT-PROOF-v2.json) remain unchanged at their original paths.

The independent fake tests exposed a real evidence-loss error: a read returned nine bytes after the observation deadline; the post-call check correctly failed, but the caller then skipped accounting and retention of the bytes already returned. A separate optional-key assumption in that first checker also failed and is corrected in a separately named checker. Neither failure is native execution evidence.

The new [v3 component](detached_abi_terminal_observation_v3.py), SHA-256 `4ea2c429a8e4d512d42ae449fc3764550421ae8cf6491e3866c8322880d5c96c`, preserves an already-returned value when the subsequent deadline check fails. Its capture path accounts/retains those already-returned bounded bytes even though the call status remains failed. It explicitly retains a returned raw Job response on the same late-return path. Limit/peak responses already remain in their outcome's value field with `return_observed=true` and failed status. No successful final predicate or complete terminal observation follows.

This is evidence retention during cleanup/finalization, not authorization for renewed work. The existing cutoff still blocks every subsequent OS read/query. There is no additional DLL, process, Job, handle-opening/closing method, API binding, source-data access or budget change.
