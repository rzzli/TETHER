# Bounded terminal-observation component

Working source/pure-test preparation only, 28 October 2026. [detached_abi_terminal_observation_v2.py](detached_abi_terminal_observation_v2.py) implements the pre-cleanup observation portion of the preserved [parent-v2 design](DETACHED-ABI-PARENT-FAILURE-OBSERVATION-DESIGN-v2.md). No target process, Windows API, DLL or compiler is executed by writing or reviewing this file. A future new parent, verified build, complete pure lifecycle evidence and exact protocol still need independent/root review.

`observe_terminal(owner, report, captures, streams, *, sdk, event, work_deadline, drain_seconds=0.25, now=..., sleep=...)` has no constructor, dispatch, process-open, termination, cleanup or handle-close authority. It observes only handles already owned by the supplied launcher. It never assigns the caller's primary failure or success status. The caller must place it inside an unconditional path that subsequently invokes the unchanged owner cleanup and existing final seals, including after an unexpected component exception.

The component attaches its record/error list to the caller's report immediately. Its finite work deadline is the existing child cutoff **before** the two-second cleanup reserve. The capture subcap is at most250ms and64 polls shared by both streams; each reserved poll can perform one existing availability query and at most one4096-byte read. Existing64KiB retention/truncation rules apply. Reservations and bounded outcome records precede calls, with returned byte counts separately retained before local capture consumption. One stream's cap/query/write failure cannot suppress the other stream's eligible observation. Subcap/poll exhaustion means incomplete capture, not EOF. The clock/capture/query interfaces are fakeable for regression tests.

The component then independently attempts one private-Job raw snapshot and one existing limit/peak query, if known owned handles, remaining work time and existing limits permit. It charges the shared40-snapshot allowance before dispatch, including an interrupted/unknown return. Raw snapshot publication precedes the generic predicate; failed publication does not establish a predicate result. A failed snapshot/predicate cannot suppress the independent peak query. Every returned error/publication/interruption is retained as a secondary observation error, and cannot clear the caller's original failure. Interruption stops new work while leaving cleanup to the parent. Deadline checks are cooperative around existing OS calls; they cannot interrupt a blocked call or establish a universal finite cleanup guarantee.

Physical **pipe EOF is distinct from process or Job completion**. An unconfirmed creation/exit can still produce an observed broken/EOF pipe; the component retains that physical observation truthfully and labels it `observed_pipe_EOF_unconfirmed_child_state`. The overall scope stays `pre_cleanup_creation_or_exit_unconfirmed` and `complete=false`. No confirmed process exit, quiescent final Job or reaped-worker claim follows. Only a caller-observed exit through a known successfully returned owned process handle permits the existing `finished` generic predicate. No PID recovery or global process scan is introduced. This clarification supplements the earlier61aa design without rewriting it.

Future parent integration should remove the early nonzero-exit barrier from terminal evidence collection, retain the nonzero exit as primary immediately, and invoke this component in `finally` before any owner handle closes. A zero-exit candidate additionally requires complete terminal observations plus the unchanged strict child-artifact validator. A component exception or incomplete evidence prevents success but cannot skip owner cleanup, input close/recheck records or authoritative post-lease sealing. Unknown creation/outcome remains negative/unknown. The existing30/60-second limits and cleanup/finalization reserves remain unchanged; no retry or fallback is added.

The consumed first attempt's missing final Job/peak/EOF evidence remains unavailable. This component creates no retroactive observations. The original SDK SHA `3bfac51893b60221728ac915516c5e816c0cfc5a82899f5871f7931469d7fdfd`, original parent and failed outputs remain unchanged. Module/CRT initializers, CPU/vocabulary/EOG, inference and scientific validity are outside its scope.
