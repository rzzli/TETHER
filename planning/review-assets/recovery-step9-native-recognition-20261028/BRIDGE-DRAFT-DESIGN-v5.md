# Diagnostic bridge v5: retain module refusal context

Source preparation only, 28 October 2026. The consumed v4 source, EXE, protocols and two failed native attempts remain unchanged. The new [author-owned v5 source](typed_public_c_recognizer_v5.cpp), SHA-256 `c2b802507dd135c33df512a386250d0781bbee0673ed6276bb5512f42adead8c`, addresses the [second attempt's missing module identity](ABI-MODULE-POLICY-FAILURE-DIAGNOSIS-v2.md). It grants no compilation or execution authority.

The same current-process `CreateToolhelp32Snapshot`/`GetModuleFileNameW` enumeration and existing path normalization are used. No global PID scan, new OS API, unknown module-file open/hash, alternative loader or allowlist expansion is added. `SystemApproval` performs the original single `GetSystemDirectoryW` query, preserves `system_directory_failed`, and exposes the original directory-match and listed-basename booleans. Approval remains exactly their conjunction. Native-module classification and its other failure predicates are unchanged.

On the first non-native policy refusal, the helper builds one optional `module_policy_rejection` row before throwing the **same** `unapproved_non_native_module` error. Context includes the original branch/tag, enumeration index, normalized reported basename/path, both predicate booleans, full UTF16 code-unit lengths, bounded prefix sizes, truncation and conversion outcomes. Name prefixes are at most256 UTF16 units and paths2048; a cut is moved back one unit if it would split a valid surrogate pair. UTF16 code-unit hexadecimal remains available when strict UTF8 conversion fails; the UTF8 field is then null. The prefix is an observation, not a replacement or normalized permission grant.

The hexadecimal representation is four lowercase hex digits per numeric UTF16 code unit, in sequence; it is **not UTF16LE byte hex**. The diagnostic JSON fields are capped at32KiB; complete row/failure/stdout framing remains below the existing64KiB per-row/stream limits. An attempted diagnostic row records `attempt_reserved` because it cannot attest to its own eventual write return. The error's owned context subsequently records `returned` or `failed`. The same context is propagated through the existing independent failure marker and stdout path, so JSONL publication failure cannot erase the original tag. A construction failure gets bounded fallback context when possible; unrecoverable allocation/OS failure may still leave partial output, which remains negative rather than accepted. Other errors receive empty optional context and preserve their existing output format.

This is **incomplete current-process metadata before policy acceptance**. It is not an inventory of the whole computer, verified unknown-file identity, dependency closure or proof that a candidate module is safe. The path comes from the existing `GetModuleFileNameW` plus `GetFullPathNameW` lexical normalization. If its prefix is truncated or conversion failed, that limitation must remain explicit. No filesystem eligibility, hash or loaded-byte identity is inferred for the unknown module. The stable failure remains authoritative even when diagnostic publication succeeds.

All25 typed symbol owners, the two intended ABI queries, success event/schema/default/layout/version/module predicates, disabled recognition header and four-runtime/16-System32 policy remain unchanged. Passing the existing Output reference to inventory calls only supplies a failure sink. CPU/backend/model/vocabulary/tokenizer/grammar/context/server paths remain forbidden in the later ABI role. The30/60-second and2/5-second reserves,256MiB, one active process,40 snapshots,16 PID slots and64KiB capture caps are unchanged.

The [pure diagnostic checks](check_module_policy_diagnostics_v5.py) test the declared encoding/bounds/publication contract and source-preservation properties without compiling or executing C++. They do not establish compiled formatter behavior or ABI acceptance. A separately retained v5 static owner proof must recheck the exact PE name/owner mapping. Source and independent peer review precede a new bounded build protocol; a verified build would still require a separate once-only diagnostic execution decision. Resource/model/scientific gates do not advance merely because a refusal becomes observable.
