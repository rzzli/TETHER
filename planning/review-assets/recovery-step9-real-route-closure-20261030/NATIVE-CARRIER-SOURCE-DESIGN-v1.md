# Internal C return-publication component

This source implements the typed return-capture part of contract `16aae7f0` and layout `4cf7a07f`. It is **not built or executed** at this source-authoring checkpoint. The accepted entry Source4 is unchanged. No kernel ticket, file admission, close/search right, native lease, child binding or path-lifetime guarantee is issued here.

The header declares the complete 128-byte header plus four 32-byte axes, with static assertions for all specified offsets, sizes and alignment. Fourteen fixed WINAPI pointer types and wrappers preserve signed BOOL bits, DWORD values and HANDLE bits. API output scratch receives counts; the wrapper records these as raw contents, separate from byte-progress eligibility. Query buffers remain caller-owned and `query_capture_state` stays zero: this component does not claim an immutable query capture.

Each wrapper assigns its target's direct return into the volatile native-width scalar payload, then stages and commits it. Useful error branches publish definedness true before a same-thread `last_error` call, retaining partial definition/error observations separately. Successful and undocumented-error branches publish false and leave the error-value axis unobserved. Count publication follows. `native_exit_phase=RAW_EXIT_PREPARED` does not claim Python caller return or conversion success.

The proposed publication primitive is the MSVC `_InterlockedExchange` intrinsic, which supplies a full barrier. Microsoft documents [InterlockedExchange](https://learn.microsoft.com/en-us/windows/win32/api/winnt/nf-winnt-interlockedexchange) as an atomic 32-bit exchange with a full memory barrier. [Last-error codes](https://learn.microsoft.com/en-us/windows/win32/debug/last-error-code) are thread-local and meaningful only under each function's documented return conditions. Source ordering is insufficient by itself: exact compiler output must still establish the intended scalar store and absence of intervening error-altering calls. An acquire/quiescent reader must be qualified before any live integration.

`pf14_initialize` is an internal structural initializer. It is not an issuer or a bank allocator. `begin` checks shape and uses a once-only phase transition to prevent a second call on an unchanged cell; arbitrary native callers can still replace memory. The pointer table and arguments are trusted-component inputs, not an ordinary Python-facing dispatch API. Ownership policy, admitted actor/target/argument consistency, pointer bounds/lifetimes and non-reuse must come from the future exact same-Core ticket bridge. The eventual canonical bank must be selected before the first bootstrap reservation; copying this component's rows into an existing Python bank cannot qualify that bridge.
