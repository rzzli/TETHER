## Architecture and reproducibility

1. **Consolidation is warranted; deleting live old modules is currently unsafe.** `question_interpretation_runtime.py:343–345` recomputes the live static import closure and calls `check_pin` on original absolute paths. `run_comparison.py:51–57` requires original paths, sizes and hashes. A Git tag or a code hash is not a replacement verification mechanism by itself. Design a versioned archive verifier/compatibility route and demonstrate clean-machine restoration of representative successful and failed runs before moving/deleting/reformatting those modules. Never auto-import code from an untrusted archived run.
2. **Core and study verification differ.** `artifacts.py:270–275` reports `code_matches_current` separately while semantic checks use the installed verifier. Question-study verification additionally enforces live byte matches. The plan must not claim one universal compatibility guarantee. A future report should name verifier version and archived policy version, and distinguish byte checks, source re-admission, execution reconstruction and scientific correctness.
3. **Portability means complete lineage, not copying only a demo folder.** Absolute roots appear in both `snapshot_base`, source proof paths, raw_root and receipt paths. A successful relocation test must include raw inputs, archived transport receipts, normalized packets, manifest/catalog policy, code and installed resources; keep original sealed bytes unchanged and resolve paths through an explicit allowed root map. Test both local and source-inclusive verification, rejected traversal and root-conflict conditions.
4. **Packaging gap is real.** pyproject packages onlysrc, with demo JSONresources; `tools.science` routines and role policies inplanning/review-assets are outside wheel resources. `comparison_workflow.py:25–33` loads one such policy from the repo. Prefer one new packaged study primitive at a time with parity fixtures, not a one-shot mandatory rewrite of all stopped-route drivers.
5. **Fixed layout in ops is intentional defense as well as inflexibility.** `registry_content_workflow.py:30,185` hard-codes an approved data root and PostgreSQL executable path. Replace with explicit resolved allowlisted configuration and exact binary identities, not an unrestricted environment variable permitting arbitrary executable/path substitution.
6. **Versioning and hashes solve different problems.** Version0.2.0 is accurate package metadata but insufficient to communicate changed backend/protocol semantics. Change versions only under explicit compatibility/release policy; do not promise a0.3.0bump alone repairs archives. Add a changelog and pinned code build identity.
7. **Local E backup is not off-machine protection.** OpusD9's phraseoff-machine is unsupported. Separately record source machine/storage fault domain, tested restore, contents, hashes and whether an independent copy exists.
8. **Tests and formatting:** AST equality does not establish archive compatibility because code hashes change. Peer tests are independently written test evidence and should not be merged merely because file names overlap. New property tests and coverage can improve confidence, but metrics are engineering diagnostics, not scientific validation or reason to expand the current scope.
9. **Broad P2 need not precede a bounded capacity check.** Once fixture contract/transport correctness is established, a controlled no-spend or separately authorized stronger-model test can run before complete architectural consolidation. A reference evaluation still needs human labels and fresh cases; exposedIL6Ris for calibration only.
