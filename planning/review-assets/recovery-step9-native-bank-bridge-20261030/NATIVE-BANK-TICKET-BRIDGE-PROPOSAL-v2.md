## 2. Binding and canonical reservation (B1)

`PreboundServices.raw_backend` selects one exact `SyntheticRawBackend` or one exact `NativeRawBackend` before entry. Native module load, initializer, target table and private factory are externally pinned pre-entry TCB; loading is not charged as if it occurred after the entry clock. After the first original clock, create the existing same Origin/nonce/Core/Registry/store identities and bind one empty Arena to them. AUTHORING exits before payload/argument/ticket arrays or original/output dispatch. Following EXECUTION policy and ordinary admitted plan, allocate once for exact admitted C, before output callbacks and earliest original reservation. Native mode has no synthetic canonical bytearray and never migrates records or replaces the backend.

Keep `state.reserve_call(api, actor, target_ref, requested=None, buffer_ref=None)` unchanged. Its native registration sequence is fixed:

1. Perform current policy, active-state, actor/early-file, exact FileRef, profile, requested-count, expected BufferRef and capacity checks. Require native buffer generation encodable and not quarantined before reserving a row. `CreateFileW` has no input handle; APIs 2–7 derive their input exclusively from this FileState's already registered, committed, usable CreateFile cell via `committed_fact`. Unknown, NULL0, INVALID_HANDLE_VALUE, foreign/unregistered open or a consumed file refuses before a new handle-taking row is appended. Close is the exception to the consumed-file gate only at the existing source-owned close reservation described below.
2. Prepare the exact preallocated CallState and assign its **canonical** `input_handle` before append/registration: UNOBSERVED for CreateFile, the just-derived exact integer for APIs 2–7. Call generation is 1, ordinal is unique/nonreused, target kind ORIGINAL=1 and target ordinal is FileState.id. The successor adds the source-owned `FileState._native_generation=1` at FileState construction and uses that positive value for target generation; current FileState has no such field, so this is an explicit source delta. File ordinals/generations are never reused; no reopen is added. Derive actor from `file.early`, never from a caller numeric code.
3. Append that same CallState to the sole Registry. `RawCallStore.register` validates the exact CallState/ref/ordinal and prepares C3 metadata from these canonical fields. API6 sets REQUESTED_PRESENT; APIs2–7 set INPUT_HANDLE_PRESENT; API7 additionally sets CLOSE_RIGHT_CONSUMED. API1 has handle bits0 with INPUT_HANDLE_PRESENT clear. Unknown flag bits and all unsupported APIs/actors refuse. Buffer IDs are native query=0 / read=1, absent=`UINT32_MAX`; requested=0 for non-read APIs. These native IDs preserve the current raw-bank convention; the unqualified legacy wire's distinct descriptive buffer IDs are not a native identity encoding.
4. Call exact `pf14_initialize` once for the unused aligned cell, with all metadata already complete. Store the strong call-ref entry first and publish the registered byte last, only after initialization success. Neither store allocates or calls Python; a C-test-injected interruption before registered publication leaves any initialized bytes and ref entry retained but unregistered, stopped and never invocable. Registration performs no target call or Python conversion. Initializer failure similarly leaves the genuine prepared/appended row unregistered. A Registry append failure preserves whether the preallocated row was prepared and whether the append actually became observable, exactly as the existing failure-retention path does; it does not manufacture an admitted native row. Later reporting returns no committed axes for unregistered rows and never retries initialization or publication. An initialized/registered row followed by reservation-index failure is retained registered/uninvoked/stopped, also never retried.
5. Preserve existing `_index_reserved_call` behavior and nonhealing faults. There is no Python patch-up of native handle/header fields after initialization.

Native `prepare_input(ref, handle)` is **validation only**: exact int, usable native-width bits, equality to the canonical registered header and CallState handle, exact same FileState/open generation. It does not store even an equal value. `_BootstrapPrimitives._call` may retain its duplicated input check, but must not assign the argument as authority. A mismatched supplied handle leaves the initialized row uninvoked and enters the ordinary stopped failure path.

Close follows the existing `_bootstrap_close` consumption point: under the original cleanup clock it sets `file.close_reserved=True` and `close_state='reserved'` before the close event and call. Native `reserve_call(CloseHandle)` requires those canonical facts, no existing `_close_call`, and this file's usable committed handle; `_index_reserved_call` binds the sole close row. A failure before/after registration cannot reset the flag or create a second close. `CLOSE_RIGHT_CONSUMED` is derived from that source state, not supplied as a ticket argument. A known handle after an earlier conversion failure still permits one *fresh close call*, under the original hard clock, when its close right was not yet consumed. Re-dispatch of the failed original ticket is forbidden.

## 3. Source/native generation table (B2)

Source BufferRef generations remain zero-based. Native present-buffer epoch is exactly `source_generation + 1`, checked as u32 before reservation. Call/axis epoch remains call generation1 and is a separate field. File target generation remains1; neither is a buffer epoch.

| Source buffer generation | Native buffer epoch | Disposition |
|---|---:|---|
| None / no BufferRef | 0, buffer ID `UINT32_MAX`, capacity0 | No buffer. |
| 0 | 1 | First buffered query/read is eligible if other gates pass. |
| 1 | 2 | New completed/released generation only; a prior ticket cannot match. |
| 4,294,967,294 | 4,294,967,295 | Last encodable generation. Completion retires it permanently; no next-generation dispatch. |
| 4,294,967,295 or larger, negative, bool, subclass | None | Refuse before reserve/entry; no wrap, truncation or reuse. |

Arguments, native header and ticket retain source generation and encoded native epoch separately. Invocation requires exact owner BufferRef identity, capacity, source generation and the corresponding `+1` epoch, plus same call ordinal/epoch and target generation. Even a matching buffer epoch cannot revive a consumed ticket. `finish_buffer` is a once-only kernel-controlled transition after successful required consumption/capture. It marks retirement intent, advances the source generation, and acknowledges that exact transition; an interruption between these facts quarantines the buffer and blocks reuse rather than repairing either side. No repeated increment on getter/reconciliation/snapshot is permitted. Unknown, failed or stopped work quarantines its current buffer generation; the same buffer cannot be reserved for another original call in this gate.

## 4. Mode-neutral observation and reporting (B3)

The existing RawCallStore object remains the sole facade. Synthetic mode keeps its existing `_bank`, `_refs` and semantics. Native mode holds the exact Arena instead of a `_bank`; it has these internal read operations, which cannot reserve, dispatch, mutate or refresh cached folds:

| Operation | Authority and precise result |
|---|---|
| `row_registered(ref)` | Exact Core/store/ref/ordinal in canonical Registry plus Arena registered byte/ref entry. False for an admitted unregistered row; foreign refs raise FOREIGN_RAW_REF. |
| `header_facts(ref)` | Quiescent acquire/copy of same native row: original binding metadata, entered/exit phase, flags, conversion and query-capture phase. Validate schema/size/epoch/API/actor/target/buffer metadata and all zero reserved fields. Corruption refuses; no repair. |
| `axis(ref,name)` | Acquire native commit, validate exact API/axis kind, width/epoch/stage/commit/padding and copy its 32 bytes. Return native state/raw bits plus known value only for COMMITTED. Preserve staged and unobserved-nonzero payloads. |
| `copy_row(ref)` | One 256-byte immutable copy after serial native quiescence, with header/axis checks. Never returns a live address or mutable alias. |
| `native_entered(ref)` | False if genuinely unregistered; otherwise C3 NATIVE_ENTERED flag plus native_exit phase1/2 with consistent metadata. Neither Python wrapper attempt nor return sets it. |
| `buffer_facts(ref)` | Preallocated native Ticket completion kind/span, export release state, source/native generations, immutable-frame reference/copy status and quarantine; unavailable for no ticket. A consumer cannot set these facts. |

`committed_fact` replaces its direct `_bank is None`/synthetic-ref test with `row_registered`, then uses the same neutral `axis`. Unknown/unregistered means UNOBSERVED; committed HANDLE64 bits0 remains known integer0, not UNOBSERVED or Python None. Cold reads after error/finalization never clock, record diagnostics, dispatch, reconcile, increment generation, fold or repair caches. Observation-object allocation may itself fail; such a failure leaves the canonical native row unchanged and cannot upgrade eligibility.

Convert `CallState.invoked` to a mode-aware readonly native property with a synthetic-only backing setter. Synthetic backend assignments retain their behavior. In native mode every existing `c.invoked` read, including `handle`, `_canonical_projection`, the unchanged Ops4 wire/report code and snapshots, derives from `native_entered(ref)`. It never copies that truth into a healing Python bool. Keep wrapper attempt in a separate preallocated Ticket field; `wrapper_return`, `wrapper_result`, clocks, cache/fold acknowledgments and `wrapper_error` remain independent Python-caller facts. Native entry followed by failed conversion therefore reports entered/committed handle with no wrapper return.

Use the same approach for `buffer_written`, `buffer_state` and `query_bytes`: synthetic backing fields/setters stay; native getters read Ticket completion/capture facts and native synthetic setters refuse. A native query's `buffer_written` means **defined returned span**, not total scratch initialized or copied. For successful attribute/size queries this is8. For successful final-path result n it is `2*(n+1)`, only after `0<n<=4100` and a checked terminator. The retained raw query copy is separately FRAMES[api] bytes (8/8,202/8), and its unused tail is not claimed as API-written data. The native `_call` branch checks valid defined span and complete immutable frame capture rather than the synthetic `buffer_written == FRAMES` test.

Native `defined(c)` requires registered/entered/RAW_EXIT phase2; committed nonzero BOOL32 scalar; committed u32 count in `[0,requested]`; exact ticket/exporter/generation binding; and native synchronous **defined read completion** for that span. Raw count and count-out scratch alone do not qualify bytes or progress. A known count may survive a later failed hash/copy/fold as raw/completed input evidence while the higher-level operation remains stopped. No hash/copy success is fabricated. Synthetic `defined` stays unchanged.

`raw_call_view` returns the same already prepared immutable native view when one exists; it does not reconstruct a failed view as a getter-side repair. If conversion never prepared a view it refuses NATIVE_STATE_NOT_REPRESENTABLE; a separately attempted source snapshot can still copy available native rows and record partial failure. `_issue_snapshot` obtains neutral row/axis/header/buffer facts while retaining independent Python wrapper/clock/fold cells. Partial/failed copies keep actual copied progress/error, remain noneligible, and cannot be replaced by an older snapshot or implicitly retried. Test scope retains at most one prepared view per call and two explicitly requested complete/partial snapshots; this is a retained-object test bound, not an unlimited-caller memory guarantee. Current ROLE1/legacy adapters continue refusing unsupported native-state projections; no native wire qualification or fifteenth producer artifact is added.

## 5. Closing every synthetic mutation route (B4)

In native mode `stage_axis`, `write_payload`, `commit_axis`, `observe`, `mark_entered`, and `mark_exit` first raise exact executing-kernel KernelRefusal with code `UNQUALIFIED_BACKEND`, before acquiring a mutable native address or changing any bit. `prepare_input` only validates as section2 specifies. Any synthetic-only CallState invoked/buffer setter and AdoptionHooks scalar/count/error/buffer/exit mutation also refuse before touching native state. The native bootstrap branch never constructs or supplies InvocationTicket/AdoptionHooks to the target. Ordinary calls to every facade method, including equal-value/idempotent writes, must prove byte-for-byte unchanged bank and no target entry. Native C3 alone publishes raw axes/entered/exit; the private C extension alone advances conversion/query-capture metadata. No Python success flag, ready bit or method-name convention substitutes for this mode check.

## 6. Immutable arguments, dispatch and error-triple protocol

The native branch first calls `prepare_arguments(ref, exact_source_dict) -> NativeArguments`. Validate exact dict/closed exact-string key set, exact source-owned FileRef/BufferRef, and exact primitive domains; copy only typed scalar values into the private object's fixed POD slots. `PyLong_CheckExact` excludes bool/subclasses/coercion; overflow and `PyErr_Occurred` are checked. Paths must be the exact admitted FileSpec.path string object. Security/template/overlapped are exactly None. Freeze the original7 constants: CreateFile desired_access `0x80000000`, sharing1, creation3, flags `0x00200080`; information class9/output8; final-path capacity4101/flags0; read requested equals the reserved value. Handle bits must equal the canonical reserved input. There is no option to pass an arbitrary function/address or mutable argument mapping into dispatch. These are project restrictions using [the exact-integer API](https://docs.python.org/3.11/c-api/long.html).

`prepare_ticket(ref, native_args) -> NativeDispatchTicket` takes the exact sealed Arguments type, same Arena/ref and unused ordinal, pins the exact writable contiguous **bytearray** exporter (no custom exporter or callback), and binds Core/Origin/nonce/Registry/store/ref/row epoch/target/buffer generations. It uses preallocated per-ordinal objects, never creates a second ticket after failed preparation. Before consumption, `invoke_reserved(ticket, args)` requires exact private types, `args is ticket.arguments`, same exact binding/unused state, current unquarantined generation and no active ticket. An equal clone refuses. NativeArguments stores all values; the original source dict is no longer consulted and its later mutation cannot change native arguments.

For CreateFile, before consumption, use `PyUnicode_AsWideChar(path,NULL,0)` to size-check the admitted exact string, then copy into the separate 4,097-WCHAR input workspace, check the returned unit count, reject embedded NUL and write the terminator. No `PyUnicode_AsWideCharString` allocation is selected. The required count includes the terminator when sizing with NULL; the copy call itself is checked rather than assumed to append one. This follows [Python's wchar API](https://docs.python.org/3.11/c-api/unicode.html#wchar-t-support). No path workspace is shared with the 4,101-WCHAR final-path output frame.

Exact dispatch order is: all validation/path conversion/export/preparation; reserve wrapper-attempt and consume ticket once; mark single active ticket with strong C-stack references; call the one fixed C3 wrapper while retaining the GIL; read exact C3 return/header at quiescence; record native completion; enter conversion; obtain immutable raw row and any required query frame; call the prebound exact kernel view factory; store its direct return pointer into `prepared_view` before any later throwable work; mark OBJECT_PREPARED; release any acquired buffer export once; clear active state; return that same prepared view to Python. `c.wrapper_result = invoke(...)` and the following `wrapper_return=True` are the separate first Python caller observations. C3 refusal, target failure, partial native capture, conversion failure or pending signal after consumption never permits another dispatch of that ticket. A pre-consumption validation error leaves consumed=false, but the source operation becomes stopped and does not retry the row/ticket; negative tests may inspect that distinction only.

The factory is captured from the actual executing kernel and is limited to observation/allocation, with no target dispatch, clock or untrusted callback. Test-only fault placement is independently frozen. In the production-shaped extension there is no Python-supplied factory replacement or fault callback after binding. A consumed call records native entry solely from C3, even if conversion raises before returning. C3 still owns first scalar/error/count transport unchanged; the extension never inserts Python C API, clock, formatting or allocation between target return and C3's scalar/error publication.

On a failing Python C API after Ticket exists, the **first failure action** is `PyErr_Fetch(&ticket.err_type,&ticket.err_value,&ticket.err_traceback)` into initially NULL preallocated slots. On arena preparation failure before a ticket is bound, use Arena's initially NULL primary triple. Do not format, normalize, inspect repr/str, decref temporary references, release a buffer or invoke a diagnostic first. Mark FAILED/stop using native scalar fields only after the triple is retained. `PyErr_Fetch` owns those exact references; absence of a value/traceback is retained as NULL, and an unnormalized value is not called an exception instance. No `PyErr_NormalizeException` is used in this bridge. [Python documents fetch/restore ownership and delayed normalization](https://docs.python.org/3.11/c-api/exceptions.html#c.PyErr_Fetch).

Cleanup may release the exact bytearray export once and clear active state. If cleanup raises, retain the first cleanup triple in the separately preallocated secondary slots without replacing the original. For propagation, `Py_XINCREF` the three stored primary references and call `PyErr_Restore` with those duplicate owned references; restore steals the duplicates while the Ticket retains the original triple for evidence. Return NULL immediately. If the initial error indicator is unexpectedly absent, latch a distinct internal protocol failure rather than inventing an original error. An already-instantiated sentinel must remain the exact value object; unnormalized triples retain their original type/value/traceback separately from whatever instance Python later creates at the boundary. `c.wrapper_error` is the actual caught Python exception and is not retroactively substituted into the original C triple. A prepared view remains strongly retained even if later cleanup/return fails; no wrapper-return fact follows from its existence.

## 7. Buffer completion, quiescence, GC and retirement

The first bridge keeps the GIL and permits one serial synchronous original7 target; no thread handoff, overlapped operation, pipe, device, completion callback or concurrent bank reader is eligible. C3 return PF14_OK plus RAW_EXIT phase2 and corresponding committed valid scalar/count are necessary for native synchronous completion. Target return without complete C3 transport, scalar failure, malformed count or generation mismatch yields unknown/failed completion and quarantines the generation. Read success/count0 is defined zero bytes but never positive progress. The [ReadFile contract](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-readfile) requires completion before buffer use; retaining a lock is not proof that an OS call cannot stall.

For successful query branches, completion spans are8, `2*(n+1)`,8 as above. The C extension records query-capture STAGED1 immediately before the actual immutable FRAMES-size copy and COMMITTED2 only after the complete bytes object is retained in `ticket.frame_ref` and its source query reference is issuable. COMMITTED_CAPTURE asserts actual immutable copy, not API success or defined bytes in the unused tail. Failed allocation leaves no committed frame, retains the first error, quarantines that generation and cannot be completed later by a getter. Read hash/copy still occurs in the source owner under its original clocks; failure quarantines and preserves any independently known native count/completion without granting a successful hash/capture fold.

Once C3 is no longer executing and no native target can use the exporter, the ticket is native-quiescent. Keep its exact BufferRef/exporter references. Each successful `PyObject_GetBuffer` has one `export_acquired` bit; `export_released` is a three-state field:0 NOT_ATTEMPTED,1 RELEASE_ENTERED,2 RELEASE_ACKNOWLEDGED. Release only when acquired && export_released==0 && native-quiescent, set1 before the matching `PyBuffer_Release`, and set2 after return. Preparation unwind uses the same rule. A release interruption or missing acknowledgment quarantines and never repeats release; the audit distinguishes intent from completed release. No release is attempted while native-active. The export is acquired only from exact bytearray, so no arbitrary Python exporter callback is in the selected route. A quarantined buffer may remain as retained memory but is not an immutable captured frame or available for reuse. [Buffer protocol rules](https://docs.python.org/3.11/c-api/buffer.html) supply the acquisition/release and exporter-reference requirements.

Arena, Arguments and Ticket are closed exact GC-tracked extension types: no public constructor, subclassing, instance dictionary, weakrefs, writable members, buffer export, address getter, pickle/reduce or caller-supplied function slots. Set immutable/noninstantiable type flags, omit BASETYPE and use captured internal allocation only. GC traversal visits every strong Python reference and each acquired `Py_buffer.obj`; no reference is omitted because it duplicates another owner. All fields initialize before tracking. The selected rules follow [Python's GC protocol](https://docs.python.org/3.11/c-api/gcsupport.html), while exact field choices are this project's design.

The external bounded harness retains the Core/backend/Arena/evidence roots until terminal review, and Arena holds each prepared Arguments/Ticket in preallocated arrays. Invocation also INCREFs Ticket and Arena across native/conversion work. Consequently native-active/prepared objects cannot legitimately reach zero references or become an unreachable GC cycle. `tp_clear` sets a preallocated retirement-pending flag and clears nothing if active/prepared/unretired; this conservative deferred clearing may retain a cycle and is reported, never claimed as memory reclamation. Explicit internal retirement requires no active ticket, all prepared/consumed tickets quiescent, exports acknowledged released, and terminal evidence retained. A missing release acknowledgment instead retains the Ticket/exporter/Arena in the existing bounded external evidence roots until process teardown; it permits no reference clearing, free or claimed reclamation. Ordinary retirement stops further registration/dispatch, permits reference clearing, and frees the bank only after all dependent tickets/arguments/views have released their Arena references. `tp_dealloc` first untracks, is legal only for quiescent/retired or never-bound empty objects, then clears owned refs and uses the matching GC allocator/free; an impossible active zero-ref state is an internal invariant failure, never a reason to free live bank memory. Neither `tp_clear`, retirement nor deallocation closes a Win32 handle or retries any original. Teardown/process death does not promise graceful snapshots, cleanup or durable evidence.

The GetFinalPath output remains4,101 WCHAR /8,202 bytes, including room for the terminator; the separate admitted input workspace is4,097 WCHAR /8,194 bytes. [Microsoft's size definition](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfinalpathnamebyhandlew) supports the distinction. No alignment/capacity claim relies on interchanging those buffers.
