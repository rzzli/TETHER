# Independent review of the proposed same-Core native-bank bridge

Status: **HOLD before freezing implementation literals or source.** This is a static design review. It does not authorize implementation, import, build, fixture provisioning, native dispatch or an execution retry. The proposal is well scoped, but its registration and observation joins need concrete decisions before an independent oracle can describe the actual adapter.

All fifteen source/metadata pins in the proposal basis match their current bytes. The four proposal inputs also match the pins retained in the companion JSON. No subject was imported or executed, no SDK/header/library was followed, and no historical/model/protected original was opened. This review inspected the proposed interfaces against Kernel5, the exact C3/header, the native contract, and the original-file admission and accounting methods. It did not perform a whole-repository or compiled audit.

## Clarifications to freeze with the same successor

1. **Exception retention.** Specify a no-formatting first latch of the C API exception triple using `PyErr_Fetch`/`PyErr_Restore` or an equivalently reviewed mechanism. Fetching an error is distinct from normalizing it into a Python exception instance. Retain type, value and traceback as originally observed, plus any prepared view, before releases/diagnostics that could reenter Python. Tests should distinguish an already instantiated sentinel exception's identity from a still unnormalized error triple. CPython's [exception API](https://docs.python.org/3.11/c-api/exceptions.html) describes error propagation and the three-part indicator; the design cannot claim an instance existed before normalization.
2. **Quiescence and GC.** Define when the single active ticket becomes quiescent, when each buffer export is released, and what the arena/ticket `tp_clear` and deallocator may do if they observe active or prepared state. Keeping strong external evidence roots is an acceptable bounded first-gate choice; clearing roots or freeing the arena during a callback is not. A release must occur once even on partial preparation. CPython requires complete traversal/clear and allocation/deallocation discipline for [GC containers](https://docs.python.org/3.11/c-api/gcsupport.html), and matching acquisition/release for the [buffer protocol](https://docs.python.org/3.11/c-api/buffer.html).
3. **Arguments and ticket consumption.** Freeze whether the duplicate `args` parameter is an exact captured immutable argument object or a field-by-field comparison against private typed slots. Type/domain/overflow failures occur before consumption, while an admitted consumed dispatch cannot retry after native rejection, target failure or conversion failure. Record wrapper attempt separately from C3 native entry.
4. **Native counts and immutable frame capture.** State exactly which native return/header facts prove synchronous buffer completion, independently of a later Python `bytes` allocation. No consumer may use initialized scratch as bytes; failure to copy a query frame quarantines the generation and cannot cause a getter to complete it later. A known successful scalar/count can remain raw evidence while an unavailable required buffer prevents higher-level progress/identity.
5. **Capacity accounting.** Freeze ticket/C arena structs, reference arrays, retained prepared objects/errors and buffer export records before build. Existing raw-view/snapshot byte arithmetic is valid payload arithmetic, not a whole memory bound. A 4,097-WCHAR input path workspace is consistent with Kernel5's 4,096-unit input path bound; the distinct GetFinalPath output frame must remain 4,101 WCHAR / 8,202 bytes. C3 already passes 4,101 to that API, whose [documented size includes the terminator](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfinalpathnamebyhandlew). The proposal presently budgets these separately, so this review does not report an input-path overflow.

## Design decisions that are supported at this scope

- A single exact prebound native backend, original Core/Origin/nonce/Registry and one canonical store is the right authority boundary. No later Python-bank migration or backend replacement is proposed.
- Allocating the native payload after EXECUTION/admission and before output callbacks/earliest original reservation preserves AUTHORING's no-payload/no-open behavior. The empty arena object's construction remains a separately acknowledged allocation after the first clock.
- Separate fixed fake-only and real-original7 images prevent a fake test pass from silently promoting a runtime-selected function table. APIs 8–14 remain unavailable, and no Python-supplied target address is proposed.
- Keeping the GIL and one synchronous active ticket is a bounded initial concurrency choice. It does not bound an OS stall; the separately bound external test supervisor is containment, not a qualified production child/lease issuer.
- C3 scalar/error/count publication and exact SDK layout are reusable source facts. Its existing fake executable and COFF cannot qualify a new CPython extension's compiled path or dependency closure.
- Nonexported native addresses, immutable copies, staged/uncommitted refusal, once-only close rights and preservation of failed conversion facts are appropriate goals. B1–B4 define the missing concrete joins needed to test them.
- Tiny original7 qualification, synthetic output sink, no native wire upgrade/artifact15, no physical14/lease/resource/inference claim and no protected/model reads preserve the intended scope.

These numbers do not establish fault-branch counts, allocation/RSS fit or joint physical14 admission.
