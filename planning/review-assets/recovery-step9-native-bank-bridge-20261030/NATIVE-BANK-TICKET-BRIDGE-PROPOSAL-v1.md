# Same-Core native-bank bridge: bounded next-gate proposal

This is source/metadata design only. It proposes a named kernel successor and one CPython 3.11 x64 extension over the accepted C3 carrier. No source, import, build, FFI, Win32, fixture preparation or runtime is authorized by this document. Exact source/basis pins are in [the basis record](NATIVE-BANK-TICKET-BRIDGE-BASIS-v1.json). Kernel5 is the selected narrow source baseline; this proposal does not infer its acceptance from a source pin.

The deliverable is a genuine native bank behind the original Core's sole `RawCallStore`, plus a private one-call ticket. It first qualifies native-bank integration with compiled fake targets, then, under a separate binding, the seven synchronous original-file APIs on a tiny owned D fixture. Positive `NativeInput`, child/image/launch authority, held-path lifetime, complete physical14, inference, resource fit and new native wire serialization remain unavailable.

Kernel5 currently accepts only `SyntheticRawBackend` at entry, constructs its store at lines 1797, allocates a synthetic bytearray at 574/2358, and writes native exit on Python return at 1585. Its synthetic registration also leaves native target-generation/flag fields unsuitable for C3 admission. Those are actual required joins, not a configuration flag that can promote Source4/5 to native qualification.

Keep `PreboundServices.raw_backend` as the sole selection point. A new exact `NativeRawBackend` captures the selected extension module/types/functions and executing kernel namespace before entry. The extension load and its initializer are explicitly pre-entry TCB work; this is not a claim that the Python entry clock measures launcher/DLL startup. Do not discover/import an extension from a fallback path during bootstrap. Pin its eventual image and dependencies as prior external TCB under E08, never as current decision/output content ancestry.

Use separate pinned fake-only and owned-D-only extension build descriptors, each with its function table fixed by the reviewed build; no Python API accepts replacement function addresses or switches target modes. The owned-D variant binds only direct typed original7 imports and GetLastError; APIs 8–14 remain null/unavailable. A fake-bridge pass does not certify the later Win32-linked image. Independent fake-target test C and build recipes are planned test inputs, not already qualified implementation.

After the first original clock, create the same Origin/nonce, Core, Registry and `RawCallStore` facade in the existing order. Bind one empty native-arena object to that exact identity tuple in the constructor. After E08 EXECUTION validation and ordinary plan admission, allocate exactly `256*C` native cell bytes once, before output callbacks and the earliest original reservation. Native mode never allocates a Python canonical bytearray, migrates prior rows or permits backend replacement. AUTHORING returns without arena payload allocation, output or original opens. Failed allocation retains the original error and no admitted dispatch.

## Private operations and ownership

The ordinary kernel API remains `state.reserve_call(api, actor, target_ref, requested=None, buffer_ref=None)`. APIs 1–7 and BOOTSTRAP/ORIGINAL are the only dispatch domains; APIs 8–14 remain data-only/unqualified. Proposed internal bridge operations are:

1. `backend.bind_core(core, origin, nonce, registry, store) -> NativeArena`: exact original class/module/function identities and references, one binding, no serialized root or caller-supplied pointer.
2. `arena.allocate(C)`: one positive admitted capacity, at most 16,384; no growth/reuse. Allocate with 16-byte alignment and the matching allocator/free pair. Microsoft's [_aligned_malloc contract](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/aligned-malloc?view=msvc-170) specifies alignment and `_aligned_free`; this is a proposed allocator choice, not measured memory fit.
3. `arena.register(call_ref, canonical_metadata)`: the kernel first prepares/appends its genuine Registry row; native registration initializes the corresponding same ordinal/epoch cell using C3. A failed append/register remains prepared/uninvoked or explicitly unregistered, with no Python-to-native repair. Initialized native metadata includes actual actor/FILE target generation, optional handle, requested count, buffer identity/generation/capacity and CLOSE_CONSUMED where applicable. Native kinds must match the API/axis, retaining Kernel5's guard.
4. `backend.prepare_ticket(call_ref, typed_args) -> NativeDispatchTicket`: only for the exact current source-issued reservation. Bind Core/Origin/nonce/Registry/store/ref/ordinal/epoch, the exact original7 function pointer, input handle/right, immutable path and pinned buffer generation. Prebind all arguments before native entry; no arbitrary Python callable, raw address, supplied ready bit, type alias or handle integer establishes ownership.
5. `backend.invoke_reserved(ticket, args) -> kernel.RawCallView`: verify the same prepared tuple and exact arguments, consume the private ticket once, then call only its C3 function. An invalid/failed consumed dispatch cannot retry. C3's entered/exit fields are authoritative; Python must not mark raw exit merely because its wrapper returned. Keep wrapper attempt, native entered, raw exit, conversion prepared and Python return observed distinct.

Ticket construction and subclassing are disabled; no pickle/reduce or writable fields are exposed. Only the captured bridge factory can mint one, and exact identities are checked again at invocation. Use exact integer checks before bounded native conversion: `PyLong_CheckExact` excludes subclasses, while documented `PyLong_As*` conversions can otherwise call `__index__` and have error sentinels that need `PyErr_Occurred`. Reject bool, coercible objects and overflow before consuming the ticket. See [Python 3.11 integers](https://docs.python.org/3.11/c-api/long.html) and [private extension type controls](https://docs.python.org/3.11/c-api/typeobj.html). These guards cover ordinary API use, not privileged arbitrary memory/reflection attacks.

The arena and tickets hold strong references to their genuine owner/ref/exporters until quiescent retirement. Cycles must implement the documented [GC container protocol](https://docs.python.org/3.11/c-api/gcsupport.html); a deallocator never performs an unrecorded CloseHandle. Do not free arena memory while a ticket, conversion or view can refer to it. The bounded first gate keeps the Core/evidence roots until terminal review; exceptional interpreter teardown remains outside graceful-cleanup guarantees.

## Native facts, conversion and buffers

Reuse C3's native-width first store and publication unchanged: return bits into the scalar cell, publish, independently observe error legality/value on the same calling thread, then raw count and native exit. No Python C API, clock, logging or allocator intervenes before the scalar first store or useful error transport. Microsoft's [GetLastError documentation](https://learn.microsoft.com/en-us/windows/win32/api/errhandlingapi/nf-errhandlingapi-getlasterror) makes usefulness conditional on the API's documented branch; a captured DWORD0 is still an observed word, not definedness. Scheduling, process death, SEH and the OS-return-to-store gap are not made atomic by this bridge.

After C3 returns, the bridge records conversion ENTERED, copies one quiescent raw row and calls an exact prebound kernel view factory. The factory is pure observation/allocation, with no clock, dispatch or user callback. Its successful return enters the ticket's preallocated `prepared_view` reference slot directly before OBJECT_PREPARED or later postchecks; the caller and ticket retain the same object. Kernel's direct `c.wrapper_result = invoke(...)` and separate wrapper-return facts remain the first Python-caller observation. Allocation, pending signal, factory or conversion failure retains the same original exception in preallocated ticket error-reference slots before diagnostic/decref work, any actually prepared object and all native bits; it cannot erase committed handle/count facts or fabricate a wrapper return. Conversion phase belongs to native observation metadata; it is not proof of caller eligibility.

Retain Kernel5's `committed_fact` authority for handle rights, defined counts, cleanup and cold reporting. A stopped call's optional caches/folds never heal or retry. Postcommit conversion failure can still grant the genuine committed usable-handle close right; staged/unobserved bits cannot. Fresh cleanup after an earlier error remains legal only under the original reliable hard clock and consumed-once right.

Keep the GIL during the first synchronous seven-API C call; permit one active native ticket, no thread handoff, callbacks or concurrent bank readers/writers. This reduces the first seam's concurrency surface; it does not bound an OS stall or protect against foreign native memory mutation. Python documents the lock/thread-state rules in [its C API](https://docs.python.org/3.11/c-api/init.html#thread-state-and-the-global-interpreter-lock). A future GIL-releasing/concurrent route needs separate design and tests.

Pin the exact owner read/query bytearrays with contiguous writable `Py_buffer` exports before dispatch, keep exporter references and release every acquired buffer once on quiescent completion/error. Export lifetime is documented by [Python's buffer protocol](https://docs.python.org/3.11/c-api/buffer.html); it does not authorize arbitrary aliases or mutation. Native bank memory itself exports no writable buffer/address. No consumer sees read bytes until the synchronous native call has returned and scalar/count/range plus source buffer-completion facts qualify them. Record synchronous buffer completion separately from a later immutable query-frame copy: failed copy leaves capture unknown, retains/quarantines that generation and stops reuse; zero-filled scratch is not an observed frame. A read's initialized/changed count scratch is never progress authority. [ReadFile](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-readfile) requires a valid buffer until completion and documents synchronous count initialization; this proposal excludes overlapped, pipe and device handles.

Source `RawCallView` is a copied readonly observation from that same bank, not a second canonical store. Read native commit with a qualified acquire/full-barrier operation, validate epoch/kind/width, then copy after native quiescence; [InterlockedCompareExchange](https://learn.microsoft.com/en-us/windows/win32/api/winnt/nf-winnt-interlockedcompareexchange) documents its barrier semantics. `KernelSnapshot` keeps immutable row copies plus independent wrapper/clock/fold facts; cold getters never refresh, resample or reconcile. Copy failure retains a noneligible partial capture. STAGED_UNCOMMITTED and UNOBSERVED-with-nonzero-payload retain their bytes and typed-refuse ROLE1/legacy normalization. No native wire schema or producer artifact15 is added. Test-harness raw copies remain separately labeled harness evidence.

## Small qualification scope and resource accounting

First freeze independent fake-extension tests for actual same-bank address/ordinal binding, backend replacement refusal, foreign/stale/replayed ticket, exact type/domain guards, all seven API return shapes, malformed API/axis kinds, pre-entry allocation failure, postcommit conversion failure, unchanged stopped caches, once-only cleanup and immutable quiescent/partial snapshots. These tests must exercise real compiled extension objects; ordinary unavailable-route refusal is not positive native integration. Freeze literals/fault placement before source execution, retain the first result and review the extension's compiled first-store path rather than inheriting the fake EXE's ABI qualification.

Only after that source/build/fake-bridge gate, separately select one fresh owned D directory and an explicit original7 fixture. A concrete minimal geometry is the exact three existing captured helpers (55,497 + 39,889 + 3,614 = 99,000 bytes) plus one invented 68-byte metadata file. Use the existing full 1 MiB profile, **not** legacy N4's 4,096-byte file cap. With N4/B3/M3 and four positive files, Q4/R68/C92/E228; normal one-read-per-file history has 28 original7 calls and four close attempts, not a promised universal count for fault branches. The real helper prefix is read/hash/identity checked through the native bank before closed compilation/attach. Provisioning writes and expected hashes are separate declared fixture preparation; no historical/model target is read or rewritten.

Read-only `OPEN_EXISTING`, FILE_SHARE_READ and reparse inspection remain fixed, without overlapped/device/pipes. Sharing restrictions constrain compatible opens but do not prove an immutable snapshot, defeat prior writable mappings, bind a child loader or establish a held path lease. Those remain separate gates under [CreateFileW's documented sharing rules](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew). Output journal/packets may remain the explicit synthetic sink for this original7 gate; harness persistence is not the physical14 writer.

For that geometry the canonical native array is 23,552 bytes. Retained per-call converted views add at most 23,552 copied raw bytes; two retained complete snapshots add at most 47,104, separately from live rows, 256-byte copy transients and boxed axis/wrapper metadata. Existing read/query buffers are 1,048,576/8,202 bytes; retain complete 4×8,218 = 32,872 original query witnesses. One serial native path workspace needs at most 4,097 WCHAR = 8,194 bytes, separately counted unless an actual allocation review proves reuse. At most C92 private tickets can exist, with native struct/GC/Python object sizes to be fixed and checked before build; no fabricated per-object coefficient or memory-fit claim. Capture total 99,068 and largest helper 55,497 remain within current limits. The maximum cell reference remains 16,384×256 = 4,194,304 bytes, not joint physical admission. No whole bulk allocation, cap lift, RSS/commit or inference claim follows.

The prospective runtime needs a separate Root binding with one original cooperative test deadline and retained first partial/error evidence. Keeping the GIL cannot interrupt a hung synchronous OS call; an external model-free test supervisor may bound its known main process, with abrupt termination explicitly losing graceful current-process snapshot/close guarantees. It is harness containment, not a positive production child/lease issuer. Owner300/child120/work117 and scientific/resource ceilings remain unchanged and unqualified here.

## What blocks progress

The present blockers are engineering decisions/evidence: exact native adapter/ticket source, complete header/ABI/CRT closure for the selected CPython interpreter, independent pre-code expectations, extension build/disassembly and separate runtime scopes. Root has checked only existence of Python3.11 `Include/Python.h` and `libs/python311.lib` under the named uv installation; this proposal follows neither path and infers no ABI/header completeness from existence. Future extension binary hashes are null while source is planned; source review/build staging must precede final execution pins.

No owner file, download, restart or permission blocker has been established. A genuinely absent header/library, unwritable selected fixture directory or unavailable required access would need a concrete retained failure before asking for help. There is no reason to open originals or request model/child/native-input authority to author this seam. Current docs, C3 and Kernel5 remain unchanged.
