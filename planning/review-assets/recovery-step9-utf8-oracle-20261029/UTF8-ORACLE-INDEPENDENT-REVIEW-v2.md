# Independent strict UTF-8 fixture review

The frozen [revision 2 specification](UTF8-ORACLE-SPEC-v2.md) and [corpus](UTF8-ORACLE-CORPUS-v2.json) are clear for a separately implemented pure adapter. Their expected states remain unchanged. This is fixture/reference evidence, not adapter, vendor, DLL, vocabulary/EOG, model, resource-fit or scientific qualification. No original native attempt is repaired or repeated.

The initial [manual HOLD](UTF8-ORACLE-DRAFT-REVIEW-v1.json) preserved the first 96-fixture candidate. Revision 2 adds the valid two-byte minimum, a valid F1 lead, every interior cut of those representatives, four restricted-second-byte failures crossing a chunk boundary and a middle BOM. Its chosen contract clearly separates consumed legal prefix bytes, committed scalar output, pending evidence, examined-but-unconsumed offending bytes, absorbing errors and final EOF. Raw NUL, ASCII controls, BOM and noncharacters are valid scalar data; UTF-16 surrogate encodings, overlong encodings and values above U+10FFFF are not. ASCII JSON escapes/unclosed JSON prefixes carry no JSON-membership claim.

The author [froze the artifacts](UTF8-ORACLE-FIXTURE-FREEZE-v2.json) before reference execution. The final [split-reference proof](UTF8-ORACLE-SPLIT-REFERENCE-PROOF-v2.json) checks all **107 fixtures, 167 step states and 29 declared interior cuts**, with no mismatches or exceptions. All semantic fields—including scalar output, pending width/bytes, error offsets/category, per-step/cumulative consumption, unconsumed tails and finalization—match under the separately labelled evidence paths:

|---|---:|---|
| Original bytewise strict CPython path, with explicit oracle consumption accounting | 104 | The accounting contract is specified here, not inferred from undocumented post-error codec state |
| RFC earliest surrogate rejection plus independent completion certificate | 3 | CPython incremental diagnosis occurs later; no direct timing/API agreement is claimed |

The first [reference proof](UTF8-ORACLE-CPYTHON-REFERENCE-PROOF-v1.json) failed on exactly those three surrogate cases. The retained [narrow probe](CPYTHON-UTF8-SURROGATE-TIMING-PROBE-v1.json) shows CPython buffering `ED A0`/`ED BF` under nonfinal feeds before rejecting a third byte. The [certificate](UTF8-SURROGATE-NONEXTENDABILITY-CERTIFICATE-v1.json) then tests all 256 possible third bytes for each distinct prefix: **512 strict-final decodes, zero accepted completions**, plus six separately counted incremental trace calls. This corroborates non-extendability; the RFC-based earliest-byte policy stays normative. Failed proof, actual timing difference and certificate remain retained. No post-exception codec state was inspected.

These distinctions follow [RFC 3629 sections 3–4](https://www.rfc-editor.org/rfc/rfc3629.html) and the buffering/finalization interface described by [Python 3.11 codecs](https://docs.python.org/3.11/library/codecs.html#incrementaldecoder-objects). The selected byte-consumption, error-offset, strict argument-type, absorbing-error and after-finalization policies are explicit local requirements. No production adapter exists in this review: its bytes-only/final-bool validation, exception precedence, state immutability, repeated-feed behavior and fresh serialization copies still require independent implementation tests.

The [pinned vendor-source review](VENDOR-UTF8-DECODER-STATIC-REVIEW-v1.json) separately finds that a later tiny source-built experiment could retain the exact chunk decoder and two-field partial structure with standard-library dependencies and no model/DLL linkage. The whole grammar translation unit has additional private includes. The helper does not return consumed counts or a final-EOF result, stops at literal NUL and has different malformed-byte assumptions; these must remain raw observations. No extraction, compilation or vendor execution occurred. Such a source-built experiment would not establish installed-DLL token/EOG behavior.
