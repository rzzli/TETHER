Status: design and coverage review only. No Inspect conformance result or runtime guarantee is claimed here. The governing requirement is [BG05](../../../TETHER%20Benchmark%20Execution%20Plan%202026-11-02.md), the unchanged [27-obligation specification](../../tether-equal-policy-20261102/POLICY-SPEC.md), and the [corrected exposed-corpus protocol](../../tether-equal-policy-v2-20261105/CORRECTED-PROTOCOL.md). The original [clause coverage ledger](../../tether-equal-policy-20261102/COVERAGE-QUALIFICATION-v2.md) remains historical evidence; its 108-case count is superseded by the frozen patched 109-case corpus, not silently edited.

## Claim and comparison boundary

The defensible target is an actual Inspect Task/solver/scorer integration that preserves the complete declared archive policy, supplemented by separately measured execution controls. Inspect must schedule samples, run the solver, invoke a custom scorer and produce native evaluation logs. A second Task must execute a local deterministic `ModelAPI` through Inspect's real `generate()` path, with genuine lifecycle callbacks, native usage and failure records. A Python launcher which calls the independent validator and prints its verdict is insufficient.

Archive parity and runtime parity are separate claims. The 109 immutable BG02 artifacts can establish finite archive conformance. They cannot demonstrate that a new Inspect execution reserved a call before dispatch, retained an interrupted write or enforced a deadline. Likewise, a scripted Inspect model is a real integration test, but it is not model capability, a provider billing test or a full therapeutic T1/T6 scheduler. If a runtime obligation is not implemented and witnessed, retain an explicit gap instead of extrapolating the old TETHER witness.

The existing independent validator is a substantive dependency: **8 files, 2,642 physical lines, 2,391 nonblank/noncomment lines and 168,968 bytes**, as recorded in the patched BG02 reconstruction. Six original modules plus two v2 routing modules implement domain contracts, lineage, source proofs, policy binding, replay, features, prediction and rendering. They import no TETHER/asof validator. Count this full closure as reused code; count new Inspect integration, measurement/analysis, tests and upstream Inspect separately. Neither the new wrapper's line count nor all of Inspect's unrelated source is a minimal-equivalent maintenance estimate.

## Native facilities and extension responsibilities

Inspect provides real task/sample execution and custom solver composition; a solver need not call a model. Its mutable `TaskState` is the framework container, not immutable scientific evidence. Keep admitted evidence, source capabilities and request fingerprints in separately frozen copied objects; validate their identity when projecting into or out of TaskState. [Official solver documentation](https://inspect.aisi.org.uk/solvers.html).

Hooks expose task/sample/attempt/model lifecycle events. Their objects are not deeply immutable; ordinary hook exceptions are logged as warnings, while `LimitExceededError` can propagate. Thus admission and durable reservation must run in the authoritative solver/provider wrapper, not depend solely on a callback succeeding. Hooks should mirror events into independent telemetry and be reconciled before success. A missing required callback is a failed extension invariant, not permission to admit. [Official hook documentation](https://inspect.aisi.org.uk/extensions-hooks.html).

Inspect distinguishes sample errors, limits, retries and recovered logs. Freeze `retry_on_error=0`, disable automatic task/eval retries, and qualify provider retry behavior separately. Errored samples may be unscored by default; `score_on_error` is useful if supported in the pinned version, but cannot replace an external all-scheduled denominator. A recovered log is not authorization to call a model again. [Official error handling](https://inspect.aisi.org.uk/handling-errors.html).

Native limits constrain sample execution and model usage, but their units differ from the contract's reservations: a turn is not necessarily one provider attempt, and working time can exclude waits. Keep separate workflow/call limits and external wall-time/output supervision. Reconcile native usage with measured extension usage; unknown interrupted-call usage remains a conservative reserved upper amount, never a fabricated measured zero. [Official limit semantics](https://inspect.aisi.org.uk/setting-limits.html).

Native evaluation logs are valuable execution artifacts, not automatically externally anchored hash-chained proof of original source lineage. Seal their exact final bytes together with the extension manifest/journal and schedule. Validate reconstruction against independent expected outcomes, not a built-in answer matcher. [Official log format](https://inspect.aisi.org.uk/eval-logs.html), [scorer interface](https://inspect.aisi.org.uk/scorers.html).

Read-only inspection of installed **inspect-ai 0.3.287** now confirms the relevant behavior: `hooks/_hooks.py:1131` swallows ordinary hook exceptions; `solver/_task_state.py:426` exposes `target` to solver code; `model/_generate_config.py:207` defaults model retries to unlimited, with `_retry.py:170` treating zero as no retries; `_eval/task/run.py:2554` handles error scoring after retries. Consequently **Sample.target must stay empty**, and both `retry_on_error=0` and `GenerateConfig(max_retries=0)` must be explicit. The model wrapper must also reject repeated calls independently of those settings. The source hashes and observations are retained in `INSPECT-SOURCE-REVIEW.json`. Environment-wide RECORD/import qualification remains a separate gate; source inspection is not execution qualification.

### Minimal faithful IX10 claim witness

Use a separately copied invented native case and packet with at least two eligible observed records in one specialist category; this is new witness input, never a rewrite of the frozen 109 bundles. Call the reused independent `admit` to obtain grounded records, eligible artifacts, the lineage graph and registered fingerprints, then recursively freeze private copies. A real scripted Inspect model returns their ordered offered IDs. The extension's live commit function must enforce ID uniqueness and offered-set membership, the registered canonical evidence fingerprint, observed status, exact target/indication/category/program capability and write-time informational eligibility. Claim identity is exactly `claim-` plus the first 20 hex characters of the canonical fingerprint of `{case: case_id, evidence: grounded_record}`; extraction mode remains `verbatim_source_selection`.

Check an injected monotonic deadline before each append. A deterministic clock control expires after the first of two valid commits. The durable ledger and journal must contain the same reviewed prefix, an explicit commit-budget stop, no later provider call, and null prediction with `run_incomplete` abstention. The positive neighbor commits both. Pair this with duplicate/unoffered/wrong-category and post-admission nested-mutation controls; a rejected selection may use only the declared review retry, while backend failures never receive that retry. Report the clock as a controlled scheduling witness, not a benchmark of long-workload timing.

Do not conflate raw context with feature applicability: opposite action, modality or tissue suppresses mismatched numerical features but does not automatically prohibit otherwise eligible contextual evidence. Full eight-category orchestration, clinical model calibration and a live therapeutic scientific specialist are still outside this small execution witness.

## Fair resource and outcome analysis

The proposed primary schedule is **109 cases × three arms × three order-rotated fresh-process batches = 981 cells**: Inspect plus the independent policy, the same independent validator directly, and standalone TETHER. All use the same newly qualified interpreter/environment and unchanged original artifact bytes; installed product sources must match the pinned old release. Historical BG02 timings are context, not fresh paired measurements. The direct independent arm isolates framework overhead; standalone TETHER supplies the task-system comparison.

Measure cold and batch execution as different modes. Batch means one fresh process per arm/repetition executing the entire fixed case order with `max_samples=1`; include one-time setup and finalization, then report amortized total/case alongside operation-only diagnostics. An optional prospectively fixed **nine-case cold diagnostic** uses EP001, EP023, EP059, EP075, EP076, EP078, EP090, EP094 and EP109, covering preparation, lineage rejection, inner verification, invalid/valid replay, inspection, schema2 policy, outer verification and local-response archive validation. Each cold cell gets a fresh interpreter and complete wall/CPU/peak-memory/import/teardown accounting. Its timings describe only those nine cases, not all 109. Do not compare cold Inspect with a warmed standalone predicate or omit lazily imported dependencies. Repetitions are repeated timings of authored constructions, not independent scientific cases. Any concurrency study requires a separate frozen mode.

Use identical source artifacts, scratch-copy policy, access checks, per-case caps and instrumentation in each measured mode. A zero-cost scripted model does not make CPU time, elapsed time or integration work free. Report native log bytes, extension outputs, retained policy copies and complete logical input inventory separately. Record physical I/O or cumulative transient writes only if actually measured; unknown values remain null. OS peak memory and Python allocation peaks have different scopes. Count the entire reused validator closure plus new adapter, runtime, reconstruction and qualification code without double-counting shared files.

For each arm/mode/repetition, retain all 109 scheduled rows: expected accept/reject/inspect-only; actual accept/reject/inspect-only/unsupported/error; unstarted/missing/unscored and operational failure fields. Report false admission among 64 rejects, false rejection among 44 accepts, the inspection case, decision agreement, full observable conformance and all-scheduled operational completion. Report both completed-only native score and all-scheduled score if they differ. An error on a normative reject is not evidence of the intended rejection. An exposed finite suite cannot establish general policy superiority or natural failure prevalence.
