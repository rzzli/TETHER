- General source eligibility uses the reused independent validator, not a second independent runtime implementation.
- Independent runtime features/prediction reader is under development; no replay pass yet.
- IX11 write failure is component/mock qualification; no native persisted write-fault control executed.
- IX11 native-log contradiction and IX12 complete/failed/interrupted independent replay results pending.
- Python hook guard is trusted-code network enforcement; not an OS sandbox.
- Injected commit clock is a contract control, not a real long-workload timing result.
- Parent proof/seal overhead not hard-preempted; owned-child guard does not prove arbitrary process-tree cleanup.

IX11 has maintained journal-write and capture-write failure qualification. It does **not** have a retained native write-fault execution in this prepared set. A future tamper reader must reject a copied native log or chain contradiction; listing that reader here is not an empirical result.

The new runtime source/proof reader is expected to bind packet ancestors, claims, deterministic features, predictions, native responses and callbacks without invoking the producer semantic checker. Its current implementation work and eventual results must be reported separately. General eligibility continues to rely on the reused domain validator; the project does not claim two independently reimplemented biomedical policies.

Actual result evidence arrays stay empty until the corresponding external anchors and independent checks are available. Final population of this draft must preserve these distinctions.
