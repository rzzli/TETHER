P05d implementation and qualification notes, version 1

Status: **CODE AND FICTIONAL QUALIFICATION ONLY; NO NATIVE RUN AUTHORITY.**
The source-reporting model branch remains closed. This implementation creates no
model call, network operation, download, provider spend, human recruitment or
clinical inference. The DRAFT still has no execution authority. Native packets,
actual reference values, prior answers, human descendants and protected clinical
originals were not read during this implementation.

`tools/science/run_source_validation_experiment.py` is a P05-only orchestrator,
packet-only literal/abstain adapter, actual-guard diagnostic evaluator and bounded
fictional fixture author/qualifier. Core source modules and prior protocols are
unchanged. The separate experiment DRAFT retains twelve native units, fourteen
designed scenarios, 38 output slots and 90 paired decision slots. Its explicit
implementation changelog distinguishes generic JSON/core fictional controls from
the unchanged native P05 Parquet scanner. C02 is an absence-handling core control,
not a claim that an absent measurement column passes that scanner.

Generation is a pure `literal_report(packet, always_abstain=...)` operation. It
has no reference argument or filesystem access. `generate_native_case` reads only
one exactly allowlisted, SHA-bound source packet and passes only that packet to
the adapter. It receives no reference-valued object, reference hash or evaluator
path in its generation spec. Fact IDs and complete physical bindings are rebuilt
from the neutral task and source-node claims and compared to the supplied
value-free skeleton. Types, signed zero, array order, missing/null/empty reasons,
all declared one-to-many locus records and scientific unknown context are
preserved. Anchor authority comes from task-declared identity, rather than
optional raw linked-row scope fields. Unsupported join shapes fail explicitly.

The evaluator separately requires the exact reference-file byte SHA, canonical
wrapper manifest fingerprint, reference READY byte SHA, upstream successful
seal/journal and admitted independent source audit. It reconstructs the retained
query/config bundle without executing archived code and invokes the unchanged
`verify_p05_references` once with an explicitly trusted original root. Only the
genuine source-replayed reference objects returned by that function reach
`score_cell`. The private derived replay root is created and checked first.
References are not fabricated from serialized documents or passed to generation.
The full wrapper and compiler share algorithms with preparation; admitted
independent original projection remains necessary and does not become independent
merely because the wrapper replays successfully.

Generic fictional sources have real invented original JSON files, exact receipts,
contemporary SourceNodes, catalog roles and hash anchors. G1 constructs the real
InputGraph and calls exclusion/verify. G2 calls actual pure mapping, eligibility
and precision-date predicates and enumerates the complete JSON inventory. G3
calls the unchanged compile/verify APIs. G4 adapts retained bytes and calls the
unchanged scorer. F02 has a genuine forbidden ancestor. F03/F04 retain the
remaining actual core guards under WITHOUT_WRAPPER; no guard is patched to force
the contrast. The WIRE_ONLY verdict is a schema/retention projection and never a
fabricated scored cell. The evaluator accepts an independently supplied fixture
root and does not accept raw-root authority from serialized fixture metadata.

Strict exact-report admission requires `answered`, every requested slot once,
matching values/units/bindings/unknown reasons and correct collection status.
It is distinct from core 80% measurement completion. Regressions cover a missing
correctly unknown fact and full facts under `partial` status: core completion can
pass while strict exact reporting rejects. C04 admits exact identities/unknowns
with null measurement coverage and false completion. C03 retains both physical
rows and a finite negative native SE; that is a technical pass with scientific
validity explicitly unestablished.

RunJournal reserves each output before dispatch and uses the existing fsynced
hash chain. Actual runs use a new ignored `data/derived/preprint-p05-experiment-`
timestamp leaf. There is no resume, replacement, overwrite or automatic repeat.
Every output has one of the six terminal dispositions, and every decision has
admitted/rejected/no_decision plus a terminal and failure stage. The outer ledger
always retains all 38 outputs and 90 decisions. The unchanged core aggregate
contains only its genuinely source-verified scored subset. Missing references
never acquire invented coverage, reference objects or scores.

Terminal writes are independent best-effort operations: a ledger failure attempts
an emergency ledger; append/close/seal errors prevent qualified success and
attempt a separate failure seal. A lifecycle failure seal overrides a previously
written candidate ledger status. Every path preserves existing artifacts rather
than overwriting them. If all storage writes fail, no implementation can promise
durability; the failure is propagated and qualification is withheld. Terminal
resource reports do not re-enter expired source-read deadlines. The fictional
qualification CLI produces an explicitly labeled test artifact: zero native
outputs, fourteen fictional attempts, 42 fictional decisions, and native slots
unexecuted. It is not the locked P06 experiment.

Memory uses optional psutil when available and the native Windows process-memory
API otherwise. A real API regression with psutil explicitly unavailable confirms
positive RSS and process-lifetime peak; unavailable or over-limit readings fail
the runtime bound. Sampled RSS and process-lifetime peak are distinct fields.
The peak can precede a timed phase and is not attributed to one arm. This does not
recover the earlier reference producer's missing peak measurements or change its
frozen resource limitation. Completed repeated logical hash bytes, cooperative
time, CPU time, emitted/retained bytes and enumeration passes are recorded;
partial failed hash bytes, physical I/O and platform cost stay explicitly unknown.
Native packet read plus literal/abstain generation are measured as a shared pair,
counted once per case; source verification is separately amortized, and schema
policy projections do not acquire artificial end-to-end runtime measurements.

The late root READY schema is intentionally strict. It binds exact DRAFT/design,
all active code plus qualification tests, existing environment, limits, cutoff
and expanded schedule; all twelve native task/packet/reference hashes and actual
requested/answerable fact/group counts; all fourteen fictional task/core-reference
hashes or explicit absent-reference dispositions/counts; fixture manifest;
independent source-only exposure/dependence register; input/source-reference
audits; independent peer review; and fictional qualification. The code checks
original-source register counts against both READY and freshly replayed
references. `measurement_answerable_groups` means groups with at least one native
answerable requested measurement component, not fully populated groups.

READY also freezes exactly seven `extra_code_sha256` entries: independent
analyzer/auditor modules, their two fictional test files, and the independent
registry/input/reference source-audit helpers. Those files are held under stable
locks throughout native execution. The analyzer module's matching flat
`analysis_code_sha256` is copied to the output ledger. Archived code is never
dynamically executed by this runner.

READY inputs are exactly `input_seal`, `input_audit`, `reference_manifest`,
`reference_seal`, `reference_audit`, `fixture_manifest`, `exposure_dependence`,
`peer_review` and `fictional_qualification`. Each descriptor has an absolute
approved path and external byte SHA. Audit descriptors also provide
`expected_fields`, a map of dotted document paths to exact expected metadata,
including the relevant source seal/manifest/code anchor. Audits must have PASS
status with no issues/findings. The peer/qualification report can expose the flat
`reviewed_code_sha256` field. Fictional qualification additionally binds the
fixture manifest and every frozen core reference/count; output truth labels
never determine source facts or verdicts. The independent register must expose
FROZEN/READY, ordered case_ids, other_exposure UNKNOWN,
independent_studies_established false and per-case metadata/counts.

For independent analysis/audit, each output retains `core_score` or null,
`strict_exact_report`, `full_source_admitted`, `full_verified_exact` and
`fact_accounting`. FULL source admission requires G0–G3. A G2-rejected but
G3-verified fictional candidate may retain an actual core score without FULL
qualification. Family counters record requested, answerable, uniquely matched
answerable facts, correctly unknown, omitted and false assertions; malformed
emission counters stay null. Unknown-ID emissions are separate. Top-level
`native_qualification` is a dict keyed by all twelve IDs, initialized unverified
with null counts, then compiled/count-bearing or blocked after actual source
replay, independent of later output success. Frozen input descriptors, subject
hash/count bindings, guard stages, bytes, journals and provenance allow the later
independent auditor to reconstruct conclusions without trusting stored scores.
