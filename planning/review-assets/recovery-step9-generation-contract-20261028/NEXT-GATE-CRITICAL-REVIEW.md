## 2. Close the smallest typed C-API and loader qualification first

listed in the native requirements; inspect their transitive include closure. The

`decltype` function pointers to approved exports. The direct GBNF path need not
cross the converter's C++ `std::string` ABI again. Nevertheless, returned C structs,
calling conventions, DLL-import macros, architecture and producer/consumer ABI
still require exact declarations. No copied layouts, private sampler casts,
RVA/ordinal guesses or invented deallocators are acceptable.

Start from the actual default parameter object. Establish `vocab_only=true`, zero
GPU layers and an explicitly empty live device list only after source inspection;
a null device pointer means all available devices. Do not equate those settings
with measured GPU isolation. Verify tensor-check/repacking/MTP/load-mode choices
and whether any backend discovery or linked dependency can initialize a device.
Do not call backend load-all, context creation, encode/decode or sampling APIs as
an undocumented convenience. A typed build or tiny ABI fixture is not loader proof.

Vocabulary-only still creates a `llama_model*` and reads model-related metadata.
Fresh hashing of approved split GGUF files reads weight-file bytes even when no
weight tensors are allocated. Record these as distinct operations. Qualify the
existing approved vocabulary and actual DLLs, not a smaller substitute. Pin secure

## 3. Qualify exact token/document completion and vocabulary EOG

Freeze a fresh non-lazy sampler per document and reject empty grammar. The corpus
has **109 + 58 = 167** retained documents, not a replacement set. Preserve authored
extension expectations separately from observed pure membership of the old cases;
review the next protocol's intended native labels before execution.

Tokenize without automatic specials or interpreting special-token text. Treat
pieces as bytes: individual pieces may be partial UTF-8; concatenated pieces must
equal the original document bytes exactly. Never normalize, trim, reorder keys,
rewrite escapes, remove a prefix or repair an invalid document to make it pass.
Cases outside fixed serialization can remain semantically valid, while duplicate
claim texts can pass grammar and still require post-validation rejection.

Apply the actual grammar sampler to each next candidate with a finite initial
logit, recording the first rejection. Accept only admitted tokens. Enumerate all
vocabulary EOG IDs, rather than assuming EOS is the sole terminator. Probe their
admission after complete input and at declared incomplete prefixes; never accept
a rejected EOG, which can abort native code. Include cuts within JSON structure,
escape pairs and naturally partial UTF-8 token prefixes where applicable. Check
trailing input, exact literal/ID mismatches, repeated references, Unicode bounds,
non-scalars and the five strict wire-parser edge cases explicitly.

Character EOF, token-piece roundtrip and actual-vocabulary EOG are separate
results. Exit zero is not document validity. Free each sampler before the
vocabulary-owning handle; return structured token/rejection/EOG/cleanup evidence.
No inference context or generation is needed for this stage. Vocabulary loading
still requires its own authorization and accounting.

## 4. Measure grammar cost and full-case feasibility separately

vocabulary. Native prefix stacks can be expensive despite an acyclic, compact and
whole-word-unambiguous grammar. A later finite resource contract should measure
representative complete-prefix states, full-candidate filtering, repeated-rule
stack growth and worst boundary strings, with declared counts and stops. Do not
claim production decoding cost from a one-candidate probe or pure grammar bytes.

Before integrating v3, profile the existing
[295.922/300-second simulation](../recovery-step9-native-duration-20261028/RESOURCE-RISK-NOTE.md).

work, payload construction, tokenization, reservations, transport, cleanup and
final verification/sealing under the unchanged budget. Preserve cold/warm I/O
conditions and failed timing observations; no easier case, larger allowance,
weaker hashing/admission or favorable-time repetition establishes feasibility.
Any correction needs a prospective scope, meaningful regressions and installed
replay evidence before a once-only integrated experiment.
