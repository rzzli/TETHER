# R09 model-backed adapter and shared-case integration

Prospective engineering contract, 27 October 2026. Implement after 0.3.8 codec
acceptance. This continues the authorized sixteen-step plan; it is not permission
to restart R07, run a new model experiment or generate a fresh evaluation case.
No human review is fabricated, and no paid/new model or source is acquired.

## Required end state

Provide a concrete native adapter for `source-quote-interpretation-v2`, trusted
source/history/capacity verification, and an explicit mode of the existing
four-arm case controller. One AsOf stage, five adapted Virtual Biotech stages,
extractive and lexical results share one unchanged default case budget and timer.
Do not stop at a backend that is disconnected from that controller. Do not build
a second scheduler, HTTP implementation, archive stack or generic plugin loader.

Keep the recorded path and legacy codecs behavior unchanged. Preserve accepted
wheels and negative R07 artifacts; old receipts retain their matching verifiers.
The new receipt track must distinguish measured native generation from evaluator
fixtures and pure work. Native execution cannot fall back to recorded stimuli.

## Explicit launch and asset capability

Use a frozen concrete `NativeExecutionConfig` supplied by trusted caller code,
never a serialized class/callback name. It carries a verified existing asset
inventory, approved bindings, exact model identity, fixed loopback/one-slot
launch configuration, and trusted ownership/health callbacks. A raw backend ID,
model alias, caller list of source IDs or absolute archived pathname is insufficient.
Archive its effective data/proofs, not executable callback code to be imported.

Construct `OwnedServer` inside the controller's already reserved output and
shared deadline. Its command is derived from the verified existing runtime/model
inputs with fixed offline/loopback/one-slot/16,384-context flags; no free-form
command or remote endpoint. Model weights must match the tokenizer specification;
runtime and required DLL/input proofs must resolve to approved bindings. Use
ordinary stable-file leases through generation and verification. Initial launch
and every call require positive ownership; no process discovery or killing by port.

Source preparation and all-candidate eligibility checks precede server launch.
The source lease stays active as on the recorded path. Record server command,
stdout/stderr, startup/qualified context and terminal cleanup with the same root
journal. Startup, exact tokenization, calls, pure methods, stop and sealing all
count inside the existing300-second budget. Bound cleanup by remaining time;
late cleanup cannot publish success, but must preserve a primary error and the
owned-process terminal state. Do not imply hard preemption of synchronous I/O.

## Native adapter and trusted replay

Reuse `LocalBackend.generate`'s one-use transport rather than copying it. Override
only the explicit payload/capacity contract. Each stage has its own concrete
adapter instance, authenticated exact prompt/payload/tokenizer quotation, earlier
parent/caller deadline, and the same positively owned model server. Recheck quote
and time immediately before consumption. No automatic retry, model switch,
source replacement, permissive JSON grammar fallback or assertion repair.

Bind original native wrapper bytes to exact stage request/payload, endpoint/PID,
model alias/provenance, echoed generation options, complete positive stop and
reported usage. Invalid content preserves measured usage. Missing usage remains
explicitly unknown/conservatively reserved. A rejected model answer stays failed.
Quote reservations are distinct from measured tokens and actual HTTP submission;
do not label a pre-POST owner failure as a known completed model call.

The trusted verifier must independently recheck complete original source lineage,
catalog policy, accepted same-run/same-arm predecessor proofs, actual source-ID
history, current payload, quote, concrete adapter identity/capabilities/provenance,
native wrapper and v2 result. Resolve feedback IDs from the materialized quotation
bindings, never from generated prose or caller suggestions. Generated assertions
and exact quotes remain separate; features empty/probabilities null. No new
scientific assertion enters the evidence ledger or scorer.

Read-only verification can reconstruct only fixed installed native receipt
semantics; JSON cannot select classes. It never starts/contacts a server, runs
archived code or retries a call. Source-inclusive replay still requires explicit
approved original input roots. Declare any model-input replay dependencies and
relocation limits; never use archived locations as access capabilities.

## Existing controller seam

Factor the smallest concrete execution mode into the existing composition. Share
source/retrieval authority, stage order, current token quotes, baseline policies,
case budgets, leases, failures and finalization. Extend stage history extraction,
caller identity, neutral projections, durable accounting and verification for
native results, while preserving recorded outputs and default behavior.

Native summaries separately report reservations, measured usage, known submitted
HTTP attempts, unknown attempts, failed/accepted stages, server/tokenizer process
counts and pure work. Final source verification and successful owned shutdown
precede receipt publication. Errors preserve partial journals, native bytes,
usage and terminal cleanup; recovery is inspection only. Root inventory/receipt
verification covers launch and mode artifacts and rejects unexplained additions.
