## Call expressions, without a hidden joint-fit claim

Let q=1,048,576, actual original sizes s_i, P the count of positive originals, N all originals, and E=2240 only for the currently proposed owner-journal envelope. Original calls are:

`Q_orig = Σ ceil(s_i/q); R_orig = Q_orig + 16P; C_orig = 6N + R_orig`.

The213 historical metadata rows give Q/R/C=8796/12204/13482 at q; this is not the complete new roster. Neither physical output nor bootstrap/launcher/pipe operations are included in that C.

For each explicitly parent-written artifact j, let b_j be its cap, K_j its logical record cap, and w=65,536 the existing output request maximum. A conservative transfer of the existing short-write rule is:

`W_j = K_j + ceil(b_j/w) + 16`; `W_parent = Σ W_j`; `Flush_parent <= E + F_parent`; `file identity/open/close calls <= 6F_parent`.

Use K_j=E for the journal and1 for each other parent artifact. If the parent physically persists both capture streams, F_parent=11: ΣK=2250, Σceil(b/w)=495, W_parent<=2921 and Flush_parent<=2251. Without stream files, the nine owner files give W<=2885 and Flush<=2249; the stream persistence path would remain unbound. At a separately specified1 MiB writer quantum, the eleven-file formula would be 2467 writes, but that is not the existing 64 KiB writer contract or an activated choice.

For one fresh full readback pass of the closed 14-file universe, using actual present sizes and the same four identity queries/open/close:

`R_rb = Σ ceil(actual_b_j/q) + 16P_rb`; `C_rb = 6F_rb + R_rb`.

The all-cap conservative universe has Σceil=51, R_rb<=275 and C_rb<=359. Missing/conditional artifacts reduce actual reservations only by a frozen membership rule; they cannot be silently omitted from a required positive gate. Parent-written bytes can be compared to their stored immutable object in bounded readback chunks rather than issuing an uncharged second full blob. Child-origin files must first be captured into their own generated-store slot. The exact source-issued comparison/readback witness is still missing; a matching reported digest is insufficient.

Retain all query frames for new physical slots: three frames total 8218 B per file open. Eleven output-writer identities plus fourteen readback identities would add 25 sets/205450 B beyond the original-only query pool. Their raw call cells, diagnostics and once-close rights also need an explicit storage/reservation channel; they are not silently covered by the original-only C=16384 table.

For directory metadata, preserve the existing finite formulas rather than unconstrained enumeration: U unique admitted ancestors including attribute-only C:/D: drive roots; two scans with S=ΣD_k, D_k<=8, depth<=4; X=Σ(64+3D_k+1)<=178. Attribute calls<=U+S, search calls<=2S+X, and explicit directory-create attempts D_out give `C_meta <= U + 3S + X + D_out`. At U=1024/S=16/X=178 this is 1250+D_out. The old one-directory allowance does not automatically create a physical child subdirectory: exact output/child namespace paths and D_out must be frozen. Roots are never file leaves or enumeration roots.

Even combining only the historical C_orig with eleven-file 64 KiB writes/flushes and one 14-file readback yields `13482 + 66 + 2921 + 2251 + 359 = 19079` calls, before directory, bootstrap, child/pipe, error-transport or physical-tail work. A one-directory metadata upper bound would bring that illustrative total to 20330. These are conservative planning expressions, not observed counts, an isolated lower bound, or a new cap proposal. C=16384 cannot be described as a joint physical fit. Reconcile the actual new roster, actor-specific API domains and raw retention before any physical activation.

## Causal publication and true first entry

Candidate bytes freeze before original closes. Terminal bytes freeze final original-close facts; neither may acquire later output-close facts by mutation. Check and read back pre-receipt artifacts under their owned leases, then close those leases before issuing receipt evidence. Journal-close attempt consumes append rights regardless of ACK; receipt/seal writes and their return facts cannot append a repaired journal tail.

Receipt write/readback/close facts necessarily occur after its prerequisites; seal follows receipt. A seal cannot contain its own hash/ACK/readback result. Final seal/readback/close outcome and the final unchanged-clock veto therefore belong to source-owned post-publication in-memory facts or a separately anchored external verification, not a self-reference or mutation of an earlier ledger. Exact placement of these physical tail records within the existing source/format universe is an unresolved binding. No extra unnamed output artifact is introduced here. Unknown, late or unreturned outcomes remain incomplete; no dispatch after the hard cutoff, including best-effort repair writes.

The missing true-entry components are concrete: an externally pinned minimal entry capturing original t0 before helper/authority imports or reads; approved typed native file bindings with immediate first-return slot registration; an adopted canonical owner/registry/output namespace; exact captured-source importer and genuine authority/checker factories; versioned role-aware producer; owned child/Job/pipe launcher; physical output/readback adapters; and exact new-format archive/journal/resource/case composition. Accepted injected bootstrap, adoption, owner and controller sources are references for those invariants, not their production implementation. Never call an old `run_once` constructor to reset origin, registry, leases or budget.
