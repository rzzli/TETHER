# Bounded interpretation development

The next gate is actual source-bounded generation and scientific review, following
the source-only sidecar implementation and the scoped IL6R primary reference.
This is one exposed development hypothesis with two deliberately selected source
contexts. It is not a fresh holdout, a paired comparison or a general performance
estimate. Original full T6/H5 and scientific Tasks 6–8 remain unfinished.

## Frozen scope

Use the existing IL6R / EFO_0000685 inhibit-antibody case, tissue unspecified,
with its October 16 origin and original receipt-bound Open Targets snapshot.
Two requests select the previously reviewed mechanism source and the MR
discovery/replication source. Each request retains all scientific fields of its
selected observation. Available versus selected counts and the original 65
missing inputs remain explicit; collection gaps cannot become biological absence.

Selection is deliberately informed by known development problems. The primary
reference is sealed before generation, while prior exposure prevents a claim of
blinding or new preregistration. Its contents never enter the model requests.
The exact executable plan is pinned in
`planning/review-assets/local-interpretation-development-20261025/prepared-plan.json`.

## Generation and controls

Extend the existing pinned Qwen2.5-14B / llama-server loopback runtime with the
optional interpretation output contract. No model download, external provider,
clinical cohort, MR computation, scorer training or clinical probability is added.
The default selection backend and archived native workflows remain unchanged.

Scientific fields are shared losslessly in the prompt and verified by complete
round-trip fingerprints, preserving null/absence and JSON numeric/boolean types.
The model selects original source string references; the adapter materializes
exact quotes and UTF-8 spans. The model still authors the propositions, inference,
limits and applicability. This conversion supplies provenance, not scientific
entailment or endorsement. Unsupported free prose still requires scientific review.

Retain default case-wide caps:16 calls,32,000 input tokens,8,000 output tokens,
300 execution seconds and zero provider cost. The two worst-case reservations
are26,308 input and4,096 output tokens. Per-request prompt limits reserve output
headroom within the16,384-token native context. Model startup and asset verification
are measured separately from the shared generation clock.

Verify receipt-pinned weights and every runtime file before startup. Bind only
127.0.0.1, reject redirects/proxies and confirm the launcher owns the listener.
Archive the server command, model configuration, full native payload/response
bytes, measured usage, materialized response and hash-chained journals. Reject
unqualified truncation/length stops. No generation retry or resumption occurs;
failures stop the pilot with accounting and readable records. Stop only the
launcher-owned process before sealing outputs. Full storage failure can limit
durability; journals retain the writable prefix and no failed output is reused.

## Ordered acceptance

1. Validate explicit selection, lossless prompt projection, transport/translation,
   budgets, native-response semantics and failure handling with fixtures and
   independent methods probes. Retain initial failures and fixes.
2. Pass full project tests, required probes and packaging with an unchanged-code
   guard; verify dependency-free and isolated checkout behavior.
3. Execute the frozen requests once under the verified local runtime. Inspect any
   failure before creating a new version or output; do not silently repair model
   output, substitute sources or rerun a possibly billed call.
4. Reconstruct source admission, exact payloads, translation, accounting and
   prediction seals without dispatching again. Hash-check protected clinical
   artifacts without parsing their answers.
5. Independently review candidate attribution, premise validity, inference,
   numeric/model context, clinical overreach, missingness and justified abstention
   against the pinned source/primary reference. Adjudicate agreements and
   disagreements, retaining unknowns and source/cohort dependence.
6. Report the actual qualification decision. A mechanically valid or all-abstaining
   candidate is not automatically scientifically qualified. Do not publish an
   error percentage, independent sample size, efficacy or superiority claim.

## Development progression rule before generation

Both source-scoped tasks must finalize without retry and pass source-inclusive
mechanical verification. Two separate AI reviewers and adjudication must examine
every generated clause, with the inherited exposure/shared-model limitations
disclosed. Each task must contain at least one useful, correctly bounded inference
or context-specific caution supported by its offered premises; a generic disclaimer
or wholly abstaining response cannot satisfy this requirement by itself.

Progression requires no unresolved critical error: source fabrication or
misattribution; effect-sign, disease or exposure/outcome reversal; an unqualified
genetic-proxy-to-antibody benefit assertion; endorsement of a contradicted premise
without its necessary qualification; provider-score-to-effect conversion; invented
species, units or study context; or treating incomplete collection as absence.
Clinical efficacy/safety claims remain outside the qualified scientific reference
and cannot count as correct support. Faithful quotation alone does not establish
validity of its premise or inference.

Record pass, fail or indeterminate with clause-level reasons. Failure or an
indeterminate decision requires a separately versioned design correction before
fresh evaluation generation. A pass permits only preparation of the next bounded
fresh feasibility study; it does not qualify general scientific performance or
the original full T6/H5 and clinical objectives. Freeze this procedure separately
against the executable plan before its execution directory exists.

Only a supported development decision permits the next fresh source-only question
frame, pre-output reference/prediction seals and bounded paired feasibility batch.
If qualification fails, retain the failure and revise the interpretation/retrieval
design before a separately frozen run. The stopped clinical acquisition route
and periodic monitor remain untouched.
