### Step 4 — Fix reproduced framework boundary failures first

Make each fix separately reviewable; add the regression before changing behavior.

**4A. Temporal precision.** Specify exact versus year-only publication semantics and the precedence of independent public-by proof. Test imprecise dates with and without sufficient proof, exact post-origin dates, inconsistent dates, later mappings/annotations, evaluator ancestors and verification replay. Reject uncertainty explicitly rather than silently substituting a current date. Version semantic changes and preserve archived-run interpretation.

**4B. Backend failures.** Introduce typed transport/protocol exceptions at the adapter boundary. Wrap known `URLError`/`HTTPError` and malformed response shapes. Preserve fatal storage/programming errors, `KeyboardInterrupt`, measured/conservative accounting and zero automatic retry. Test category-continuation policy, unknown billed calls and readable terminal journals.

**4C. Backend payload preflight.** Derive request allowance from backend capabilities and complete framing/escaping. Keep retrieval byte count, prompt byte cap, context tokens and output reservation separate. Test a request below retrieval allowance but above native prompt capacity; it must fail before dispatch. Cover quotes, Unicode and model control tokens.

**4D. Store construction.** Make `snapshot_base` an explicit invariant or fail during construction. Test directly constructed stores and normal loaders through finalization. No late `AttributeError` after a model call.

**4E. Small contract repairs.** Correct optional mapping annotations and union-decoder diagnostics where compatible. For hard-link publication, first specify supported filesystems and no-clobber semantics, then test concurrent writers and failures. Defer serialization optimization until measured bounds justify it.

**Validation:** new regressions fail on the old behavior and pass on the new code; source-inclusive verification, v1 compatibility, failed-call accounting, package demo and appropriate full checks pass. Previously sealed live-code closures remain usable through the migration strategy; never edit a pin file to hide a mismatch.

4. Define matched conditions where available: existing model with current interface; existing model with simplified interface; stronger model with the same simplified interface. Add the stronger/current-interface cell only if access and budget permit. Record any incomplete design and avoid causal capacity claims.
5. Freeze the exact evidence, questions, candidate order, output meaning, temperatures/seeds, source budgets, output bounds and failure policy. Different tokenizers may require different token counts; keep semantic evidence parity and report actual reservations.
6. Prepare the strongest accessible condition without spending. If access requires a file, model download or paid provider authorization, show the concrete capped plan to the owner. Continue unrelated work while that condition remains unavailable.
7. Preflight complete payloads and estimate local runtime/memory from measured hardware. Do not inflate defaults or silently truncate inputs to obtain fit.

**Validation:** exact request/source equality and payload fit are machine-checkable; no model call occurs during preparation; no evaluator answer is in the prompt; all cost and resource ceilings are explicit.

**Stop:** if no valid stronger condition is available, report capacity as unresolved. If the task still cannot be represented simply, redesign it before another full controller stack. Do not continue an unbounded converter/grammar search.

**Validation:** independent methods review can reconstruct all denominators and analyses from the protocol; the chosen sample meets the declared precision/power objective or the study is explicitly exploratory.

6. Report provider spending, local compute/time, human time and explicitly unmetered external AI work. Limit cost claims to what is measured.

**Validation:** source-inclusive mechanical verification for every finalized run; complete review lineage; locked analysis script reproduces tables; no undocumented exclusions or arm-specific retries.

**Completion:** H5 is complete only for the amended protocol and stated scope. Report negative findings if superiority is not established. Do not claim original H1–H4 or T1 completion.

## 5. Conditional original-project branches

### Step 13 — Qualify an alternative clinical outcome source before scaling

1. Audit the dated labels and reuse terms of candidate CTO/CTOD, released Virtual Biotech or other specified benchmark products. A paper's reported accuracy does not qualify the project's linked labels.
2. Define the exact clinical endpoint and risk set, origin eligibility, follow-up, reporting-lag policy, censoring and mapping confidence. Separate trial efficacy, phase transition, approval and sponsor continuation.
3. Audit an origin-selected sample with source-grounded endpoint adjudication. Record both event and public availability dates. Keep evaluator-only labels isolated and already exposed members out of untouched tests.
4. Quantify usable positives/negatives, unresolved fractions, clusters and reporting bias. Do not choose a new cohort after seeing favorable outcomes.
5. If restricted files are missing, prepare exact product/date/path requests; the owner handles acquisition. Existing AACT archives should not be re-requested without a specific gap.

**Gate:** enough qualified independent information for the original declared clinical effect/precision target under realistic dependence. Otherwise defer T1 explicitly; do not use registry statuses as substitute efficacy labels.

### Step 14 — Qualify predictors, optional genetics and scorer

1. Freeze outcome-independent predictor derivations and temporal lineages. Keep null real-data features until derivations are validated.
2. For non-genetic scoring, qualify training/calibration/test origins, leakage controls, missingness and minimum event information. Genetics is optional unless the hypothesis explicitly requires it.
3. For MR/colocalization, start from the existing full-cis assets. Verify estimator-specific coverage, allele/build alignment, units/uncertainty, ancestry/LD, assay identity, overlap, checksum exceptions and exposure-to-action interpretation. Plan sensitivity analyses before computing results.
4. Reopen downloads only for named scientific requirements. Preserve restricted-provider terms and contemporary/historical separation.
5. Fit/calibrate only after the label/predictor gates pass, with chronological splits and frozen applicability. No fit to an exposed twelve-case development audit.

**Gate:** each feature/scorer has a reviewed derivation, applicable scope and independent validation; otherwise record defer. No probability appears merely because a logistic-scoring implementation exists.

### Step 15 — Run original clinical baselines and ablations

1. Simulate dependence-aware power using actual qualified positives/negatives and paired predictions. The original H1 smallest effect of interest is AUROC 0.05; preserve co-primary Brier and other registered requirements or amend prospectively.
2. Pin model chronology. A contemporary model-capacity control cannot become a January 2025 historical arm. Immutable pre-origin weights bound acquisition, not necessarily every training-data source; disclose uncertainty.
3. Freeze simple baselines, adapted/reproduced Virtual Biotech configuration, genetics and other justified ablations. Keep original base-rate predictor distinct from the stopped registry-content audit.
4. Lock external test anchors, run once, and evaluate paired AUROC/Brier, calibration and clustered uncertainty. Preserve H3 subgroup and H4 ablation definitions with correct multiplicity/dependence.

**Gate:** all prerequisites, adequate power and chronology pass. Otherwise report feasibility/negative results rather than a clinical superiority claim.

### Step 16 — Evaluate extensions separately and release reproducibly

1. Give each T2–T5 task its own endpoint, reference source and feasibility gate. Some may reuse qualified clinical mappings; others need different evidence and experts. Do not activate them as a single unchecked bundle.
2. H6 is a separate reanalysis: require released per-drug/per-target data, original covariates, dependence structure and compatible out-of-time reconstruction. Aggregate plots cannot supply individual-level analyses. If unavailable, record the precise external blocker.
3. Prepare the final release: installed-wheel quick start, stable docs index, current status matrix, concise TODO/memory, dated history, source/license inventory and reproducible analyses. Compress or release-attach large inventories only with stable hashes/links.
4. Complete hosted Windows/Linux CI on the release commit, tested archive restoration and a genuinely independent backup destination if authorized. Publishing or paying is a separate owner-controlled action where not already authorized.

**Completion:** every original task is either implemented and validated or explicitly deferred/externally blocked under an approved scope. A bounded H5 paper is not described as completion of the original entire programme.

## 6. Governance, resources and reporting
